# Глоссарий проекта

Единый словарь терминов. Имена в коде, топики сообщений и обсуждение должны
использовать эти слова в одном значении.

## Ядро

**Шина (MessageBus)** — центральный механизм обмена сообщениями между
подсистемами. Единственная точка, через которую модули узнают друг о друге.

**Сообщение (Message)** — общий предок событий и команд. Несёт строковый
**топик** (`TOPIC`) — имя, по которому сообщение ходит между Rust и интерфейсом.

**Топик (TOPIC)** — строковый идентификатор сообщения, например `core:ping`.
Разделитель — двоеточие (требование Tauri к именам событий).

**Событие (Event)** — уведомление о факте. Доставляется асинхронно, через
очередь и фоновый диспетчер; подписчиков может быть много; ошибка одного
подписчика изолируется.

**Команда (Command)** — императивная операция. Выполняется синхронно, ровно
одним обработчиком; ошибка возвращается вызывающему. Применяется там, где нужен
немедленный результат или побочный эффект: жизненный цикл, трей, окна,
настройки, отмена.

**ask** — надстройка над событиями для запрос/ответа. Добавляет в нагрузку
`correlation_id`, публикует событие-запрос и ждёт событие-ответ с тем же
идентификатором. Не является третьим типом сообщения.

**correlation_id** — идентификатор конкретного запроса, по которому ответ
сопоставляется с ожидающим.

**reply_topic** — топик ожидаемого ответа в `ask`. Обязателен: запрос сам несёт
`correlation_id`, поэтому без явного топика шина приняла бы запрос за ответ.

**Диспетчер** — фоновый поток, который разбирает очередь событий и вызывает
подписчиков и приёмник.

**Приёмник (EventSink)** — абстрактный выход шины наружу. В приложении это мост
в интерфейс через Tauri; в тестах — любая другая реализация.

## Слои

**Слой** — уровень кода с фиксированным правом импорта. Зависимости идут
только вниз: `contracts → core → ui → { tools | workbench } → app`. В Rust —
`lib.rs → modules → core`.

**Зона** — часть ядра с фиксированным правом импорта. Зон три, имена
одинаковы в Rust и TypeScript: `infra`, `store`, `services`. Зависимости идут
только вниз: `infra ← store ← services`. Состав разный: `store` есть только
в Rust, `contracts` — только в интерфейсе. Границы проверяются стражем:
тестом в Rust и скриптом перед сборкой (ADR 0035).

**Держатель состояния** — модуль ядра, который создаёт наблюдаемое
состояние и живёт до конца сеанса: журнал, каталог словаря, профили,
настройки, рабочее пространство и им подобные. Только держателям разрешён
импорт `vue` в ядре (`reactive`/`ref`/`computed`/`watch`). Правила, разбор
и проверка ввода остаются без фреймворка (ADR 0047).

**Алиас слоя (`@/`)** — имя `src/` для перехода между слоями:
`@/core/infra/journal` вместо `../../../core/infra/journal`. Внутри модуля
остаются относительные пути: они показывают, что файл лежит рядом.

**Инфраструктура (infra)** — зона ядра с механизмами без предметного
словаря: шина, `Deps`, сообщение, контракт подсистемы, приёмник, трасса;
в интерфейсе — мост, журнал, статусы операций, ошибки, стражи формы.
Объясняется, не называя ни профиля, ни пресета.

**Зона хранения (store)** — зона ядра, которая знает, где лежат файлы
и как они читаются и пишутся: `files`, `names`, `storage`, `stats`. Решает
«где», а не «что». Не путать с хранилищем (`storage`): хранилище — сервис,
который определяет корень программы, зона — все файловые механизмы.

**Сервис домена (сервис ядра)** — файл в зоне `services`, владеющий
правилами одного домена и его форматом на диске: настройки, профили, пресеты,
вкладки, данные, логирование, окно. Пункта меню не имеет;
в отличие от модуля, отключить его нельзя (ADR 0005). Правило живёт здесь,
а не в точке сборки; побочные эффекты (логгер, событие интерфейсу, окно)
остаются в `lib.rs`.

**Контракт** — типы, которые пересекают границы слоёв: топики, дескриптор
инструмента, раскладка вкладки, запись журнала, ответы ядра (`Stored*`).
Живут в `src/contracts`, поведения не содержат: функция, константа или класс
в контракте — ошибка. Модель после разбора (`Preset`) принадлежит своему
домену, а не контракту.

**Хранилище (storage)** — сервис зоны `store`, который определяет
портативный корень, проверяет доступность записи в него и выдаёт остальным
пути к настройкам и логам.

## Подсистемы

**Модуль (Module)** — самодостаточная подсистема. Знает свои топики и
регистрирует обработчики в шине. Ядро знает о модуле только идентификатор и
факт регистрации.

**Папка-область** — подпапка модуля для трёх и более файлов одной роли:
`sections/` разделов экрана, `state/` сеансов, `presets/` формата пресетов.
Корень модуля остаётся оглавлением; папка на один-два файла не заводится
(ADR 0036, ADR 0038).

**Инструмент** — мини-утилита в интерфейсе: busprobe, dnslookup, статус.
Занимает папку `src/tools/<id>/` и, при наличии поведения в Rust, модуль
с тем же `id`. Чисто фронтовый инструмент — норма.

**Busprobe**: инструмент для демонстрации шины. Отправляет учебный запрос и показывает
путь сообщения. Живёт целиком в интерфейсе; топики `core:ping` и `core:pong`
принадлежат протоколу ядра, а не имени инструмента. Не путать
с самопроверкой (ping/pong): это протокол, а не экран.

**Реестр инструментов** — список дескрипторов (`id`, название, иконка,
компонент, порядок), который собирает `app` и передаёт оболочке. Оболочка
не импортирует инструменты напрямую.

**Мост (bridge)** — четыре операции между Vue и Rust: `sendEvent`,
`invokeCommand`, `ask`, `subscribeEvent`.

**Зависимость (Deps)** — объект, который обработчик получает извне, а не
создаёт сам. Внедрение выполняется **по типу** (в Rust нет рефлексии по именам
параметров, как в Python-образце).

**Оболочка (workbench)** — каркас интерфейса: сайдбар, полоса вкладок и рабочая
область. Знает инструменты только через реестр; конкретные подсистемы
не импортирует.

## Интерфейс

**Обёртка операции (useAsyncAction)** — способ вести одну асинхронную
операцию: `loading`, текст отказа и защита от повторного запуска. Ошибка
не глотается: обёртка кладёт её в `status.error`, а журнал пишет сама
операция. Прогон, живущий дольше промиса (события ядра пачкой), ведёт
состояние сам.

**Тема** — набор токенов PrimeVue: палитра, типографика и радиусы единственного
светлого оформления. Тёплая нейтральная база, белые панели и тонкие линии.
Схема не переключается; значения живут в `src/ui/primevue/theme.ts` (ADR 0019).
Не путать с пресетом настроек: тема — оформление приложения, пресет —
сохранённый вход инструмента.

**Акцент** — тёмно-зелёный цвет действия и выбора: основные кнопки, фокус,
активное состояние. Декоративно не используется; ошибки остаются красными
(ADR 0019).

**Заголовок экрана** — `h1` основного экрана: имя инструмента или раздела
(«DNSlookup», «Журнал», «Настройки», «Новая вкладка»). Крупный, но
приглушённый: цвет `--ag-text-heading` на шаг мягче основного текста, чтобы
шапка не спорила с данными. Не путать с заголовком раздела или диалога —
те меньше и цвет заголовка экрана не берут (ADR 0033).

**Закреплённая колонка** — колонка таблицы, которая при горизонтальной
прокрутке стоит на месте, а остальные уходят под неё. В таблице DNS закреплены
слева «Домены» и «Тип»; их отступ пересчитывается по ширине колонок
(ADR 0026).

**Полоса вкладок** — верхняя строка оболочки с открытыми вкладками и кнопкой
«Новая вкладка». При переполнении прокручивается шевронами у кромок;
активная вкладка всегда подкручивается в видимую зону целиком — с запасом
на ширину шеврона (ADR 0043, ADR 0045).

**Шеврон полосы вкладок** — кнопка со стрелкой у кромки полосы: появляется,
только когда в эту сторону есть скрытые вкладки, и прокручивает полосу почти
на экран. Лежит поверх вкладок, место у них не отнимает; под кнопкой —
градиентная кромка (ADR 0043).

**Вкладка** — экземпляр рабочего места: одна–три колонки, в колонках
инструменты. Раскладка принадлежит самой вкладке.

**Пустая вкладка** - вкладка без инструментов. Показывает экран запуска.
Она же выполняет роль главной; вкладок не может быть меньше одной.
При открытии содержимого пустые вкладки закрываются: экран запуска уступает
место работе (ADR 0040).

**Экран запуска** - содержимое пустой вкладки: каталог инструментов
и разделов приложения и строка состояния ядра. С него начинают работу;
навигацией остаётся сайдбар. Не путать с блокирующим экраном запуска: тот
показывается вместо интерфейса, когда писать в папку программы нельзя
(ADR 0062).

**Быстрый запуск** - карточка раздела приложения на экране запуска: открывает
журнал или настройки одним нажатием. Навигацией не является и сайдбар
не заменяет: сайдбар показывает, что открыто, и остаётся на месте. Карточки
разделов дублируют меню осознанно; список быстрого запуска не растёт до всего
сайдбара (ADR 0062).

**Единственная вкладка** — умолчание для всех инструментов и разделов:
журнал и настройки существуют в одном экземпляре всегда, инструмент — если
в его дескрипторе нет признака `multipleTabs`. Повторный выбор активирует
вкладку, активированную последней, а новая создаётся, только если такой
вкладки нет. Раскладку правило не ограничивает (ADR 0042).

**Многовариантный инструмент** — инструмент, которому разрешено несколько
вкладок: в дескрипторе стоит признак `multipleTabs`. Обычный выбор ведёт
в последнюю активную вкладку с ним, а Ctrl+клик, средняя кнопка мыши или
Ctrl+Enter открывают ещё одну — отдельную вкладку только с этим инструментом
(ADR 0042).

**Пресет настроек** — сохранённый вход инструмента: строки, выбранные серверы
и параметры работы с ними. Результаты проверок в пресет не входят: он
фиксирует настройку задачи, а не её итог. Не путать с сеансом (состояние
в памяти, привязанное к ячейке).
Пресет лежит в `profiles/<id>/presets/<tool>/` (ADR 0028).

**Пресет по умолчанию** — пресет, который автоматически загружается в новую
вкладку инструмента. Указатель «инструмент → идентификатор пресета» хранится
в `profiles/<id>/profile.json` в разделе `defaults` и принадлежит профилю.
Умолчания нет — вкладка открывается пустой, как раньше. Открытую вкладку
настройка не трогает (ADR 0030).

**Свежая ячейка** - ячейка, появившаяся вместе с вкладкой, при открытии
инструмента. Только в неё инструмент грузит пресет по умолчанию; признак
одноразовый и в файл не попадает (ADR 0030).

**Снимок пресета** — JSON настроек сеанса на момент загрузки или сохранения
пресета. Хранится только в сеансе и служит для подписи «Изменён»; в файл
пресета не пишется.

**Ячейка (cellKey)** — одно место инструмента в сетке вкладки. Ключ
`<tabId>:<columnIndex>:<toolIndex>`: вкладки имеют UUID, поэтому ключ
уникален на всё время жизни интерфейса. По ключу инструмент хранит своё
состояние, переживающее переключение вкладок (ADR 0017).

**Рейл** — свёрнутый сайдбар шириной 64 px с иконками и подсказками.
Развёрнутый сайдбар — 240 px.

**Пункт рейла** — строка навигации в сайдбаре: иконка, подпись и активное
состояние. Один компонент `RailItem.vue` на инструменты, разделы приложения
и профиль; свёрнутый вид скрывает подпись и включает подсказку.

**Рабочее пространство** — набор открытых вкладок, активная вкладка
и размеры колонок. Хранится в `local/workspaces/<id>.json`: у каждого
профиля своё, принадлежит машине.

**Профиль** — папка `profiles/<id>/` с пресетами настроек и данными
инструментов. Профили не пересекаются; активный хранится в
`local/settings.json`, переключение перезапускает приложение.

**Корзина** - служебная папка `local/trash/` для удалённых файлов и папок.
Верхний уровень повторяет единицу удаления: `profiles/<id>/`,
`presets/<profile>/<tool>/<id>.json`, `languages/<code>.jsonc`.
В интерфейсе не показывается, восстановление не обещается; записи старше
14 дней удаляются автоматически. Вне синхронизации, чтобы удаление
не возвращалось с другой машины.

**Блокирующий экран** — экран вместо интерфейса, который показывается, если
писать в папку программы нельзя. Оболочка получает статус запуска и не даёт
работать «наполовину».

**Видимая граница окна** - прямоугольник, который видит пользователь.
Внешний прямоугольник окна шире него на невидимую рамку: на Windows это
7-8 px слева, справа и снизу. Величина измеряется у живого окна через DWM,
а не задаётся числом (ADR 0064).

**Геометрия окна** — размер и положение главного окна, которые переживают
перезапуск: раздел `window` в `local/settings.json`. Размер хранится
в логических пикселях, положение — в физических (ADR 0014).

**Положение окна** - координаты внешнего прямоугольника главного окна
на общем рабочем столе, в физических пикселях (`x`, `y` раздела `window`).
`null` - положение выбирает система. Задаётся перетаскиванием и вручную
в разделе «Окно»; недостижимая точка прижимается к рабочей области
ближайшего монитора (ADR 0014, ADR 0066).

**Прилипание окна** - окно само встаёт вплотную к краю рабочей области,
когда его видимая граница приближается к краю на 6 логических пикселей.
Магнит работает только по ходу движения: окно, которое ведут от края,
идёт за курсором сразу, без мёртвой зоны отрыва. Порог пересчитывается
по масштабу монитора (ADR 0064, ADR 0065).

**Рабочая область монитора** — часть экрана без панели задач, дока и других
системных панелей (`Monitor::work_area()`). Окно прижимается к ней, а не
к границам экрана. Не путать с рабочей областью оболочки — местом под вкладки.

**Размер окна** - ширина и высота клиентской области главного окна
в логических пикселях (ADR 0014). Задаётся перетаскиванием рамки и полями
«Ширина»/«Высота» в разделе «Окно»; меньше `minWidth`/`minHeight` не бывает
(ADR 0067).

**Рамка окна** — разница внешнего и клиентского размера окна. Задаётся оконной
системой, поэтому измеряется у живого окна, а не считается константой.
Невидимая часть рамки описана отдельно: «Видимая граница окна».

**Самопроверка (ping/pong)** — служебный модуль `core:ping` → `core:pong`,
проверяющий всю цепочку шины без прикладных подсистем.

## Мультиязычность

**Язык интерфейса** — язык, на котором программа говорит с конечным
пользователем. Хранится в `local/settings.json` разделом `ui.language`;
`null` — «как в системе», выбор определяется при первом запуске и
сохраняется. Не путать с языком кода: комментарии, тесты и лог остаются
русскими (ADR 0039).

**Локаль** — тег BCP 47 (`ru`, `en`, `pt-BR`), который выбирает формы
склонения и формат чисел и дат. Совпадает с именем файла внешнего словаря.

**Словарь** — набор сообщений интерфейса по ключам. Встроенных словаря два:
`ru` (эталон) и `en`; оба живут в интерфейсе и не требуют файлов. Внешний
словарь — файл `local/languages/<code>.jsonc`, который пользователь правит
руками; он перекрывает встроенный язык с тем же кодом. Приложение внешние
файлы никогда не перезаписывает (ADR 0039, ADR 0057).

**Встроенный язык** - `ru` или `en`, поставляемый вместе с программой.
Не требует файла, всегда полон и обновляется вместе с приложением.

**Внешний словарь** - файл `local/languages/<code>.jsonc`, принадлежащий
пользователю. Появляется по кнопке выгрузки у встроенного языка или
создаётся вручную для нового языка. Приложение его только читает.

**Выгрузка языка** - создание внешнего словаря из встроенного по кнопке
раздела «Язык». Файл создаётся, только если его ещё нет; после выгрузки
язык становится внешним и перекрывает встроенный.

**Возврат к встроенному** - перенос внешнего словаря в
`local/trash/languages/` и возврат к встроенному языку с тем же кодом.

**Файл дополнений** - `<code>.missing.jsonc` рядом со словарём: недостающие
ключи с текстом из встроенного языка того же кода или из русского эталона.
Создаётся программой, словарём не считается и может перезаписываться.

**Цепочка отката словаря** - внешний файл → встроенный язык с тем же кодом
→ русский эталон → ключ.

**Эталонный словарь** — русский встроенный словарь: он обязан быть полным,
и только его пропуск валит сборку. Остальные словари могут отставать.

**Образец словаря** — файл `<code>.template.jsonc`, выгруженный кнопкой
раздела «Язык». Копия эталонного словаря для начала перевода; создаётся
только если файла ещё нет.

**Ключ словаря** — публичный контракт сообщения: `область.сущность.поле`
(`settings.section.log`, `errors.settings.read`). Формулировку менять можно,
ключ — нет: переименование молча ломает чужие переводы.

**Сообщение словаря** — значение по ключу: строка или набор форм по
категориям склонения. Подстановка записывается как `{name}`; другого
синтаксиса нет.

**Подстановка** — именованное значение внутри сообщения (`{count}`,
`{path}`). Числа форматируются по локали; неизвестное имя остаётся
видимым, чтобы ошибку перевода было легко заметить.

**Категория склонения** — форма сообщения по правилам CLDR: `zero`, `one`,
`two`, `few`, `many`, `other`. Выбирается через `Intl.PluralRules`;
русскому нужны `one`, `few`, `many`, английскому — `one`, `other`.

**Отчёт словаря** — число непереведённых и лишних ключей внешнего файла,
а также причина, по которой файл не прочитан. Показывается в разделе
«Язык»; неполнота внешнего словаря работу не останавливает.

## Наблюдаемость

**Журнал** - поток фактов о работе подсистем, который показывает интерфейс.
Запись делает модуль или ядро явно; шина сама записей не создаёт. Журнал
отвечает на вопрос «что делала программа» и живёт до конца сеанса (ADR 0052).

**Вид записи** - оттенок факта журнала: ход, итог или отказ. Вид виден
на экране цветом точки, а отказ - ещё и словом.

**Лог** — запись отказов самого приложения: падений, ошибок ядра, моста и
загрузки настроек. Отвечает на вопрос «почему приложение или его функция не
сработали». Бизнес-события модулей в лог не попадают: это работа журнала.

**Уведомление** - короткое сообщение поверх экрана о факте, который требует внимания сейчас. Живёт секунды, не сохраняется и не заменяет журнал (ADR 0058).

**Группа уведомлений** - ключ, по которому новое уведомление заменяет предыдущее с той же группой: повторяющийся факт не копится стопкой.

**Приёмник уведомлений** - единственное место в интерфейсе, куда попадают уведомления из шины и от интерфейса; он же рисует тосты по правилам ADR 0058.

**Уровень лога** — порог подробности записи в лог: `error`, `warn`, `info`,
`debug`. Управляет подробностью внутренностей ядра, а не работой модулей.

**Отчёт об отказе (`core:error`)** — событие, которое шина отправляет напрямую
в приёмник, минуя очередь: паника обработчика, потеря данных при сериализации,
недоставка события в интерфейс. Журнал показывает короткую строку, подробности
остаются в логе.

**Трасса** — наблюдаемый путь сообщения через шину. Контейнер из секций по
сообщениям: один `ask` — одна трасса из двух секций с зазором ожидания между
ними. Живёт только в интерфейсе, в файловый лог не пишется.

**Этап** — одна запись внутри трассы: точка, через которую прошло сообщение
(`ask.start`, `queue.enqueue`, `handler.invoke`, `sink.emit` и т.п.). Список
этапов закрытый.

**Точка съёма** — место в коде ядра, где рождается запись этапа. Этапы уходят
в приёмник напрямую, минуя очередь событий, поэтому трассировка не рекурсивна.

**Корень трассы** — трасса, начатая без унаследованного контекста: событие из
интерфейса или публикация из потока, созданного обработчиком.

## DNS

**Проверка (run)** — один запуск набора запросов в инструменте DNS: домены,
типы записей и выбранные серверы на момент нажатия кнопки. Проверка не
сохраняется на диск; живёт в сеансе инструмента до очистки или закрытия
вкладки.

**Сеанс (session)** — состояние инструмента DNS, привязанное к ячейке
(`cellKey`): строки доменов, выбранные серверы, результаты и статус
операции. Переживает переключение вкладок, но не перезапуск приложения.

**Системный сервер** — резолверы операционной системы, полученные через
`ipconfig`. В сравнении участвует наравне с указанными серверами; ответ —
первый пришедший от любого системного резолвера.

**Расхождение (diff)** — отличие ответа сервера от ответа системного сервера
для той же пары «домен + тип». Без системного сервера расхождение
не определено, фильтр расхождений отключён.

**Пользовательский сервер** — DNS-сервер, добавленный вручную строкой
`IP[:port]`; хранится в `profiles/<id>/data/dnslookup/servers.json`.
