# Ручной ввод размера и положения окна

Основание: ADR 0066, ADR 0067. Согласовано: поля чисел с одной кнопкой
«Применить» внизу, координаты в физических пикселях, размер в логических,
недостижимые числа подтягиваются к рабочей области ближайшего монитора.
Расположение полей: подпись слева от поля, поля в одну строку.

## Решение

- В разделе «Окно» две карточки-формы: «Размер» с полями «Ширина»
  и «Высота», «Положение» с полями `X` и `Y`. Карточки идут друг под другом.
- Подпись стоит слева от поля; поля идут в одну строку. Кнопка «Применить»
  одна и стоит внизу, рядом со сбросом: геометрия окна одна, и применение
  одно.
- Применяется только изменённая часть: незатронутые поля окно не трогают.
  Enter применяет, Escape возвращает сохранённые числа. Кнопка неактивна,
  пока значения не изменились или пока ввод неверен.
- Ошибка ввода показывается под полями карточки; сами поля подсвечены.
- Пока положение не выбрано, поля положения пустые с подсказкой «Система».
  Размер всегда задан, пустое поле размера - ошибка.
- Числа меньше минимального размера окна (`minWidth`/`minHeight`) поля
  размера не принимают.
- После применения поля показывают фактические числа: прижатая точка,
  уменьшенный размер или сдвинутое место изменят значения.
- Развёрнутое, свёрнутое и полноэкранное окно перед применением
  восстанавливается, развёрнутость снимается и в настройках.
- Окно не становится больше рабочей области монитора: размер уменьшается
  до места, положение подтягивается. Верхний левый угол остаётся на месте,
  пока помещается.

## Приёмка

- `npm run verify` зелёный: тесты, lint, `vue-tsc`, сборка, `cargo check`,
  `cargo test --lib`.
- Пока введённые числа совпадают с сохранёнными, «Применить» неактивна:
  применяется только изменение.
- Изменение только размера не трогает введённые координаты: окно
  смещается, лишь если новый размер выходит за рабочую область.
- Ввод точки в пределах рабочей области: окно встаёт в неё, положение
  сохраняется и переживает перезапуск.
- Ввод точки за экраном: окно прижимается к рабочей области ближайшего
  монитора видимой границей, поля показывают фактическое положение.
- Ввод размера: окно меняет размер, верхний левый угол остаётся на месте,
  размер сохраняется и переживает перезапуск.
- Ввод размера больше рабочей области: окно уменьшается до места, поля
  показывают фактический размер.
- Ввод размера меньше минимального: поле показывает ошибку, окно не меняется.
- Развёрнутое окно: после применения оно восстанавливается и получает
  заданную геометрию.
- Русский и английский интерфейс показывают одинаковый набор полей
  и ошибок.

## Швы тестов

- `window::pressed_position`: точка внутри рабочей области не меняется;
  выход за каждый из четырёх краёв прижимается с учётом видимой вставки;
  окно больше рабочей области не сдвигается по этой оси.
- `window::pressed_size`: помещающийся размер не меняется; размер больше
  рабочей области уменьшается до неё; размер меньше минимального
  поднимается; масштаб, рамка и вставка учитываются.
- `window::nearest_screen`: точка внутри монитора выбирает его; точка вне
  всех мониторов выбирает ближайший; монитор отдаёт и свой масштаб.
- `settings::move_window`, `settings::resize_window`: числа записываются,
  развёрнутость снимается, чужие разделы не тронуты.
- `parseCoordinate` (фронтенд): координата (`i32`) и размер (`u32`)
  с пробелами по краям; пустое поле; дробное число; посторонний текст;
  значения на границах и за ними; размер меньше минимального.
- Применение к живому окну (`move_to`, `resize`, команды `window_move`,
  `window_resize`) юнит-тестами не покрывается: это адаптер к оконной
  системе, проверяется запуском.
