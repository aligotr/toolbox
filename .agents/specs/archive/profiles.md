# Профили: доводка и своё рабочее пространство

Решения — ADR 0050 (рабочее пространство профиля) и дополнение к ADR 0049
(перезапуск внутри `profile_switch`). Цель: закрыть найденные слабые места
профилей и дать каждому профилю свой набор вкладок, не ломая границу
синхронизации из ADR 0010.

## Что входит

- Замок на чтение-изменение-запись `profile.json`.
- Идентификатор профиля по умолчанию приходит из ядра, а не из литерала в TS.
- Проверка записи в папку целевого профиля при переключении.
- Счётчики профилей отдельной командой; список профилей файлы не считает.
- `profile_switch` сам просит перезапуск; `app_restart` удаляется.
- Рабочее пространство — `local/workspaces/<id>.json`, у каждого профиля своё.
- Уборка осиротевших и посторонних файлов рабочих пространств.
- Обновление ADR, глоссария, README и комментариев к путям.

## Что не входит

- Восстановление профиля или рабочего пространства из корзины.
- Синхронизация вкладок вместе с профилем: рабочее пространство остаётся
  машинным.
- Миграция старого `local/workspace.json`: приложение не выпущено, файл
  удаляется вручную.
- Перенос `presets.rs` и другие необязательные работы из `.scratch/audit`.

## Критерии приёмки

1. Параллельные правки `profile.json` не теряют ни одну: замок вокруг
   `write_profile` и `update_document`.
2. `ProfileList` отдаёт `default_id`; в интерфейсе нет литерала `"work"`.
3. `profile_switch` проверяет запись в папку целевого профиля до записи
   настроек; отказ не меняет активный профиль.
4. `profiles_list` возвращает только идентификатор и название; счётчики —
   отдельной командой `profiles_usage`. Сайдбар счётчики не запрашивает.
5. `profile_switch` перезапускает приложение после успешной записи;
   команды `app_restart` больше нет; ADR 0049 дополнен.
6. Активный профиль читает и пишет `local/workspaces/<id>.json`; другой
   профиль — другой файл; формат версии 1 не меняется.
7. При запуске остаются только `<id>.json` существующих профилей; прочие
   файлы удаляются, каталоги логируются. При недоступной папке профилей
   уборка не запускается. Удаление и создание профиля чистят его файл.
8. `npm run verify` зелёный: тесты интерфейса, линт, сборка, `cargo check`,
   `cargo test --lib`; предупреждений не прибавилось.

## Проверка

- `npm run verify`.
- Ручная: старый `local/workspace.json` удалить, открыть приложение —
  одна пустая вкладка; открыть вкладки в профиле A, переключиться на B —
  свой набор; вернуться в A — прежний.
- Ручная: удалить папку неактивного профиля в проводнике, перезапустить —
  его файл рабочего пространства исчез, живые файлы на месте.
