# План: от аудита к «доведённому до ума»

Основание — `report.md` в этой папке. Порядок принципиален: сначала страховка
от регрессий, потом структура, в конце — косметика и необязательная оптимизация.
Каждый этап заканчивается зелёными `npm run test`, `npm run build`,
`cargo check`, `cargo test --lib`; новые предупреждения не накапливаются.

## Этап 2. Страховка: тесты интерфейса (P1, 2 сессии)

Сейчас 19 тестов и все про перевод. Цель — покрыть доменное состояние,
которое не видно ни типам, ни сборке. Тест-раннер `node --test` уже есть.

| № | Работа | Критерий |
|---|---|---|
| 2.1 | Тесты разбора `workspace.json`: нет файла, битый JSON, пустой список, дубли вкладок, неизвестный вид вкладки, файл с устаревшим полем `bindings`, сохранение активной | каждое правило из шапки модуля имеет тест |
| 2.2 | Тесты свёртки «вкладок не меньше одной» и «закрытие активной активирует соседнюю» на чистых функциях модуля | тесты без Tauri и Vue-рендера |
| 2.3 | Тесты пресетов: создание, переименование, копия, удаление, пресет по умолчанию, отказ при занятом имени | сценарии из `presets/index.ts` покрыты |
| 2.4 | Тесты `dnslookup`: нормализация домена, применение пресета, отбор строк | чистые функции без сети |
| 2.5 | Ввести `npm run verify` = `test` + `build` + `cargo check` + `cargo test --lib` | одна команда воспроизводит все требования `quality.md` |

Требование к реализации: чистые функции выносятся из `workspace/index.ts`
и `presets/index.ts` в отдельные файлы роли (`parse.ts`, `edits.ts`),
если это нужно для теста без Tauri. Дробить ради теста сам сервис не нужно.

## Этап 6. Необязательное (P2)

- `manualChunks` в `vite.config.ts`: vendor/приложение отдельно. Выигрыш только
  в кэше между сборками, для десктопа не критично.
- Ленивая загрузка инструментов через `defineAsyncComponent`, если появится
  третий-четвёртый инструмент.
- Разделение `PresetsDialog.vue` (654 строки) по образцу `TabStrip`/`TabItem`,
  когда следующая правка коснётся диалога.

## Чего не делать

Осознанные решения, которые аудит подтвердил, а не осудил:

- разные ключи для одинаково звучащих текстов (`workspace.empty.title`
  и `tab.empty.title`) — требование `i18n.md`;
- повтор шкалы в `theme.ts` и `global.css` — требование `ui.md`;
- `unwrap()` в тестах Rust и `str`-литералы;
- дробление `bus.rs`, `settings.rs`, `request.rs` только по числу строк;
- 480 строк `dnslookup/styles.css` без реальной причины.

## Оценка и порядок

| Этап | Ценность | Труд | Когда |
|---|---|---|---|
| 1. Гигиена | убирает шум, закрывает правило о предупреждениях | полсессии | сразу |
| 2. Тесты интерфейса | ловит регрессии состояния вкладок и пресетов | 2 сессии | до новых фич |
| 3. `lib.rs` | ускоряет каждую следующую правку ядра | 1–2 сессии | после этапа 2 |
| 4. CI и линт | держит планку без ручной дисциплины | 1 сессия | после этапа 2 |
| 5. Документация | вход для человека и для будущих правок | полсессии | параллельно |
| 6. Необязательное | кэш сборки, косметика | по мере надобности | последним |

Первые три этапа закрывают все находки высокой важности из отчёта;
этапы 4–5 — средние; этап 6 — низкие и необязательные.
