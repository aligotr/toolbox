# Команды Tauri: отдельный слой

Решение — ADR 0048. Цель: `lib.rs` снова только собирает приложение,
а команды интерфейса живут по областям и не содержат правил домена.

## Что входит

- `core/runtime.rs`: `Runtime`, `StartupError` и доступ к хранилищу.
- `core/commands/`: `bridge`, `workspace`, `profiles`, `presets`,
  `languages`, `settings`, `info`, `window`, `lifecycle`.
- Перенос проверки «активный профиль не удаляется» из команды
  в `profiles::delete`.
- Запрет `crate::core::commands` для `infra`, `store` и `services`
  в `core::zone_tests`.
- Абзац в `.agents/rules/project/architecture.md`.

## Что не входит

- Изменение поведения команд, топиков, кодов отказа и формата файлов.
- Разделение `presets.rs` (этап 3.2 плана) — отдельная работа.
- Прямые команды жизненного цикла: их правило — ADR 0049.
- Тесты команд: у них нет собственных правил.

## Критерии приёмки

1. `lib.rs` ≤ 400 строк; в нём нет `#[tauri::command]`.
2. Все 34 команды зарегистрированы и доступны интерфейсу под прежними
   именами.
3. `cargo check`, `cargo test --lib`, `cargo clippy --all-targets`
   без предупреждений; число тестов не уменьшилось.
4. `npm run test` и `npm run build` зелёные.
5. Попытка импорта `crate::core::commands` из сервиса валит `zone_tests`.

## Проверка

- запуск `npm run tauri dev`: вкладки, настройки, профили, пресеты,
  журнал — по одному действию на область;
- тест зон: временная строка `use crate::core::commands;` в сервисе
  валит `cargo test --lib`, после отката — зелёный.
