# Скрипты документации

Здесь переносные скрипты для работы с каталогом `.agents` и документацией.
Скрипты проекта, не относящиеся к `.agents` и документации, живут в `scripts/`
в корне и в этот каталог не попадают.

Набор универсальный: он копируется целиком и может содержать реализации на
разных языках. Выбирать один язык при копировании не нужно.

## Структура

```text
auxiliary/scripts/
  README.md
  conformance.mjs
  node/
    manifest.json
    check-docs.mjs
    build-adr-index.mjs
```

- `node/` - реализация на Node.
- Новая реализация добавляет свой каталог и `manifest.json`, существующие
  каталоги не переписывает.
- `conformance.mjs` сверяет реализации между собой.

Манифест объявляет команды реализации:

```json
{
  "language": "node",
  "checkDocs": ["node", "check-docs.mjs"],
  "buildAdrIndex": ["node", "build-adr-index.mjs"]
}
```

Команды запускаются из каталога реализации и принимают `--root <каталог>`.

## Контракт

Контракт один для всех языков. Расхождение считается ошибкой набора.

`check-docs`:

- проверяет локальные markdown-ссылки, пути `.agents/...` в обратных кавычках,
  обязательные файлы памяти, поля и полноту ADR, статусы спек и их упоминание
  в `specs/README.md`, ссылки на страницы библиотеки, термины глоссария;
- без `--json` печатает проблемы или число проверенных файлов;
- с `--json` печатает `{ "files": N, "problems": [], "warnings": [] }`;
- завершается кодом 1, если есть проблемы, иначе кодом 0;
- пишет те же тексты проблем, что и другие реализации: сверка сравнивает
  строки, а не только код выхода.

`build-adr-index`:

- собирает `.agents/decisions/INDEX.md` по файлам ADR;
- принимает `--root <каталог>`;
- завершается кодом 1, если каталога решений нет.

`--root` по умолчанию равен текущему каталогу, поэтому обычный запуск
предполагает корень проекта.

## Сверка реализаций

`conformance.mjs` читает манифесты и сравнивает доступные реализации на одном
входе:

- действующий проект;
- пустой корень, где срабатывают обязательные файлы;
- намеренно сломанная документация с нарушением каждого вида;
- копия каталога решений для указателя ADR.

Реализация, чей рантайм не установлен, пропускается: набор остаётся
универсальным, сверяются только доступные языки. Если реализация одна,
сверять нечего.

```powershell
node .agents/auxiliary/scripts/conformance.mjs
```

В проекте с npm эта команда называется `npm run docs:conformance` и входит
в `npm run verify`.

## Обычный запуск

```powershell
node .agents/auxiliary/scripts/node/check-docs.mjs
node .agents/auxiliary/scripts/node/build-adr-index.mjs
```

В проекте с npm:

```powershell
npm run docs:check
npm run docs:index
npm run docs:conformance
```

- `check-docs` завершается с кодом 1, если есть проблемы.
- Каталоги `skills`, `mcp`, `templates` и `node_modules` не проверяются:
  скилы ставит установщик, шаблоны содержат примеры, MCP-контекст подключается
  отдельно. `bootstrap.md` описывает будущий проект и тоже пропускается.
- Скрипты не входят в ESLint и Prettier: `.agents/` исключён из проверок кода.
  Их проверка - собственный запуск и сверка реализаций.
