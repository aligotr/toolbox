# ADR 0001: Модель памяти проекта

- **Статус:** принято
- **Дата:** ГГГГ-ММ-ДД
- **Область:** `.agents/`, `AGENTS.md`, `.scratch/`

## Контекст

Проект начинается с нуля. Нужно заранее договориться, где живут решения,
правила, спеки, термины и готовые элементы, чтобы память не расползлась
по случайным файлам и не начала конкурировать с кодом.

## Решение

1. Вся память проекта живёт в `.agents/`.
2. ADR неизменяемы. Новое решение оформляется отдельным ADR.
3. `.agents/decisions/INDEX.md` - производный обзор, а не решение.
4. `.scratch/` - временная записная книжка, не память проекта.
5. Глоссарий разбит по доменам, вход - `.agents/GLOSSARY.md`.
6. Библиотека готовых элементов лежит в `.agents/library/` по областям.
7. Шаблоны и пособия - в `.agents/auxiliary/`.

## Почему так

Один вход в память снижает риск устаревших копий. Неизменяемые ADR хранят
историю решений. Производный индекс даёт обзор без правки истории. Записная
книжка не засоряет репозиторий и не притворяется источником истины.

## Последствия

- Новый ADR добавляет строку в `INDEX.md`.
- `.scratch/` не коммитится.
- Спеки, на которые ссылаются ADR, лежат в `.agents/specs/` и не удаляются.
- Правила и шаблоны обновляются вместе с раскладкой памяти.

## Отклонённые альтернативы

- **Хранить память в `docs/`.** Второе место памяти расходится с `.agents/`.
- **Коммитить `.scratch/`.** Черновик начинает конкурировать с ADR и спеками.
- **Переписывать старые ADR.** История решений теряется, а ссылки ломаются.
