Toolbox / память проекта

Один вход, четыре вида знаний и одноразовый черновик

Problem

Правила лежат в десятках файлов. Без входа агент читает случайное и пропускает обязательное.

Solution

AGENTS.md задаёт инварианты и порядок чтения, а priorities.md объясняет, что главнее при конфликте.

  • 8 глобальных правил и 1 машинный запрет

Три состояния знания

Истина

ADR, спеки, правила, библиотека, определения глоссария.

Меняется только новым решением или новой версией контракта.

Производное

INDEX.md, README-указатели, таблица GLOSSARY.md, списки страниц.

Пересобирается скриптом, ручные правки теряются.

Черновик

.scratch: план, заметки, вопросы по текущей задаче.

Удаляется без потери понимания проекта.

Files

.agents/
.scratch/
AGENTS.md

Problem

Без ролей каталог превращается в свалку: черновик выглядит как решение, а производный индекс - как истина.

Solution

Каждый каталог отвечает за один вид знания. Производное помечено и собирается, черновик лежит отдельно и не коммитится.

  • истина не переписывается молча
  • производное пересобирается скриптом
  • черновик удаляется свободно
  • инструменты проверяют согласованность

Problem

Статусы и актуальность спрятаны внутри десятков файлов. Чтобы понять, что действует, нужно открыть каждый.

Solution

INDEX.md - производный обзор. Источник истины - сами ADR. Статус «заменено» ставит только владелец.

  • номер и заголовок по форме «# ADR NNNN: ...»
  • поля Статус, Дата и Область обязательны
  • заменяющий ADR должен существовать
  • новое решение - новый файл, а не правка старого

Ручные правки INDEX.md теряются при следующем запуске. Меняют ADR, а индекс пересобирают.

Problem

Без разделения знание расползается: причина решения смешивается с поведением, инструкцией и готовым элементом.

Solution

Один вид знания - один каталог. Спека описывает поведение, правило - норму, библиотека - элемент, глоссарий - слово.

  • спека не дублирует ADR: она описывает поведение
  • правило не объясняет причину решения
  • библиотека экономит новую реализацию
  • глоссарий держит единый язык проекта

12 шаблонов в auxiliary/templates - подсказка, а не обязательный каркас. Лишние разделы удаляются, пустые не заполняются.

Problem

Черновик легко принять за истину и закоммитить. Тогда удалённые механизмы остаются в истории как действующие.

Solution

Папка не коммитится. Долговечное сразу уходит в ADR, спеку, библиотеку или правило. Завершённую задачу можно удалить.

  • .scratch не попадает в git
  • ADR, спеки и правила не ссылаются на .scratch
  • мелкая задача может обойтись без папки
  • удаление безопасно: понимание остаётся в .agents

Если результат отменён, удаление записной книжки ничего не меняет: решение и спека уже лежат в .agents.

Problem

Документация стареет молча, а реализации проверки на разных языках расходятся в текстах и кодах выхода.

Solution

docs:check ловит битые ссылки и неполные индексы, conformance сверяет реализации, verify запускает всё.

  • docs:check прошёл на 137 файлах
  • conformance входит в npm run verify
  • точечная, областная и полная проверки
  • живое окно проверяется через CDP

Пока реализация одна, conformance говорит «сверять нечего». При второй реализации расхождение остановит verify.

7. Старт нового проекта: каркас без чужих решений

bootstrap.md - пособие, а не правило; память нового проекта начинается с пустого каркаса

Flow

Копировать

AGENTS.md
rules/global/
auxiliary/
glossary/

Шаблоны, скрипты и bootstrap переносятся вместе с auxiliary. Набор скриптов универсальный.

Создать своё

decisions/INDEX.md
specs/README.md
library/README.md
GLOSSARY.md
project/quality.md
project/agents-guard.yml

Не переносить: чужие ADR, спеки, страницы библиотеки, project-правила, skills, mcp, .scratch.

Files

.agents/auxiliary/bootstrap.md
.agents/auxiliary/templates/
.agents/auxiliary/scripts/

Problem

Новый проект легко тащит чужие ADR и команды. Тогда память описывает не его, а предыдущий продукт.

Solution

Копируются только global-правила и шаблоны. ADR, спеки, библиотека и project-правила создаются свои.

  • global задаёт умолчание, project уточняет стек
  • версия по CalVer: 26.11.0
  • первый коммит после docs:check
  • признак готовности: в decisions только свои ADR

Признак готовности: docs:check проходит, в decisions только свои ADR, в GLOSSARY нет чужих терминов, в library нет чужих элементов.

Один вход, четыре истины, один черновик
