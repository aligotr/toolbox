# ADR 0002: Топики и мост между Rust и интерфейсом

- **Статус:** принято
- **Дата:** 2026-11-10
- **Область:** `src-tauri/src/core/`, `src-tauri/src/lib.rs`, `src/core/infra/bus.ts`

## Контекст

Шина живёт в Rust и работает с типами. Интерфейс живёт в Vue и не может
передавать типы Rust — только строки и JSON. Нужна граница, которая:

- не заставляет UI знать внутреннее устройство шины;
- сохраняет типобезопасность на стороне Rust;
- корректно работает с механизмом событий Tauri.

## Решение

1. **Топик объявлен на базовом трейте `Message`.** Каждое сообщение реализует
   `impl Message` (константа `TOPIC`) и затем `impl Event` или `impl Command`.
2. **Разделитель топика — двоеточие:** `core:ping`, `core:pong`, `app:quit`.
   Точка не используется.
3. **Мост — четыре операции:**
   - `send_event(topic, payload)` — событие «выстрелил и забыл»;
   - `invoke_command(topic, payload)` — команда, ошибка возвращается в Promise;
   - `ask(topic, reply_topic, payload, timeout_ms)` — запрос/ответ;
   - подписка на событие через `listen(topic)`.
4. **Маршруты (`register_event_route`, `subscribe_command`) разбирают JSON в
   конкретный тип Rust.** UI работает только со строками.
5. **Приёмник (`EventSink`) пересылает каждое событие в UI** под его топиком.

## Почему так

Tauri v2 разрешает в именах событий только буквы, цифры, `-`, `/`, `:` и `_`.
Топик с точкой (`core.ping`) выглядит привычно, но событие с таким именем до
интерфейса **не дойдёт**. Двоеточие сохраняет читаемость пространства имён и
проходит проверку.

`ask` вынесен в одну операцию моста, чтобы UI не занимался корреляцией вручную.
Но топик ответа передаётся явно: без него шина не может отличить запрос от
ответа (см. ADR 0001).

## Последствия

- Строки топиков — часть контракта между Rust и Vue. Переименование топика
  ломает совместимость и требует правок в двух местах.
- В JS параметры команд приходят в camelCase (`replyTopic`, `timeoutMs`), Tauri
  сам сопоставляет их со snake_case (`reply_topic`, `timeout_ms`) в Rust.
- События в UI приходят с нагрузкой в виде JSON-объекта; типы описываются
  интерфейсами TypeScript на стороне модуля.
- Тесты шины не требуют Tauri: маршруты и приёмник подменяются.

## Отклонённые альтернативы

- **Точка в топиках + замена символа в приёмнике.** Работает, но появляется
  скрытое преобразование: в коде `core.ping`, в интерфейсе `core:ping`. Такое
  расхождение быстро становится источником ошибок.
- **Числовые или enum-коды сообщений.** Теряется читаемость логов и сетевых
  событий; для отладки хуже.
- **Отдельный тип для каждого направления (запрос/ответ).** Усложняет шину без
  выгоды: корреляция уже решает задачу.
