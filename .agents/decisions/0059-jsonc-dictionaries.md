# ADR 0059: Расширение jsonc для словарей

- **Статус:** принято
- **Дата:** 2026-11-19
- **Область:** `src-tauri/src/core/services/languages.rs`,
  `src-tauri/src/core/commands/languages.rs`, `src/core/services/languages/`,
  `.scratch/languages-notifications/`, правила `i18n.md`, глоссарий

## Контекст

Словарь интерфейса - JSON с комментариями и висячими запятыми. Ядро разбирает
этот диалект, а заголовок выгруженного файла объясняет, что комментарии
допустимы. При этом файлы назывались `<code>.json`: расширение обещало
строгий JSON, которого в файле нет. Строгие редакторы и внешние инструменты
законно ругались на комментарии, а пользователю приходилось объяснять
расхождение.

Старых внешних словарей нет: единственный `local/languages/en.json` на стенде
удалён, других установок с файлами нет. Поэтому переход не требует читать
два расширения и разруливать два файла с одним кодом.

## Решение

1. **Каноническое расширение - `.jsonc`.** Так называются внешний словарь
   `<code>.jsonc`, файл дополнений `<code>.missing.jsonc` и образец
   `<code>.template.jsonc`.
2. **`.json` не читается.** Каталог принимает только `.jsonc`; старый файл
   с тем же кодом словарём не считается. Наследства нет: файлов не осталось,
   а двойное расширение вернуло бы неоднозначность «какой файл главный».
3. **Диалект не меняется.** Внутри по-прежнему JSONC: комментарии, висячие
   запятые, разбор в Rust. Меняется только имя файла.
4. **Один код - один файл.** У языка ровно один внешний файл; приоритет
   между расширениями не нужен.

## Почему так

- **Расширение говорит правду.** `.jsonc` - принятое обозначение JSON
  с комментариями; редакторы включают для него нужный режим сами.
- **Нет двойственности.** Чтение обоих расширений потребовало бы правила
  приоритета, отображения «какой файл перекрывает», отдельного возврата
  и объяснения в списке. Это ровно та сложность, от которой избавился
  ADR 0057.
- **Переход дешёвый.** Файлов нет, миграция не нужна: достаточно поменять
  расширение, пути и тексты.

## Последствия

- `EXTENSION` в `languages.rs` равен `jsonc`; каталог, выгрузка, возврат
  и файл дополнений используют его.
- Старый `local/languages/<code>.json` игнорируется. Если он появится,
  пользователь переименовывает файл в `.jsonc`; приложение его не трогает.
- Тесты каталога явно проверяют, что `.json` не читается.
- Живые документы - правила, глоссарий, задачи - говорят `.jsonc`;
  ADR 0039 и 0057 остаются историей со статусом, уточнённым этим решением.

## Отклонённые альтернативы

- **Оставить `.json`.** Приложение разбирает файл, но расширение обещает
  строгий JSON; расхождение остаётся навсегда.
- **Читать `.json` и `.jsonc` одновременно.** Два файла с одним кодом,
  приоритет, отдельный возврат и подпись в списке ради совместимости
  с файлами, которых нет.
- **Писать строгий JSON без комментариев.** Теряется подсказка в файле,
  а пользовательские комментарии всё равно сделают файл нестрогим.
