# ADR 0069: Общая раскладка инструментов с таблицей

- **Статус:** принято
- **Дата:** 2026-11-23
- **Область:** `src/ui/tool-layout.css`, `src/ui/toolLayout.ts`,
  `src/app/main.ts`, `src/tools/dnslookup/`, `src/tools/icmp/`,
  `.agents/rules/project/ui/architecture.md`, `.agents/rules/project/vue.md`

## Контекст

Ping повторяет форму DNSlookup: шапка с названием и пресетом, строка
добавления, фильтры, таблица с раскрытием строк. При переносе эти части
оказались дважды: разметка получила разные BEM-префиксы, а CSS почти
целиком повторился. Размеры полей, списков, кнопок строки и таблицы были
литералами в двух файлах, и правка одного размера требовала помнить
о втором инструменте.

Правило «стили инструмента живут в `tools/<id>/styles.css`» описывало
один инструмент и не отвечало на вопрос, где место каркасу, который нужен
двоим. Копирование каркаса уже начало расходиться: у Ping поле семейства
было 120 px против 104 px у типа записи DNS, хотя это одна роль
«компактный список рядом с главным полем».

## Решение

1. **Каркас экрана инструмента - `src/ui/tool-layout.css`.** В файле только
   то, что повторяется у инструментов с таблицей: `.tool`, `.tool__body`,
   `.tool__head`, `.tool__toolbar`, `.tool__filters`, `.tool-table*` и кнопки
   строки. Файл подключается один раз в `src/app/main.ts` рядом с
   `global.css`; экраны не импортируют его повторно.

2. **Классы каркаса несут префикс `tool-`, а не имя инструмента.**
   Это защита вместо `scoped`, как `wb-` у оболочки (ADR 0037). Инструмент
   ставит общие классы рядом со своими: `dns-table tool-table`,
   `icmp-table__target tool-table__name`. Своё имя остаётся у того, что
   относится только к инструменту: серверные колонки, ячейка DNS, статусы.

3. **Размеры каркаса - токены `--tool-*` в `:root` того же файла.**
   Главное поле 320 px, компактный список 104 px, поле параметра 92 px,
   нижняя граница поиска 160 px, кнопка строки и стрелка списка 24 px,
   чип 21 px, пустая таблица 200 px, подпись пресета 240 px. Локальные
   правила берут токен вместо числа.

4. **Ширина диалогов - общие константы `src/ui/toolLayout.ts`.**
   Ширина 560 px и потолок 92vw одинаковы у пресетов и настроек серверов;
   значения для `:style` не выразить CSS-токеном без посредника.

5. **Файл инструмента остаётся для своего.** `tools/<id>/styles.css`
   описывает только части, которых нет у соседа: список резолверов DNS,
   параметры прогона Ping, статусы, раскрытие, подсветку строк. Общие
   правила из него удаляются, а не дублируются.

6. **`global.css` не получает стилей инструментов.** Общий каркас - это
   уровень между базой и инструментом, а не глобальный сброс: он нужен
   только экранам с таблицей.

## Почему так

- **Копия расходится молча.** Один и тот же список уже был 104 и 120 px.
  Общий класс и токен фиксируют роль, а не текущее число.
- **Каркас - не стиль инструмента.** Шапка, строка добавления и рамка
  таблицы не знают, что внутри: домен, цель или следующий тип данных.
- **Один импорт.** Файл не зависит от порядка монтирования экранов и не
  попадает в бандл дважды.
- **Префикс вместо `:is(.dns, .icmp)`.** Селектор с перечислением имён
  заставляет править общий файл при каждом новом инструменте; класс
  `tool-*` этого не требует.
- **Токен вместо литерала.** Размер меняется в одном месте, а локальные
  правила читают его по роли.

## Последствия

- DNSlookup и Ping используют одни классы каркаса; `dns__head`,
  `icmp__body`, `dns-table__empty` и подобные удалены.
- Поле семейства Ping стало 104 px, как тип записи DNS: это одна роль.
- Новый инструмент с таблицей не выписывает шапку, фильтры и рамку заново;
  он добавляет только свои части и данные.
- Правило «общий каркас инструментов - `src/ui/tool-layout.css` с классами
  `tool-*` и токенами `--tool-*`, импорт один раз в `main.ts`» становится
  обязательным и попадает в `ui/architecture.md` и `vue.md`.
- Размеры диалогов больше не дублируются в константах инструментов.

## Отклонённые альтернативы

- **Оставить копию в каждом инструменте.** Два файла уже разошлись по
  ширине списка; третий инструмент закрепил бы расхождение.
- **Общий файл с селекторами `:is(.dns, .icmp)`.** Правило пришлось бы
  править при добавлении каждого инструмента, а имена инструментов
  протекали бы в общий слой.
- **Только токены без общих классов.** Размеры стали бы едиными, но
  каркас остался бы скопированным; выигрыш не покрывает дубль.
- **Перенести каркас в `global.css`.** Глобальный файл не содержит
  карточек, полей и таблиц: это правило ADR 0037 остаётся в силе.
- **Сделать каркас компонентом Vue.** У шапки, фильтров и таблицы разные
  слоты и данные; обёртка добавила бы пропсы ради тех же правил.
