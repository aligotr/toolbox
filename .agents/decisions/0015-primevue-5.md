# ADR 0015: Интерфейс на PrimeVue 5

- **Статус:** заменено (ADR 0018)
- **Дата:** 2026-11-12
- **Область:** `package.json`, `src/app/main.ts`, `src/ui/theme.ts`,
  `.env.local`, `.gitignore`

## Контекст

ADR 0009 выбрал PrimeVue 4 как основу интерфейса, ADR 0013 зафиксировал
мажор 4: мажор 5 распространяется по PrimeUI License, на старте проверяет
ключ и без ключа показывает в углу окна баннер «Invalid PrimeUI License».

Сейчас актуальная версия — PrimeVue 5.0.5. Миграционный гид v5 утверждает,
что публичные API компонентов не менялись: существующее приложение
обновляется без правок кода. Базовая типографика v5 — 16 px, и проект уже
живёт на базе 16 px (ADR 0009), поэтому compat-пресет для 14 px не нужен.

Лицензия v5 двойная: Community и Commercial. Community бесплатна для
физлиц и небольших организаций (до $1 млн выручки, меньше 5 разработчиков,
меньше 10 сотрудников, до $3 млн внешнего финансирования). Для работы нужен
ключ, который выдаётся после регистрации на primeui.dev; проверка идёт
офлайн.

## Решение

1. Проект переходит на **PrimeVue 5.0.5** и **`@primeuix/themes` 3.1.1**.
   Версии записываются точно, без `^`: `npm install primevue` без версии
   снова поставит другой мажор.
2. Ключ передаётся в конфигурацию PrimeVue из переменной сборки
   `VITE_PRIMEUI_LICENSE`. Значение живёт в `.env.local`, файл добавлен
   в `.gitignore`; ключ не попадает в репозиторий.
3. Тема остаётся одной: preset `toolboxPreset` поверх стандартного Aura
   (16 px). Разметка экранов не переписывается под новые токены.
4. Переход выполняется **сразу для всего приложения**: в одном
   `package.json` нельзя держать v4 для старых экранов и v5 для DNS.
   Отдельным последующим тикетом остаётся только уборка устаревших API
   (`MultiSelect`, `InputChips`, свойства `Button`), которые в v5 ещё
   работают.
5. Новый код DNS пишется сразу на API v5: `Select` с `multiple` вместо
   `MultiSelect`, `InputTags` вместо `InputChips`, `ToggleSwitch` вместо
   `InputSwitch`, `Popover` вместо `OverlayPanel`.

## Почему так

- **Ломающих изменений нет.** v5 сохраняет публичные API компонентов,
  поэтому обновление не превращается в переписывание оболочки.
- **База 16 px совпадает.** Проект уже задаёт 16 px, значит стандартный
  Aura даёт тот же масштаб, что и v4; compat-вариант не нужен.
- **Ключ — единственное новое требование.** Без него приложение работает,
  но показывает баннер, который нельзя скрыть стилями: он живёт в закрытом
  shadow root. Это видно пользователю и неприемлемо для рабочего экрана.
- **Точные версии.** Сборка остаётся воспроизводимой, а обновление мажора —
  осознанное действие, а не побочный эффект `npm install`.

## Последствия

- Без `VITE_PRIMEUI_LICENSE` приложение показывает баннер лицензии.
  Ключ обязателен для разработки и для сборки, которая уходит пользователю.
- Ключ встроен в собранный интерфейс. Для личного переносимого приложения
  это приемлемо; передавать сборку третьим лицам нельзя.
- Устаревшие API v5 продолжают работать до v6. Их замена — отдельная задача
  после DNS; новый код их не использует.
- Обновление зависимостей больше не может незаметно сменить мажор:
  версии зафиксированы.

## Отклонённые альтернативы

- **Остаться на PrimeVue 4.** Дешевле сегодня, но v4 больше не развивается,
  а весь новый код пришлось бы писать на устаревшем API и переписывать
  следом.
- **PrimeVue 5 без ключа.** Баннер «Invalid PrimeUI License» в правом нижнем
  углу виден на всех экранах; обход стилями запрещён лицензией и технически
  ненадёжен.
- **Ключ в исходниках или в `local/settings.json`.** В исходниках ключ
  утёк бы в репозиторий; в настройках — потребовал бы асинхронной загрузки
  до монтирования приложения и привязки к машине. Переменная сборки —
  наименьшая цена.
- **Держать v4 для старых экранов и v5 только для DNS.** Две версии одной
  библиотеки в одном бандле: конфликт символов и стилей, двойной вес.
