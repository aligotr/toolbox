# ADR 0056: Упразднение раздела настроек «Данные»

- **Статус:** принято
- **Дата:** 2026-11-18
- **Область:** `src/workbench/settings/`, `src/core/services/`,
  `src/core/contracts/`, `src-tauri/src/core/`, словари ru/en

## Контекст

Раздел «Данные» показывал размеры лога и папок инструментов активного
профиля и умел переносить данные одного инструмента в `local/trash/data/`.
К моменту разбора экран повторял то, что уже видно рядом: занятое место
профиля показывает раздел «Профили» (`profiles_usage`), а файлы лога чистит
раздел «Журнал» по сроку хранения. Отдельная кнопка удаления данных
инструмента в работе не использовалась.

Владелец попросил убрать раздел.

## Решение

1. **Пункт «Данные» исчезает из списка разделов.** `SettingsSection` больше
   не содержит `data`, `SettingsView` не рисует раздел и не принимает
   `tools`.
2. **Удалены команды и их обвязка.** `storage_stats` и `tool_data_clear`
   сняты с регистрации в `lib.rs`, удалены из `commands/info.rs`. Удалены
   сервис `services/data.rs`, фронтовые `contracts/data.ts`,
   `services/data.ts`, `sections/DataSection.vue`, `formatBytes.ts`.
3. **Статистика профиля остаётся.** В `store/stats.rs` сохранены
   `DirStats`, `dir_stats` и `profile_usage`: ими живёт `profiles_usage`.
   `StorageStats`, `ToolStats`, `summary` и `tools` удалены.
4. **Чистка логов переезжает в отдельный сервис.** `pruneLogs` и его
   состояние живут в `src/core/services/logs.ts`; ключи журнала -
   `journal.logs.pruned` и `journal.logs.pruneError`. Раздел «Журнал»
   работает как раньше.
5. **Удаление профиля не затрагивается.** `profile_delete` по-прежнему
   переносит папку `profiles/<id>/` в `local/trash/`. Точечной очистки
   данных одного инструмента в интерфейсе не остаётся: данные уходят
   вместе с профилем.

## Почему так

Раздел отвечал на вопрос «сколько занято» и «удалить данные инструмента»,
но ни один из ответов не был ежедневным. Размеры профиля спрашивают при
уборке профилей, логи - при разборе отказа. Держать третий экран ради двух
кнопок значило дублировать навигацию и словарь.

Удаление данных инструмента безвозвратно убирало единственную копию списка,
поэтому шло через корзину. Теперь этого действия нет, и случайно стереть
данные инструмента из настроек нельзя: профиль удаляется целиком и тоже
в корзину.

## Последствия

- В интерфейсе нет способа очистить данные одного инструмента, не трогая
  профиль. Если действие понадобится, его место - экран инструмента.
- Ядро не считает размеры лога и разбивку по инструментам: счётчик остаётся
  только у профиля.
- `Storage::data_trash_dir()` удалён вместе с единственным потребителем.
  Путь `local/trash/data/` приложение больше не создаёт; то, что было
  удалено раньше, остаётся на диске, пока корзину не почистят руками.
- Ключи `settings.data.*`, `journal.data.*`, `settings.section.data`,
  `units.*` и `errors.data.*` удалены из обоих словарей: без раздела
  и его сервисов переводить их нечему.
- Список держателей состояния (`check-zones.mjs` и ADR 0047) обновлён:
  `services/data` заменён на `services/logs`, иначе сборка видит Vue в ядре
  без права на него.

## Отклонённые альтернативы

- **Оставить раздел только с размерами.** Экран повторял бы «Профили»
  и «Журнал» без нового действия.
- **Перенести удаление данных на экран инструмента сразу.** Для этого нужен
  экран инструмента и решение, где показывать размеры; это отдельная задача,
  а не часть уборки настроек.
- **Оставить `tool_data_clear` без интерфейса.** Команда без вызывающего -
  мёртвый код в точке сборки и лишняя поверхность для ошибок.
