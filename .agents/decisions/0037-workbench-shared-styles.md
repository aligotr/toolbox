# ADR 0037: Общие стили оболочки — каркас экрана и пункт рейла

- **Статус:** принято
- **Дата:** 2026-11-16
- **Область:** `src/workbench/`, `.agents/rules/project/ui/architecture.md`

## Контекст

К концу ревизии стилей два файла оболочки переросли ориентир по `<style>`
(ADR 0036 п. 8): `Sidebar.vue` — 388 строк, из них 201 в стилях;
`EmptyTab.vue` — 329 строк, из них 211 в стилях.

Причина была не в объёме разметки, а в копировании: один и тот же пункт рейла
выписан четыре раза (инструмент, журнал, настройки, профиль), шапка экрана —
трижды (`journal__*`, `settings__*`, `empty__*`), заголовок раздела — шесть раз
(`app__*`, `data__*`, `log__*`, `profiles__*`, `templates__*`, `window__*`),
а карточки шаблона и инструмента дублировали базу с состояниями.

Правило ADR 0036 п. 7 знало два уровня общих стилей: `global.css` для документа
и `tools/<id>/styles.css` для классов инструмента. У оболочки такого уровня
не было, хотя она состоит из десятка экранов с одинаковым каркасом.

## Решение

1. **Пункт рейла — компонент `RailItem.vue`.** Иконка, подпись, активное
   состояние, свёрнутый вид, подсказка и шеврон. `Sidebar.vue` остаётся
   каркасом: шапка, две группы пунктов, подвал профиля. Сайдбар передаёт
   данные и ловит `click`, вид и состояния не повторяет.

2. **Общий файл оболочки — `src/workbench/styles.css`.** В нём только
   каркас, нужный нескольким экранам:

   | Класс | Что задаёт |
   |---|---|
   | `wb-screen__head / __title / __lead` | шапка экрана: название и пояснение |
   | `wb-section` | раздел экрана: вертикальный список с шагом |
   | `wb-section__head / __title / __lead` | шапка раздела внутри экрана |

   Файл подключается один раз — `import "./styles.css"` в `WorkbenchView.vue`,
   как стили инструмента в корневом view.

3. **Префикс `wb-` — защита вместо `scoped`.** Файл общий, значит правила
   видны всем компонентам внутри оболочки; префикс отделяет каркас от блоков
   конкретного экрана (`journal__*`, `settings__*`).

4. **Повторяющийся контрол становится компонентом, а не общим классом.**
   У пункта рейла есть пропсы и событие; это ответственность, а не набор
   правил. Стили `RailItem` остаются `scoped`.

5. **Карточка-действие остаётся в `EmptyTab.vue`.** `.action-card` с
   модификаторами `--template` и `--tool` нужна одному экрану, поэтому в общий
   файл не переезжает: правило выносится, когда нужно двоим (ADR 0036 п. 7).

6. **Токены оболочки живут в `.workbench`, а не в `:root`.** Рядом с ширинами
   сайдбара: `--ag-tile-size` (плитка шапки), `--ag-content-catalog` (потолок
   каталога), `--ag-content-settings` (потолок настроек). Компоненты читают их
   как унаследованные переменные.

7. **В общий файл не попадает ничего однократного.** Точка статуса, миниатюра
   раскладки, строки списков, поля и диалоги остаются в своих компонентах.
   `global.css` по-прежнему не содержит карточек, кнопок и диалогов.

## Почему так

- **Копия расходится.** Четыре пункта рейла уже начали отличаться: у профиля
  подпись мельче и есть шеврон, у разделов нет. Компонент фиксирует различие
  пропсом, а не второй копией правил.
- **Каркас экрана — не стиль экрана.** Шапка и раздел описывают раскладку
  оболочки, а не содержимое журнала или настроек. Их место — рядом с оболочкой.
- **Общий файл без `scoped` дешевле, чем протаскивание `:deep()`.** Стили
  инструмента уже живут так (ADR 0036 п. 7); оболочка получает то же правило
  с собственным префиксом.
- **Один импорт** не даёт бандлу двух копий и не зависит от порядка
  монтирования экранов.
- **Токен вместо числа** сохраняет смысл: «плитка шапки» и «потолок каталога»
  меняются в одном месте, а не поиском по файлам.

## Последствия

- `Sidebar.vue` — 295 строк (стили 117 вместо 201); `RailItem.vue` — 125
  (стили 59). `EmptyTab.vue` — 280 (стили 157 вместо 211).
- Экраны оболочки используют `wb-screen__*` и `wb-section*`; локальные
  `__head / __title / __lead` у заголовков удалены. Свои обёртки остаются там,
  где шапка — строка с действиями (`journal__head`, `profiles__head`).
- Новый экран оболочки не выписывает шапку заново: он берёт классы из
  `styles.css`.
- `EmptyTab` остаётся чуть выше ориентира 150 строк по стилям. Это сигнал,
  а не дубль: карточки в отдельные компоненты не выносятся, пока их не
  использует второй экран.
- Межстрочный пояснений берётся из `:root` (1.5) и в общих классах не
  повторяется. Плотный межстрочный остаётся только у заголовка экрана:
  базовые 1.5 рассчитаны на текст, а не на строку в 24 px.
- Правило «стили оболочки — `src/workbench/styles.css` с префиксом `wb-`,
  импорт один раз в `WorkbenchView.vue`» становится обязательным и попадает
  в `ui/architecture.md`.

## Отклонённые альтернативы

- **`<style scoped src="./sidebar.css">`.** Область видимости сохраняется,
  но CSS не уменьшается: это обход метрики, а не устранение копий.
- **Вынести каждый пункт рейла в отдельный компонент** (инструмент, журнал,
  профиль). Три файла с почти одинаковой разметкой — то же копирование,
  только по папкам.
- **Общий CSS ради одного контрола** (пункт рейла классом, точка статуса).
  Нарушает условие «правило выносится, когда нужно двоим».
- **Перенести `.action-card` в `global.css`.** Запрещено правилами интерфейса:
  глобальный файл не содержит карточек.
- **Дробить `EmptyTab` по 40 строк.** Прямо запрещено ADR 0036: файл короче
  ~60 строк оправдан только именованной ответственностью.
