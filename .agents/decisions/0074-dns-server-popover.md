# ADR 0074: Серверы DNS выбираются в поповере, а не в строке добавления

- **Статус:** принято; место строки добавления уточнено ADR 0076
- **Дата:** 2026-11-24
- **Область:** `src/tools/dnslookup/`, `.agents/rules/project/ui/elements.md`,
  `.scratch/dnslookup/spec.md`

## Контекст

Выбор резолверов DNS жил в строке добавления рядом с полем домена и типом
записи. Это был `MultiSelect` с чипами: два выбранных сервера занимали
около 290 px, остальные прятались за счётчиком «+N». Список настраивал
проверку, но стоял в месте, где пользователь вводит данные, и отнимал
ширину у главного поля. Свои серверы открывались отдельной кнопкой рядом,
хотя относятся к тому же выбору.

Владелец попросил убрать список из верхней строки, перенести его в поповер
шестерёнки и сделать выбор компактным: название и адрес в одну строку,
флажок меньше, все серверы видны без прокрутки. Настройка своих серверов
должна открываться оттуда же.

## Решение

1. **Список серверов живёт в поповере «Серверы проверки».** Шестерёнка
   стоит в строке фильтров рядом с «Проверить». Список резолверов больше
   не занимает строку добавления.
2. **Выбор - флажки, а не выпадающий список.** Каждый сервер занимает одну
   строку: флажок 16×16, название, точка-разделитель и адрес. У системного
   сервера виден первый адрес и счётчик остальных (`+3`); полный список
   адресов раскрывает системная подсказка. Длинные название и адрес
   обрезаются многоточием, полный текст остаётся в подсказке.
3. **Счётчик и предел.** Над списком стоит «Выбрано N из 8». При восьми
   выбранных серверах невыбранные флажки блокируются, а под списком
   появляется пояснение. Снять можно любой сервер, включая последний:
   тогда проверка недоступна, а шестерёнка предупреждает цветом.
4. **Свои серверы открываются из поповера.** Кнопка «Свои DNS-серверы»
   внизу поповера открывает существующий диалог. После добавления свой
   сервер сразу становится выбранным, если есть место.
5. **Кнопка «Проверить» переехала в строку фильтров.** Строка добавления
   теперь содержит только домен, тип записи и кнопку добавления.
6. **Выбор сервера не запускает проверку.** Появляется или скрывается
   колонка, данные остаются в сеансе. Это поведение не изменилось.
7. **Токен высоты чипа удалён.** Чипов в интерфейсе больше нет;
   `--tool-chip-height` не используется.

## Почему так

- **Настройка отделена от ввода.** Домен и тип относятся к строке, серверы -
  к проверке целиком. Разные задачи не должны делить одну строку.
- **Поповер даёт место без потери контекста.** В нём помещаются название,
  адрес, счётчик и действия; строка добавления остаётся короткой.
- **Одна строка на сервер читается быстрее чипов.** Видно все адреса,
  а не два чипа и загадочное «+N».
- **Флажки честнее выпадающего списка.** Текущий выбор виден сразу,
  без раскрытия; предел объясняется блокировкой, а не молчаливым отказом.
- **Свои серверы рядом с выбором.** Пользователь не ищет вторую кнопку:
  оба действия относятся к одному списку.

## Последствия

- Строка добавления DNS стала короче; ширины домена и типа из ADR 0054
  остаются в силе, а часть про список резолверов устарела.
- В `DnslookupView.vue` появились поповер, счётчик и обработчик переключения;
  `MultiSelect`, `Chip` и `SERVER_LABEL_LIMIT` удалены.
- Выбор серверов больше не влияет на ширину строки добавления и не
  переносится на узком окне.
- Свои серверы по-прежнему хранятся в профиле и открываются тем же диалогом.
- Если понадобится другой способ выбора серверов, он заменит поповер
  отдельным решением, а не вернёт чипы в строку.

## Отклонённые альтернативы

- **Оставить `MultiSelect`, но сузить.** Чипы и счётчик «+N» всё равно
  скрывали адреса и делили строку с вводом домена.
- **Отдельный модальный диалог выбора серверов.** Для четырёх-шести
  серверов это тяжёлый слой; поповер ближе к кнопке и не запирает экран.
- **Список без флажков, только подсветка строки.** Не видно, что выбор
  множественный, и сложнее снимать серверы.
- **Оставить свои серверы отдельной кнопкой в строке.** Два входа
  в одну настройку разошлись бы по смыслу и месту.
