# ADR 0003: Внедрение зависимостей и порядок инициализации

- **Статус:** принято
- **Дата:** 2026-11-10
- **Область:** `src-tauri/src/core/infra/deps.rs`, `src-tauri/src/core/infra/bus.rs`,
  `src-tauri/src/lib.rs`, `src-tauri/src/modules/`

## Контекст

В Python-образце зависимости внедряются **по имени параметра**: шина читает
сигнатуру обработчика и подставляет значения из словаря. В Rust рефлексии нет —
сигнатуру функции во время выполнения прочитать нельзя.

Кроме того, порядок запуска критичен: если обработчик зарегистрирован раньше,
чем появилась зависимость, он упадёт при первом вызове. Если событие
опубликовано раньше, чем модуль подписался, оно потеряется.

## Решение

1. **Внедрение по типу.** Контейнер `Deps` хранит значения по `TypeId`.
   Обработчик получает `&Deps` и вызывает `get::<T>()` или `require::<T>()`.
2. **`require` паникует при отсутствии зависимости.** Это ошибка программиста
   (нарушен порядок), а не штатная ситуация.
3. **Строгий порядок инициализации:**
   `зависимости → шина → приёмник → регистрация модулей → bus.start() →
   app.manage(bus)`.
4. **Остановка — в `RunEvent::Exit`,** то есть в потоке ОС, а не в диспетчере.
5. **Список подсистем — `modules::register_all`.** Новая подсистема
   подключается одним файлом и одной строкой.

## Почему так

- В Rust тип — единственный надёжный ключ, известный и компилятору, и рантайму.
  Имя параметра недоступно, а строка-ключ подвержена опечаткам.
- `Deps` внутри — `Arc<RwLock<HashMap<...>>>`, поэтому клонируется дёшево и
  безопасно делится между обработчиками.
- Паника в `require` лучше тихого `None`: отсутствие зависимости означает, что
  приложение собрано неправильно, и это нужно заметить сразу.
- `bus.start()` последним гарантирует, что к моменту первой доставки все
  подписчики уже на месте.
- `stop()` только из потока ОС исключает `join()` самого себя.

## Последствия

- Обработчики не создают зависимости сами — это упрощает тесты: в тесте
  достаточно собрать `Deps` без Tauri.
- Порядок в `run()` нельзя переставлять; при добавлении новой зависимости её
  регистрируют до `bus.start()`.
- Модуль не должен обращаться к другому модулю напрямую: только через шину.
- Ошибка в `require` роняет обработчик; для событий она изолируется
  `catch_unwind`, для команд — пробрасывается как паника (в разработке это
  допустимо, в продакшене требует осторожности).

## Отклонённые альтернативы

- **DI по строковому имени.** Повторяет Python-образец, но теряет проверку
  компилятора и провоцирует опечатки.
- **Глобальные синглтоны (`OnceLock`, `lazy_static`).** Скрывают зависимости,
  мешают тестам и создают неявный порядок инициализации.
- **Ленивая инициализация шины при первом обращении.** Не даёт гарантии, что
  все подписчики зарегистрированы до первого события.
