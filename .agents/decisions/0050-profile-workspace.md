# ADR 0050: Рабочее пространство принадлежит профилю

- **Статус:** принято
- **Дата:** 2026-11-17
- **Область:** `src-tauri/src/core/store/storage.rs`,
  `src-tauri/src/core/commands/{workspace,profiles}.rs`,
  `src-tauri/src/core/services/{workspace,profiles}.rs`,
  `src-tauri/src/lib.rs`, `src/core/services/workspace/`, `README.md`,
  `.agents/GLOSSARY.md`

## Контекст

Сейчас рабочее пространство одно на приложение: `local/workspace.json`.
Профили меняют пресеты и данные инструментов, но открытые вкладки остаются
общими. При переключении профиля приложение перезапускается, вкладки
восстанавливаются те же, а инструменты создают сеансы уже с данными нового
профиля.

Нужно, чтобы у каждого профиля был свой набор вкладок. При этом ADR 0010
поместил рабочее пространство в `local/` осознанно: вкладки — частое
машинное состояние, и каждое перетаскивание границы колонки не должно
попадать в синхронизируемую папку профиля.

## Решение

1. **Файл профиля — `local/workspaces/<id>.json`.** `<id>` — идентификатор
   активного профиля из `local/settings.json`. Формат не меняется: версия 1,
   вкладки, колонки и активная вкладка.

2. **Рабочее пространство остаётся машинным.** Оно не переезжает в
   `profiles/`: синхронизация профилей не должна получать конфликты от
   частых правок раскладки. Это сохраняет границу ADR 0010, меняется только
   путь внутри `local/`.

3. **Плоская раскладка.** Один файл на профиль, без папки `<id>/`:
   сегодня машинного состояния на профиль ровно одно. Если появится второе,
   переезд `<id>.json` → `<id>/workspace.json` — один `rename` в рамках
   новой функции, версия формата для этого не нужна.

4. **Миграции нет.** Приложение не выпущено, поэтому старый
   `local/workspace.json` новая версия не читает. Файл удаляется вручную;
   первый запуск даёт одну пустую вкладку.

5. **Уборка — три точки, все без корзины.** Рабочее пространство — машинное
   состояние, а не данные пользователя:
   - при удалении профиля его файл удаляется сразу;
   - при создании профиля удаляется остаток с тем же `<id>`: идентификатор
     был свободен, значит файл осиротел (иначе новый профиль унаследовал бы
     чужие вкладки после повторного использования имени);
   - при запуске удаляются все файлы, кроме `<id>.json` существующих
     профилей: осиротевшие, `*.tmp` от прерванной записи, конфликтные копии
     и случайные имена. Каталоги не трогаются и попадают в лог
     предупреждением. Если папку профилей не удалось прочитать, уборка
     не запускается.

6. **Пути — в `Storage`, уборка — в сервисе `workspace`.** `Storage` создаёт
   папку `local/workspaces/` при проверке записи и отдаёт путь активного
   профиля. Сервис `workspace` выполняет `forget` и `prune`: правило «что
   оставить» — его ответственность, а «что считать профилем» он не решает,
   а спрашивает у сервиса `profiles`. Точка сборки только пишет отчёт в лог.

## Почему так

- **Требование — своё рабочее пространство, а не синхронизация вкладок.**
  Плоский файл в `local/` даёт разный набор вкладок у профилей и не меняет
  правила синхронизации.
- **Частое состояние не попадает в `profiles/`.** Иначе перетаскивание
  границы колонки создавало бы конфликтные копии, которые некому разбирать.
- **Уборка без корзины.** Восстанавливать вкладки, которых пользователь
  не просил сохранять, незачем; корзина остаётся для профилей, пресетов
  и данных.
- **Один файл — одна сущность.** Уборка читается как список файлов, а не
  как обход дерева; ошибка в одном профиле не задевает остальные.

## Последствия

- При переключении профиля после перезапуска открывается его набор вкладок;
  у нового профиля — одна пустая вкладка.
- Удаление профиля уносит его вкладки; повторное создание профиля с тем же
  именем не подхватывает старые.
- Старый `local/workspace.json` остаётся мусором до удаления вручную.
- `Storage::probe` создаёт `local/workspaces/`; ошибки чтения папки профилей
  больше не приводят к удалению чужих вкладок.
- ADR 0010 остаётся в силе, кроме точного пути рабочего пространства:
  файл по-прежнему машинный и не синхронизируется.
- Упоминания `local/workspace.json` в более ранних ADR и закрытых задачах
  считаются историческими.

## Отклонённые альтернативы

- **`profiles/<id>/workspace.json`.** Вкладки переезжали бы вместе
  с профилем, но частая запись раскладки создавала бы конфликты
  синхронизации; это разворот границы ADR 0010.
- **Один `local/workspace.json` с картой профилей.** Любая правка вкладок
  перезаписывала бы документ всех профилей, а конфликт затрагивал бы сразу
  все наборы.
- **Папка `local/workspaces/<id>/` на будущее.** Пустой каталог, рекурсивная
  уборка и лишний уровень без второго артефакта; переезд позже дешевле.
- **Миграция старого файла.** Приложение не выпущено; код миграции дороже
  ручного удаления одного файла.
- **Корзина для рабочих пространств.** Машинное состояние не является
  данными пользователя, а интерфейса восстановления всё равно нет.
