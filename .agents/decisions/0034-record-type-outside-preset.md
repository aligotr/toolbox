# ADR 0034: Тип новых строк — состояние сеанса, а не пресета

- **Статус:** принято
- **Дата:** 2026-11-16
- **Область:** `src/tools/dnslookup/types.ts`,
  `src/contracts/presets.ts`, формат `payload` пресета DNSlookup

## Контекст

Пресет DNSlookup хранил `defaultType` — тип, который получают новые строки
(ADR 0028, п. 1 и 9). Поле попадало в снимок настроек и участвовало в
сравнении, поэтому смена типа в строке добавления зажигала «изменён», хотя
ни одна строка таблицы не менялась. Владелец менял тип перед вводом домена
и получал ложный признак правки пресета.

Тип нужен только на момент добавления строки: сама строка хранит свой тип.
В сохранённом входе инструмента это значение ничего не задаёт — при
загрузке пресета все строки приходят со своими типами.

## Решение

1. **`defaultType` исключён из `DnsPresetPayload`.** Поле убрано из
   разбора, сборки снимка, применения пресета и отката правок.

2. **Тип новых строк — состояние сеанса.** `DnsSession.defaultType` остаётся:
   новому сеансу он достаётся из `DEFAULT_RECORD_TYPE`, дальше живёт сам
   по себе и на «изменён» не влияет.

3. **Старые файлы читаются без ошибки.** Разбор пропускает незнакомое
   поле; сохранение тем же пресетом записывает файл уже без `defaultType`.
   Отдельной миграции нет: поле ни на что не влияло при загрузке.

## Почему так

- **Ложная правка дороже удобства.** «Изменён» означает расхождение
  сохранённого входа с текущим; тип добавления к нему не относится.
- **Полное исключение, а не тихое игнорирование при сравнении.** Если
  оставить поле в файле, но не сравнивать, файл молча расходился бы
  с сеансом: записанное значение ни на что не влияет и вводит в заблуждение.
- **Строки самодостаточны.** Тип у каждой строки свой, поэтому пресету
  нечего восстанавливать в поле добавления.

## Последствия

- Смена типа в строке добавления больше не даёт «изменён»; откат правок
  тип не трогает.
- Сохранение пресета не пишет `defaultType`; формат `payload` стал меньше,
  версия конверта не меняется (ADR 0028, п. 2).
- ADR 0028, п. 1 и 9, в части «тип новых строк» считается уточнённым этим
  решением; остальные пункты действуют.

## Отклонённые альтернативы

- **Оставить `defaultType` в файле, но не сравнивать.** Файл хранил бы
  значение, которое ни на что не влияет, и расходился бы с сеансом.
- **Сравнивать только при загрузке.** Признак «изменён» всё равно зажигался
  бы от смены типа, то есть проблема оставалась.
