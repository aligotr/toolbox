# ADR 0047: Vue в ядре — только реактивность состояния

- **Статус:** принято
- **Дата:** 2026-11-17
- **Область:** `src/core/`, `src/tools/dnslookup/`, `scripts/check-zones.mjs`, `.agents/rules/`

## Контекст

Аудит кодовой базы показал: десять модулей `src/core` импортируют `vue`
напрямую — `reactive`, `ref`, `computed`, `watch`, `toRaw`. Само по себе
это не ошибка: состояние домена должно быть наблюдаемым, иначе компоненты
не узнают об изменении вкладок, журнала или словаря.

Проблема в другом. Вместе с состоянием Vue протёк в правила. Разбор
`local/workspace.json` живёт внутри `workspace/index.ts` рядом с реактивным
состоянием и `watch`, а проверка DNS-ввода тянет `t()` из `i18n`, который
поднимает реактивный каталог. В итоге правило «какая вкладка считается
битой» и правило «какой домен допустим» нельзя выполнить без рантайма Vue:
тесты требуют заглушку фреймворка, а сами правила перестают быть переносимыми.

ADR 0039 уже зафиксировал принцип «чистые функции без Vue» — но применил его
только к механизму перевода (`translate.ts`). Граница не была ни описана,
ни проверена, поэтому остальной домен её не заметил.

## Решение

1. **Vue в ядре разрешён только держателям состояния.** Это модули, которые
   создают наблюдаемое состояние и живут до конца сеанса:
   `core/infra/journal`, `core/infra/i18n/catalog`, `core/infra/useAsyncAction`,
   `core/services/appInfo`, `core/services/languages`, `core/services/logs`,
   `core/services/presets/index`, `core/services/profiles`,
   `core/services/settings/index`, `core/services/workspace/index`.
   Разрешённые примитивы — `reactive`, `ref`, `computed`, `watch`, `toRaw`.

2. **Правила не импортируют Vue — ни прямо, ни через импорты.** Модули
   правил: `core/infra/guards`, `core/infra/i18n/locale`,
   `core/infra/i18n/translate`, `core/services/workspace/layout`,
   `core/services/workspace/parse`, `core/services/workspace/recentTabs`,
   `tools/dnslookup/normalize`. Цепочка импортов от них до `vue` или
   `@tauri-apps/` — нарушение.

3. **Разбор файла рабочего пространства выносится в `workspace/parse.ts`.**
   Функции `parseTab`, `singleTab`, `parseFile` покидают реактивный модуль;
   `index.ts` вызывает `parseWorkspaceFile`. Поведение и формат не меняются.

4. **Проверка DNS возвращает код словаря, а не готовый текст.**
   `parseAddressInput` и `parseServerAddress` отдают
   `{ ok: false, code, params }`; перевод выполняет вызывающий слой.
   Коды записаны литералами в `code:`, поэтому полнота словаря остаётся
   под проверкой `check-messages`.

5. **Граница проверяется сборкой.** `scripts/check-zones.mjs` падает, если:
   - файл `src/core` импортирует `vue`/`@vue/` и его нет в списке держателей;
   - от модуля правил достижим `vue` или `@tauri-apps/` по цепочке импортов.

6. **Правила проверяются без заглушек.** Тесты модулей правил идут через
   `node --test` с резолвером `@/` и расширений, без подмены Vue.

## Почему так

- **Правила — то, что должно быть проверяемым.** Разбор файла и валидация
  ввода определяют, увидит ли пользователь свои вкладки и уйдёт ли запрос
  в ядро. Это части, которые обязаны тестироваться без фреймворка.
- **Реактивность — законная работа Vue.** Свой стор пришлось бы писать
  с нуля: отслеживание вложенных мутаций, планирование эффектов, кэш
  производных. Vue это уже делает и стоит в зависимостях.
- **Документ без проверки расходится с кодом.** Поэтому граница закреплена
  в `check-zones`, а не только в этом ADR: новое правило без Vue проходит
  молча, нарушение — валит сборку с цепочкой импортов.
- **Цена полного отказа не оправдана.** Приложение не выпущено, клиент один,
  домен вне приложения не нужен. Свой стор добавил бы риск в сохранение
  рабочего пространства и в смену языка ради переносимости без потребителя.

## Последствия

- Новый модуль ядра по умолчанию без Vue. Если ему действительно нужно
  наблюдаемое состояние, файл добавляется в список держателей осознанно.
- Новый модуль правил добавляется в список `PURE_MODULES`; сборка проверяет
  его цепочку импортов.
- `normalize.ts` больше не знает о словаре: тексты ошибок собираются
  в `state/rows.ts` и `ServerDialog.vue` через `t(code, params)`.
- Тесты правил не требуют заглушки Vue; для тестов держателей состояния
  заглушка остаётся допустимой.
- `@vue/reactivity` как отдельный пакет не берётся: это та же зависимость
  под другим именем и новый пакет в сборке.

## Отклонённые альтернативы

- **Полностью убрать Vue из ядра.** Свой `state.ts` с подписками, переписать
  десять модулей и всех потребителей. Риск: вложенные мутации колонок
  и записей, автосохранение на `watch`, перерисовка при смене языка.
  Покупает переносимость домена, которой некому пользоваться. Вернуться
  к этому стоит только при втором клиенте или выносе домена в библиотеку.
- **Импортировать `@vue/reactivity` вместо `vue`.** Оптическая чистота:
  зависимость остаётся Vue, появляется второй пакет, тесты по-прежнему
  требуют флагов сборки.
- **Тонкий фасад `core/infra/state.ts` с реэкспортом примитивов.** Скрывает
  зависимость, не убирая её; добавляет слой без поведения.
- **Оставить как есть и записать в правиле.** Граница, которая держится
  только документом, исчезает при первой спешной правке — это уже произошло
  с принципом из ADR 0039.
