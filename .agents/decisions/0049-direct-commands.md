# ADR 0049: Прямые команды Tauri и команды шины

- **Статус:** принято
- **Дата:** 2026-11-17
- **Область:** `src/core/services/`, `src/core/infra/bus.ts`,
  `src-tauri/src/core/commands/`

## Контекст

В приложении два канала «интерфейс → ядро»:

- **шина** — команды и события модулей: интерфейс называет топик
  (`dnslookup:check`), ядро находит обработчик, зарегистрированный модулем;
- **прямая команда Tauri** — `invoke("settings_get")` и подобные: имя
  функции Rust, аргументы и результат описаны типами.

Большая часть прямых вызовов — оболочка и её сервисы: настройки, рабочее
пространство, профили, пресеты, словари, сведения о программе. Это не домен
модуля, и топик у них был бы лишним уровнем адресации: сервис один, имя
команды уже однозначно.

Отдельно стоят пять вызовов: `exit_app`, `log_frontend`, `open_folder`,
`profile_switch`, `app_restart` (удалена, см. дополнение ниже). Они обходят
шину осознанно: это управление процессом, окном и ОС, а не операция над
данными. Но правило нигде не записано, поэтому следующая правка может
«выровнять» их через шину (и сломать выход при заблокированном запуске) или
добавить шестое исключение по вкусу.

## Решение

1. **Домен модуля — только через шину.** Команда или событие модуля
   регистрируется в `Module::register`, интерфейс обращается по топику.
   Прямой `invoke` к внутренностям модуля запрещён: это обход владельца
   команды и корреляции запрос/ответ.

2. **Инфраструктура оболочки — прямой командой.** Настройки, рабочее
   пространство, профили, пресеты, словари, сведения и данные — сервисы
   ядра с единственным экземпляром. Топик не добавил бы ни адресации,
   ни маршрутизации, зато потребовал бы ручного разбора аргументов.

3. **Жизненный цикл, окно, ОС и диагностика — прямой командой, даже если
   шина доступна.** Закрытый список:

   | Команда | Почему мимо шины |
   |---|---|
   | `exit_app` | обязан работать при заблокированном запуске, когда шины ещё нет |
   | `app_restart` | удалена: перезапуск просит `profile_switch` после успешной записи настроек (см. дополнение) |
   | `log_frontend` | отчёт об ошибке JS обязан дойти без шины; уровень закрыт и равен `error` (ADR 0004) |
   | `open_folder` | интегрируется с ОС через `opener`; путь выбирает ядро по имени, а не интерфейс |
   | `profile_switch` | подготовка следующего запуска: интерфейс обязан увидеть отказ записи настроек до перезапуска |

4. **Новый прямой вызов жизненного цикла — только с правкой этого ADR.**
   Условия: операция не принадлежит домену модуля, и либо ей нужна работа
   без запущенной шины, либо она управляет процессом, окном или ОС.
   Если ни одно условие не выполняется — это команда шины.

5. **Место в коде.** Прямые команды лежат в `core/commands` по областям
   (ADR 0048); жизненный цикл — `commands/lifecycle.rs`. Список прямых
   вызовов интерфейса виден поиском `invoke(` в `src/core/services`
   и `src/app`.

## Почему так

- **Выход не должен зависеть от домена.** Блокирующий экран показывается
  до запуска модулей; команда выхода через шину в этот момент вернула бы
  «нет обработчика» и окно осталось бы висеть.
- **Шина — механизм модулей, а не универсальный транспорт.** Её ценность
  в маршрутизации по топикам и корреляции; для одиночного сервиса это
  накладные расходы без выгоды.
- **Список превращает вкус в правило.** Пять исключений уже существуют;
  записанные условия не дают шестому появиться случайно.

## Последствия

- Новый инструмент регистрирует команды в шине; новый сервис оболочки —
  прямой командой в своём файле `core/commands`.
- Проверка «команда модуля не вызывается напрямую» остаётся дисциплиной
  ревью: имена топиков и прямых команд не пересекаются по построению.
- `commands/lifecycle.rs` — единственное место, где живут команды,
  обязанные работать без шины.
- Перенос `profile_switch` в шину потребовал бы отдельного ADR
  и синхронного отчёта об отказе записи до перезапуска.

## Отклонённые альтернативы

- **Все команды — через шину.** Унификация ценой работоспособности
  блокирующего экрана: `exit_app` и `log_frontend` вызываются до старта
  модулей.
- **Все команды — напрямую.** Шина теряет смысл: модули перестают быть
  владельцами своих команд, а корреляция запрос/ответ уезжает в интерфейс.
- **Оставить пять исключений без правила.** Следующая правка либо
  «исправит» их, либо расширит список без обоснования.

## Дополнение от 2026-11-17: перезапуск — часть смены профиля

`profile_switch` сам просит перезапуск после успешной записи настроек.
Интерфейс больше не вызывает `app_restart`, команда удалена: отдельный шаг
оставлял окно, в котором настройки уже указывали на новый профиль, а сеанс
работал со старым. Запись по-прежнему идёт первой — отказ виден интерфейсу
до перезапуска.
