# ADR 0057: Два встроенных языка и внешние словари

- **Статус:** принято; расширение словарей `.jsonc` уточнено ADR 0059,
  ключи до выпуска и файл изменений - ADR 0081
- **Дата:** 2026-11-19
- **Область:** `src/app/locales.ts`, `src/core/services/languages.ts`,
  `src/workbench/settings/sections/LanguageSection.vue`,
  `src-tauri/src/core/services/languages.rs`,
  `src-tauri/src/core/commands/languages.rs`,
  `src-tauri/resources/languages/`, ADR 0039, словари ru/en

## Контекст

ADR 0039 оставил один встроенный словарь - русский, а английский поставлял
внешним файлом: при первом запуске он копировался в `local/languages/en.json`
и дальше не обновлялся. Копия у существующей установки устаревает вместе
с текстами, а отличить нетронутый файл от правленого нечем: маркер `.seeded`
хранит только факт установки.

Отсюда выросла отдельная машинерия: отпечатки, манифест, автообновление
нетронутых копий и кнопка для правленых. Владелец предложил модель проще.

## Решение

1. **Встроенных языков два: `ru` и `en`.** Оба полны, лежат в интерфейсе
   и не требуют файлов. `ru` - эталон ключей и форм склонения; `en` -
   встроенный перевод. Файловый посев и маркер `.seeded` удаляются.
2. **Внешний словарь - всегда файл пользователя.** Приложение его не пишет
   никогда: ни при обновлении, ни при старте, ни по кнопке. Всё, что оно
   создаёт само, - отдельный файл изменений.
3. **Выгрузка делает встроенный язык внешним.** Кнопка у встроенного языка
   создаёт `<code>.json`, только если файла ещё нет. С этого момента файл
   перекрывает встроенный словарь по ключам и принадлежит пользователю.
4. **Возврат к встроенному.** Файл перекрытого встроенного языка переносится
   в `local/trash/languages/`, после чего снова работает встроенный перевод.
5. **Цепочка отката: внешний файл → встроенный тот же код → русский → ключ.**
   Для `de` встроенного источника нет, поэтому после файла идёт русский.
   Для внешнего `en` пропущенный ключ показывает встроенный английский,
   а не русский.
6. **Изменения словаря.** Для внешнего файла считаются ключи, которых нет
   или у которых не хватает форм склонения языка, и ключи, которых больше
   нет в программе. Результат отдаётся файлом `<code>.updates.jsonc`
   с полями `messages` (что добавить, с текстом источника) и `obsolete`
   (что убрать, список ключей):
   - файл генерируется детерминированно и сравнивается с существующим
     побайтово; совпал - не переписывается;
   - при старте генерируется только для активного внешнего языка;
   - в разделе «Язык» - по кнопке «Выгрузить изменения» для любого
     внешнего файла;
   - при пустом наборе и при возврате к встроенному файл удаляется;
   - прежний `<code>.missing.jsonc` убирается: его место занял файл
     изменений;
   - файл изменений не считается словарём: точка в имени исключает его
     из каталога.
7. **Чтение без двойной работы.** Каталог внешних словарей читается
   и разбирается один раз за обращение и отдаёт сообщения вместе со
   сведениями о файле. На старте с внешним языком читается только активный
   файл, без полного каталога.
8. **Проверка актуальности.** Счётчики считаются при открытии раздела
   «Язык», по кнопке «Обновить» и при возврате фокуса в окно, пока раздел
   открыт. Фонового наблюдения за файлами нет.
9. **Существующие копии не мигрируют автоматически.** Старый
   `local/languages/en.json` становится обычным внешним файлом. Если он
   устарел, пользователь нажимает «Вернуть встроенный» и получает свежий
   английский. Правленые файлы не трогаются.

## Почему так

- **Убирает причину, а не следствие.** Нетронющей копии встроенного языка
  больше не существует, поэтому нечему устаревать и нечего сравнивать.
  Отпечатки, манифест и автообновление становятся не нужны.
- **Внешний файл всегда осознанный.** Он появляется только по кнопке,
  значит его правки - решение пользователя, и правило «не переписывать»
  действует без исключений.
- **Откат естественный.** Удалил файл - вернулся встроенный перевод.
- **Два встроенных языка дешевле, чем один плюс копия.** Английский едет
  в поставке и обновляется вместе с программой; цена - около 12 КБ gzip
  в сборке интерфейса.

## Последствия

- `seed()`, `.seeded`, `include_str!` английского в ядре и тесты посева
  удаляются.
- `src-tauri/resources/languages/en.json` перестаёт быть внешним словарём;
  встроенный английский живёт в интерфейсе, а ядро получает документ для
  выгрузки от интерфейса.
- `languages_list` заменяется каталогом с сообщениями; `language_load`
  остаётся для загрузки одного активного файла на старте.
- В разделе «Язык» появляются бейджи «Встроенный», «Внешний», «Полный»,
  счётчики «Добавить» и «Удалить», действия выгрузки, возврата и изменений.
- Файл `<code>.updates.jsonc` - новое машинное состояние рядом со словарями;
  в коммит не попадает. Прежний `<code>.missing.jsonc` больше не создаётся.
- `check-messages` проверяет два встроенных языка; состояние внешних
  словарей показывает раздел «Язык».

## Отклонённые альтернативы

- **Один встроенный `ru` плюс посев `en`.** Возвращает устаревшую копию
  и необходимость отличать правленый файл от нетронутого.
- **Автообновление нетронутых копий по отпечатку.** Манифест, миграция,
  ложные срабатывания; модель с двумя встроенными языками снимает задачу.
- **Дописывать недостающие ключи прямо во внешний файл.** Ломает обещание
  «ваш файл не трогаем» и требует построчного редактора JSONC с сохранением
  комментариев.
- **Файл миграций со старыми именами.** Пользователю нужны два списка:
  что добавить и что убрать. Перечень переименований не помогает перенести
  перевод и заставляет держать манифест имён.
- **Полная замена внешнего файла по кнопке.** Обесценивает перевод
  пользователя; для возврата к заводскому переводу есть отдельное действие.
