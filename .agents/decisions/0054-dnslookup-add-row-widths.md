# ADR 0054: Ширины строки добавления DNS заданы ролью поля

- **Статус:** принято
- **Дата:** 2026-11-18
- **Область:** `src/tools/dnslookup/styles.css`,
  `src/tools/dnslookup/components/DnsTable.vue`,
  `src/tools/dnslookup/constants.ts`, `.agents/rules/project/ui.md`

## Контекст

Строка добавления записи DNS собрана из групп PrimeVue `InputGroup`.
Пресет задаёт `.p-inputgroup .p-inputtext, .p-inputgroup .p-inputwrapper
{ flex: 1 1 auto; width: 1%; }`, и это правило перебивало ширины
инструмента: поле домена и выбор типа шли по содержимому, а список
резолверов растягивался на всю строку. Поле типа в таблице имело своё
число (`TYPE_FIELD_WIDTH`), поэтому выбор в панели и в таблице могли
разойтись.

Владелец попросил: увеличить поле домена, сузить выбор типа, сделать
общий токен для выбора типа в панели и в таблице, дать списку резолверов
ширину под два чипа и не растягивать элементы на всю строку.

## Решение

1. **Поле домена - 360 px** (`--dns-name-width`). Оно главный ввод строки,
   поэтому шире общего поля `--ag-field-width` (320 px).
2. **Выбор типа - 92 px** (`--dns-type-width`). Это общий токен: его берут
   выбор типа в строке добавления и поле типа в таблице. Колонка типа
   сохраняет минимальную ширину 104 px: поле плюс отступ ячейки.
3. **Список резолверов - 300 px** (`--dns-servers-width`). Столько нужно
   двум чипам (около 103 px каждый), счётчику «+N» и стрелке; список
   не растягивается.
4. **Правила ширины перебивают пресет.** Селекторы называют группу
   и поле точнее (`.dns__add .p-inputgroup .p-inputtext`), поэтому
   правило `.p-inputgroup` не забирает ширину себе.
5. **Кнопка «Проверить» остаётся у правого края.** Свободное место
   строки не заполняется списком: оно остаётся между списком и кнопкой.

## Почему так

- **Ширина по роли.** Домен - главный ввод, тип - служебный выбор: их
  размеры не могут быть одинаковыми по остатку строки.
- **Один токен на повторяющийся контрол.** Выбор типа в панели и в таблице
  отвечает на один вопрос и должен выглядеть одинаково; два числа
  разошлись бы при первой правке.
- **Список под чипы, а не под строку.** Растянутый список показывал
  два чипа слева и пустоту справа; ширина под чипы убирает пустоту.
- **Правило пресета не переопределяется `!important`.** Селектор точнее
  по структуре, а не по весу: причина в том, что поле внутри группы,
  и это названо в селекторе.

## Последствия

- На узком окне строка переносится, список сжимается до 160 px,
  а поле типа и кнопка остаются читаемыми.
- Новое поле в строке добавления берёт ширину по роли и, если повторяется
  в таблице, получает общий токен в `styles.css`.
- `TYPE_FIELD_WIDTH` из `constants.ts` удалён: значение переехало
  в токен `--dns-type-width`.

## Отклонённые альтернативы

- **Оставить растяжение группы.** Поле домена шло по содержимому, список
  занимал всю строку: ровно то, что просили убрать.
- **`!important` на ширинах.** Перебивает пресет силой, а не точностью,
  и мешает будущим правкам.
- **Два числа для выбора типа.** Панель и таблица разошлись бы при первой
  правке одного из них.
- **Кнопка «Проверить» сразу после списка.** Главное действие уезжало
  в середину строки и теряло правый край.
