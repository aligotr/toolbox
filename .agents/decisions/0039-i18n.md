# ADR 0039: Мультиязычность интерфейса

- **Статус:** принято; встроенных языков два, правило внешних словарей
  уточнено ADR 0057
- **Дата:** 2026-11-16
- **Область:** `src/`, `tests/`, `src-tauri/src/`,
  `src-tauri/resources/languages/`, `scripts/`, `.agents/rules/project/`

## Контекст

Программа русскоязычная, но конечным пользователем может быть человек
с другим языком. Переводить нужно только то, что он видит: оболочку,
настройки, инструменты, ошибки и замечания, умолчания, создаваемые
программой. Комментарии, докстринги, тесты и файловый лог остаются русскими:
это инструменты разработки и разбора, а не интерфейс.

Из этого следовало четыре вопроса.

- **Где граница перевода.** Если переводить всё, объём утраивается за счёт
  комментариев и тестов, а пользы пользователю нет.
- **Кто пишет перевод.** Встроенный второй язык пришлось бы обновлять при
  каждой правке русского текста; внешний файл можно править руками.
- **Чем переводить.** `vue-i18n` превращает текст в мини-язык (`|`, `@`, `{}`),
  а нам нужен формат, который переводчик не сможет сломать случайным символом.
- **Как показывать журнал.** Журнал — поток фактов; если хранить готовые
  строки, при смене языка история останется на прежнем языке.

## Решение

1. **Переводится только то, что видит конечный пользователь.** Оболочка,
   центр управления, инструменты, статусы, ошибки и замечания из Rust,
   умолчания, создаваемые программой. Не переводятся: комментарии и
   докстринги, тесты и тестовые данные, файловый лог, топики, `id`, имена
   файлов, данные пользователя и названия-бренды (`ToolBox`, `Busprobe`,
   `DNSlookup`). Названия инструментов остаются именами, описания —
   обычный текст.

2. **Встроенный словарь один — русский.** Он лежит в коде: сейчас одним
   файлом `messages.ts`, по мере перевода фрагменты уходят к владельцам
   кода, а `src/app/locales.ts` собирает из них каталог и ставит эталон.
   Русский обязан быть полным: используемый в коде ключ, которого нет
   в русском словаре, валит сборку. Любой другой язык — внешний файл;
   его неполнота сборку не валит.

3. **Внешние словари — `local/languages/<code>.json`.** Это машинное
   состояние рядом с настройками, а не пользовательские данные профиля:
   язык не переезжает между машинами вместе с `profiles/`. Папку создаёт
   проба записи. Приложение файлы **никогда не перезаписывает**: правки,
   комментарии и удалённые ключи остаются как есть.

4. **Английский — обычный внешний файл.** Он поставляется в
   `src-tauri/resources/languages/en.json`, вшивается в бинарник и при
   первом запуске копируется в `local/languages/en.json`, если файла нет.
   Маркер `local/languages/.seeded` не даёт восстановить файл после
   осознанного удаления. Английский — полигон проверки механизма:
   непереведённый ключ виден как русское слово в английском интерфейсе.

5. **Формат словаря — JSON с комментариями и висячими запятыми (JSONC).**
   Строгий JSON комментариев не допускает, а пользователю нужно подписать
   файл или закомментировать ключ. Разбирает **только Rust** (`json5`),
   интерфейс получает готовый объект: один диалект на обе стороны, номер
   строки в ошибке, новой зависимости в `package.json` нет. Остальные
   вольности JSON5 (ключи без кавычек, одинарные кавычки) не поощряются,
   но и не ломаются.

6. **Схема файла:**

   ```json5
   {
     // Название языка в списке.
     "name": "English",
     "messages": {
       "settings.section.log": "Log",
       // Русский обязан быть полным; остальные языки могут отставать.
       "settings.language.missing": { "one": "{count} key missing", "other": "{count} keys missing" },
     },
   }
   ```

   Код языка — имя файла без расширения и валидный тег BCP 47. Значение —
   строка или набор форм по категориям CLDR (`zero`, `one`, `two`, `few`,
   `many`, `other`). Подстановка — `{name}`, всё остальное — текст.

7. **Ключ — публичный контракт.** Схема `область.сущность.поле`:
   `settings.section.log`, `errors.settings.read_failed`,
   `journal.profile.created`. Формулировку можно менять, ключ — нет:
   переименование молча ломает чужие переводы, и вместо сломанного места
   покажется русский текст.

8. **Цепочка отката: выбранный файл → встроенный русский → ключ.** Ошибка
   разбора, пропавший файл или непереведённый ключ не мешают работе.
   Выбранный, но недоступный словарь сохраняется в настройках, а раздел
   «Язык» показывает заметное предупреждение.

9. **Язык хранится в `ui.language`.** `null` — «как в системе»: интерфейс
   определяет язык по `navigator.language` при первом запуске, сохраняет
   выбор и дальше его не переопределяет. Язык блокирующего экрана приходит
   в `StartupStatus`: настройки в этот момент ещё не читаются интерфейсом,
   а причина отказа уже должна быть переведена. Если папку программы
   прочитать нельзя, внешний словарь недоступен и экран показывает
   встроенный русский — это та же цепочка отката, а не отдельное правило.

10. **Механизм свой, на `Intl`.** Поиск ключа, подстановки и склонения —
    `translate.ts`; форматирование чисел и дат — `Intl.NumberFormat`,
    `Intl.DateTimeFormat`; категории — `Intl.PluralRules`. Механизм не
    содержит Vue в чистых функциях: тесты идут через `node --test` без
    vitest. `vue-i18n` не берётся: его синтаксис сообщений — мини-язык,
    который пришлось бы запрещать валидатором, а runtime-компилятор стоит
    +20–30 kB gzip. Пересмотр — при третьем языке с профессиональными
    переводчиками или при необходимости HTML и слотов в сообщениях.

11. **Журнал — структурные записи.** `write(source, kind, code, params)`
    хранит код и данные, `JournalView` переводит при показе. Смена языка
    перерисовывает всю историю: записи живут в памяти, миграции не нужны.
    `source` ядра — `core`, а не `ядро`: это подпись словаря.

12. **Лог остаётся русским.** Лог — артефакт разбора, а не интерфейс;
    пути, имена и системные ошибки всё равно приходят на языке ОС.
    Смешанный лог хуже и для чтения, и для поиска.

13. **RTL и нелатинские письменности вне области первой версии.** Файл
    загрузится и текст отрисуется, но раскладка останется слева-направо.
    Это ограничение, а не недоделка; пересмотр — вместе с первым RTL-языком.

## Почему так

- **Граница по пользователю, а не по файлу.** Комментарий и тест читает
  разработчик; перевод не делает их полезнее, но добавляет работу и шум
  в каждом коммите.
- **Внешний файл — единственный способ дать пользователю перевести
  программу без сборки.** Встроенные языки пришлось бы синхронизировать
  с русским при каждой правке.
- **JSONC, а не YAML и не TOML.** У YAML отступы — главная причина поломок
  у переводчиков, у TOML глубокая вложенность превращается в лестницу
  заголовков. JSONC сохраняет форму данных и допускает комментарии.
- **Разбор в Rust.** Один парсер на обе стороны; ошибка приходит с номером
  строки; интерфейс не тащит парсер в поставку.
- **Свой механизм дешевле, чем кажется.** Формат `{name}` нельзя сломать
  случайным символом; всё остальное даёт `Intl`. Тесты на `node --test`
  снимают главный довод против своего кода — «нечем проверить».
- **Структурный журнал — следствие смены языка без перезапуска.** Готовые
  строки пришлось бы хранить на языке, который был в момент записи.

## Последствия

- Появляется новое состояние `local/languages/`: папка, словари и маркер
  начальной установки. В коммит она не попадает: при разработке лежит
  внутри `src-tauri/target/`, в поставке — рядом с `.exe`.
- Русский словарь растёт вместе с текстами; сборка проверяет его полноту.
  Остальные словари отстают безопасно, но отчёт о пропусках становится
  частью раздела «Язык».
- Ошибки Rust перестают быть голой строкой: код, параметры и русский
  `fallback`. Тесты продолжают сравнивать `fallback`.
- Названия одиночных вкладок перестают храниться в `workspace.json`:
  подпись производна от `kind`. Старый файл с подписью читается, поле
  игнорируется.
- `source` записи журнала — код; старые записи в памяти отсутствуют,
  миграция не нужна.
- Журнал переходит на структурные записи отдельным этапом: до него записи
  остаются русскими строками, а источником — `ядро`.
- Умолчания, записываемые в файлы (название профиля, приписка к названию
  копии), задаёт интерфейс: он знает язык, а ядро — нет. Ядро создаёт
  только папку профиля, и до первой правки подпись совпадает с `id`;
  приписку копии оно принимает параметром. Записанное остаётся данными:
  смена языка не переименовывает ни профили, ни пресеты.

## Отклонённые альтернативы

- **Переводить комментарии и тесты.** Дорого, бесполезно пользователю
  и ломает привычку читать код на родном языке.
- **Встроить английский вторым словарём.** Каждая правка русского текста
  требовала бы синхронной правки английского в коде; внешний файл
  обновляется отдельно.
- **`vue-i18n`.** Даёт ленивую загрузку, слоты и экосистему, которых у нас
  нет; ценой — мини-язык сообщений и runtime-компилятор.
- **Словари рядом с `.exe`.** Пользователь правил бы файлы в папке программы,
  но это ломает единое правило «машинное — в `local/`» и не даёт пробе
  записи покрыть папку словарей.
- **Строгий JSON.** Нельзя ни подписать файл, ни закомментировать ключ.
- **Свой вырезатель комментариев.** Ломается на `https://` внутри строки —
  классическая ошибка, которую не хочется поддерживать.
- **Готовые строки в журнале.** Смена языка оставила бы историю на старом
  языке или потребовала бы миграции.
- **«Универсальный английский» в журнале и логе.** Для русскоязычных хуже,
  для иностранцев всё равно смесь: пути и системные ошибки приходят
  на языке ОС.
- **`vitest` ради `t()`.** Отдельная инфраструктура ради чистых функций;
  Node 26 запускает TypeScript-тесты напрямую.
