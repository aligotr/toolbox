# ADR 0017: Состояние инструмента привязано к ячейке (cellKey)

- **Статус:** принято
- **Дата:** 2026-11-12
- **Область:** `src/contracts/tools.ts`, `src/workbench/workspace/ToolGrid.vue`,
  `src/workbench/workspace/WorkspaceView.vue`, `src/tools/dnslookup/`

## Контекст

Рабочая область показывает только активную вкладку: `WorkspaceView` рисует
`ToolGrid` для `activeTab`, а `ToolGrid` создаёт компонент инструмента
через `<component :is>`. При переключении вкладки компонент **размонтируется**,
и всё состояние внутри `setup` пропадает.

Для ping это незаметно: там нет долгой работы. Для DNS это неприемлемо:
пользователь запускает проверку, переходит в журнал и возвращается —
результаты и введённые домены должны остаться. Одновременно один и тот же
инструмент может стоять в нескольких вкладках и даже в двух колонках одной
вкладки: сеансы не должны смешиваться.

Ключ «по индексу в массиве» ненадёжен: он меняется при любой правке
раскладки. Ключ «по `id` инструмента» не различает два экземпляра.

## Решение

1. **Идентификатор места — `cellKey`.** Строка
   `<tabId>:<columnIndex>:<toolIndex>`: вкладки получают UUID при создании,
   индексы колонки и инструмента стабильны, пока раскладка не меняется.
2. **Оболочка передаёт ключ, инструмент его не вычисляет.** `WorkspaceView`
   передаёт в `ToolGrid` идентификатор активной вкладки; `ToolGrid` —
   `cellKey` в каждый компонент. Для этого в контракт инструмента добавлен
   необязательный проп `cellKey`.
3. **Состояние живёт вне компонента.** Инструмент держит модульную
   `Map<string, Session>`; компонент при монтировании берёт сеанс по
   `cellKey` и создаёт новый, если его нет. Размонтирование карточки
   сеанс не уничтожает.
4. **Закрытые вкладки убираются при монтировании.** Инструмент сверяет
   ключи карты с открытыми вкладками рабочего пространства и удаляет
   сеансы вкладок, которых больше нет. Отдельного события «вкладка
   закрыта» не требуется.

## Почему так

- **Переключение вкладок перестаёт быть разрушительным.** Это главное
  требование: результат проверки DNS не должен зависеть от того, куда
  пользователь посмотрел.
- **Два экземпляра не мешают друг другу.** Каждая ячейка получает свой
  сеанс, даже если это один и тот же инструмент.
- **Оболочка не знает про DNS.** Она сообщает только координату; что с ней
  делать, решает инструмент. Контракт остаётся тонким.

## Последствия

- `ToolGrid` обязан знать `tabId`; `WorkspaceView` передаёт `activeTab.id`.
- `cellKey` — необязательный проп: инструменты без состояния (ping)
  его игнорируют.
- Пока в раскладке нет drag-and-drop и вставки инструмента в существующую
  колонку, индексы не смещаются. Когда такие операции появятся, ячейке
  понадобится собственный `id`, а формат ключа — новый ADR.
- Память сеансов ограничена: карта чистится при монтировании и при
  закрытии вкладок; результаты в файлы не пишутся.

## Отклонённые альтернативы

- **Состояние внутри компонента.** Теряется при переключении вкладки —
  ровно то, чего нельзя допустить.
- **Один глобальный синглтон инструмента.** Два экземпляра DNS в разных
  вкладках перезаписывали бы результаты друг друга.
- **`v-show` вместо `v-if` для вкладок.** Все вкладки остаются в DOM:
  скрытые инструменты продолжают занимать память и могут завершать
  фоновые операции, которых пользователь не видит.
- **Хранилище (Pinia) с ключом по `id` инструмента.** Лишняя зависимость
  и та же проблема различения экземпляров; карта в модуле решает задачу
  без библиотеки.
