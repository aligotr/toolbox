# ADR 0035: Зоны ядра — инфраструктура, хранилище, сервисы

- **Статус:** принято
- **Дата:** 2026-11-16
- **Область:** `src-tauri/src/core/`, `src/core/`, `src/contracts/`,
  `src-tauri/src/lib.rs`, `scripts/check-zones.mjs`, `package.json`

## Контекст

`core` разросся: восемнадцать файлов в Rust и пятнадцать в TypeScript лежали
в одной плоской папке. Рядом находились шина сообщений, пути к файлам, чтение
JSON и правила домена. Из этого следовало четыре боли.

- На вопрос «где правило пресета» нельзя ответить по дереву: приходится
  открывать файлы подряд.
- Точка сборки обрастала правилами. `commit_settings` держал порядок «сначала
  запись, потом память», `lib.rs` — DTO пресета по умолчанию, потому что
  сервису некуда было положить проверку.
- `contracts` смешивал словарь и поведение: рядом с типами жили `sortedTools`
  и `isRecord`.
- Хранение и правила выглядели одинаково, хотя меняются по разным поводам:
  «переехала папка данных» и «пресет по умолчанию теперь выбирается иначе» —
  правки разного масштаба.

Утверждение «`core` — инфраструктура без Vue» (ADR 0012) перестало быть
правдой: половина `core` знала про профили, пресеты и вкладки.

## Решение

1. **Три зоны ядра, одинаковые по именам в Rust и TypeScript:**

   | Зона | Что содержит | Чего не содержит |
   |---|---|---|
   | `infra` | механизмы без предметного словаря: шина, `Deps`, сообщение, `Module`, приёмник, трасса; в TS — мост, журнал, статусы операций, ошибки, стражи формы | имён профиля, пресета, шаблона |
   | `store` | где лежат файлы и как они читаются: `files`, `names`, `storage`, `stats` | решений «что делать» |
   | `services` | один домен на файл: `settings`, `profiles`, `presets`, `templates`, `workspace`, `data`, `logging`, `window` | чужих правил |

   Состав зон разный, потому что разный стек: `store` есть только в Rust —
   файлы читает он; `contracts` есть только в TypeScript — словарь обмена
   между интерфейсом и ядром.

2. **Зависимости идут только вниз: `infra ← store ← services`.** `infra`
   не знает ни `store`, ни `services`. `store` не знает `services`. Сервисы
   видят обе нижние зоны; связи между сервисами редки и видны по импортам
   (`settings` читает профили, `presets` — указатель в `profile.json`).

3. **Граница проходит по владению правилами.** Файл объясняется без
   предметных слов — это `infra`. Файл знает пути, форматы и имена, но не
   решает, что с ними делать, — это `store`. Файл решает — это `services`.
   Упоминание сущности само по себе зону не определяет: `storage` знает
   `profiles/`, потому что это папка, а не потому что профиль — его домен.

4. **`contracts` — словарь обмена без поведения.** Типы, которые пересекают
   границы слоёв, остаются в `src/contracts`. `Stored*` — то, что отдаёт
   Rust, — живут там же; модели после разбора (`Preset`, `Template`) уезжают
   к своему домену в `services/*`. Поведение из контрактов убрано:
   `sortedTools` переехал в точку сборки `app/tools.ts`, `isRecord` —
   в `infra/guards.ts`.

5. **Побочные эффекты принадлежат точке сборки.** `settings::commit`
   проверяет правку, пишет файл и обновляет память, возвращая
   `Committed { settings, log_level_changed }`; переключение логгера и событие
   интерфейсу остаются в `lib.rs`. Правило указателя по умолчанию —
   в `presets::default_for`, `presets::set_default` и `presets::delete`:
   профиль отдаёт `profile.json` целиком и не знает, что в нём лежит,
   а раздел `defaults` и его проверки принадлежат пресетам.

6. **Рамки держат стражи, а не документ.** В Rust тест `core::zone_tests`
   читает исходники зон и падает, если `infra` или `store` сослались наверх;
   строки комментариев не считаются, а пробелы убираются, чтобы ссылка
   в скобках (`use crate::core::{store::files}`) не проскочила мимо запрета.
   В TypeScript `scripts/check-zones.mjs` запускается перед сборкой: ловит
   импорты (`from`, побочные и динамические) и запрещает экспортируемое
   поведение в `contracts`.

7. **Кросс-доменные сводки остаются в точке сборки.** `AppInfo`
   и `StartupStatus` собирают версию, профиль, срок хранения лога
   и статус запуска из нескольких сервисов. Ни одному домену они
   не принадлежат, поэтому живут в `lib.rs`. Размеры папок
   (`store::stats::summary`) — не такая сводка: это подсчёт файлов,
   у которого нет предметных правил, и его место в зоне хранения.

## Почему так

- **Один вопрос — одна папка.** «Где правило пресета» отвечается путём
  `core/services/presets.rs`, а не чтением восемнадцати файлов.
- **Правило уезжает туда, где его можно проверить тестом.** `settings::commit`
  покрыт тестом Rust; прежний `commit_settings` в точке сборки — нет.
- **Стрелка вверх — самая дорогая ошибка.** `infra`, узнавшая про пресет,
  перестаёт быть общей: каждая правка домена начинает тянуть изменение
  механизма.
- **Стражи стоят копейки.** Тест Rust читает исходники двух зон, скрипт TS —
  все исходники интерфейса; цена — доли секунды, выигрыш — граница, которая
  не расходится с кодом.

## Последствия

- Новый файл кладётся не «в core», а в зону: сначала ответ на вопрос, знает
  ли он предмет.
- Константы домена переезжают в `constants.ts` домена (`settings/`,
  `presets/`, `workspace/`); в `core/constants.ts` остаётся оболочка —
  названия одиночных вкладок, заготовка пустой вкладки, договор
  подтверждений.
- Импорт сервиса из `infra` или `store` — ошибка сборки в TypeScript
  и упавший тест в Rust.
- `src/contracts` без поведения: экспортируемые функции, константы, классы
  и перечисления там запрещены стражем.
- ADR 0012 в части «`core` — инфраструктура без Vue» уточняется: `core`
  делится на зоны, а сервисы ядра владеют правилами домена. Остальные
  пункты ADR 0012 действуют.

## Отклонённые альтернативы

- **Зоны на словах, комментарием в `mod.rs`.** Не проверяется: через месяц
  папка снова станет плоской, а комментарий устареет молча. Границу держит
  только то, что падает при нарушении.
- **`contracts` с поведением.** Общий код удобно класть рядом с типом, но
  контракт тогда зависит от деталей: `sortedTools` знал бы про порядок
  реестра, `isRecord` — про форму хранения. Контракт — словарь, а не место
  для логики.
- **Порт-трейт для хранилища.** `trait Storage` с реализацией на диск
  и подменой в тестах дал бы изоляцию, но добавил бы слой ради слоя:
  сервисы и сейчас принимают пути, а тесты кладут файлы во временную папку.
  Порт оправдан, когда появится второе хранилище; сейчас его нет.
- **Отдельный `domain/` вместо `services/`.** «Сервис ядра» — устоявшийся
  термин глоссария и всей документации (ADR 0005); переименование запутало
  бы чтение ради модного слова.
