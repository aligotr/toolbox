# Приоритеты правил

Подробное описание того, как соотносятся между собой три источника правил.
Краткая версия — в `AGENTS.md` → секция «Источник истины (кратко)».

## Источники правил

1. **`rules/*.md`** (глобальные + проектные) — текстовая семантика, обоснования, инварианты
2. **Машиночитаемые запреты** (`agents-guard.yml` — глобальный + проектный) — точные списки команд, запрещённых без явного запроса пользователя
3. **Базовые инварианты `AGENTS.md`** — автономны, действуют даже без файлов

Глобальный и проектный YAML — **один источник** приоритета. Правила из обоих объединяются; при конфликте между global и project — project главнее (он специфичнее).

## Правила приоритета

- **Правило есть только в `rules/*.md`** — применяется как написано (MD дополняет YAML)
- **Правило есть только в `agents-guard.yml`** — применяется как написано (YAML дополняет MD)
- **Правило есть в обоих и совпадает** — применяется без вопросов
- **Правило есть в обоих и конфликтует** — `agents-guard.yml` главнее (YAML — single source of truth при конфликте)
  - Сообщить пользователю о конфликте
  - Не продолжать задачи до явного разрешения
- **Конфликт между global и project (YAML↔YAML, MD↔MD)** — project главнее (он специфичнее). Это норма: глобальные правила задают дефолт, проектные — уточняют под стек и продукт. Глобальное и проектное **дополняют** друг друга, не дублируют
- **Конфликт между `AGENTS.md` (базовые инварианты) и любым файлом** — базовые инварианты всегда главнее. Они автономны: продолжают действовать, даже если папка `.agents/` отсутствует или повреждена

## Примеры

### Согласованные правила

- `agents-guard.yml` разрешает `npx nuxi typecheck`
- `nuxt_4.md` говорит «Typecheck: `npx nuxi typecheck`»
- `AGENTS.md` говорит «Запрещено откатывать без явного запроса»
- → Правила не пересекаются, все три применяются как написано (typecheck + запрет отката)

### Конфликт YAML ↔ MD

- `agents-guard.yml` разрешает `npm run dev`
- `git.md` запрещает dev-сервер
- → Конфликт, YAML главнее (npm run dev разрешён, но это скорее всего ошибка в YAML — сообщить)

### Правило только в MD

- `code-style.md` говорит «все идентификаторы в camelCase»
- В `agents-guard.yml` такого правила нет
- → Применяется правило из MD (YAML не отменяет MD, а дополняет)

### Правило только в YAML

- `agents-guard.yml` запрещает `rm -rf node_modules`
- В `rules/*.md` этого нет
- → Применяется правило из YAML (MD не отменяет YAML, а дополняет)
