# Память проекта

Память хранит то, что нельзя восстановить из кода: почему сделано именно так,
что отвергли и какие последствия приняли. Код показывает «как», память
объясняет «почему».

Назначение документов и границы между ними - таблица «Память и документы»
в `AGENTS.md`. Здесь подробные правила.

## Единственное место

Вся память проекта живёт в `.agents/`. Других мест нет:

- нет `docs/`, `docs/adr/` и `docs/agents/`;
- нет `GLOSSARY.md` и `GLOSSARY-MAP.md` в корне;
- нет правил и спек, спрятанных в `.scratch/`.

Если скил или внешний шаблон предлагает другую раскладку, действует это
правило. Скилы ниже правил проекта.

Проект single-context: один глоссарий и один каталог решений на весь
репозиторий. `GLOSSARY-MAP.md` не используется.

## Структура

```text
.agents/
├── GLOSSARY.md      - оглавление глоссария
├── glossary/        - термины по доменам
├── decisions/       - архитектурные решения (ADR)
│   ├── INDEX.md     - производный обзор решений
│   └── NNNN-....md
├── specs/           - долговечные спецификации поведения
├── auxiliary/       - вспомогательные материалы
│   ├── templates/   - шаблоны ADR, спек, задач, страниц и индексов
│   ├── scripts/     - переносные скрипты для .agents и документации
│   └── bootstrap.md - порядок старта нового проекта
├── library/         - каталог готовых элементов и решений
├── rules/           - правила агентов: global и project
└── skills/          - скилы агента, управляются установщиком
```

`AGENTS.md` в корне ведёт в правила. Этот файл - часть глобальных правил.
Скрипты проекта лежат в `scripts/` в корне, вне `.agents/`.

## ADR

Одно решение - один файл в `.agents/decisions/`. Формат - ADR, шаблон -
`.agents/auxiliary/templates/adr.md`. Номер выдаётся по порядку и не переиспользуется,
даже если решение отменено.

Имя файла: `NNNN-краткое-название.md`, только строчные буквы и дефисы.

### Неизменяемость

- Содержимое ADR не переписывают, не перемещают, не переименовывают
  и не переформатируют.
- Агент не меняет ADR и не предлагает их менять по своей инициативе.
- Изменение возможно только по явному запросу владельца проекта.
- Устаревшее решение не удаляют. Новое решение оформляется отдельным ADR,
  а в старом меняется только статус на «заменено (ADR NNNN)».
- Статус «заменено» ставится только по явному запросу владельца.
- Актуальные пути и связи показывает `INDEX.md`. История в теле ADR
  не переписывается.

### INDEX.md

`INDEX.md` - производный обзор, не решение. В нём: номер, название, статус,
область, актуальный код и заменяющее решение. Новый ADR добавляет строку
в индекс. Индекс можно править без изменения самих ADR.

### Правила записи

- Одно решение - один файл.
- Пишем «почему», а не «что»: пересказ кода не нужен, код и есть код.
- Фиксируем отклонённые варианты: иначе спор возникнет повторно.
- Ссылки на код обязательны: решение без привязки к файлам расходится
  с реальностью.

### Когда писать ADR

- выбор библиотеки, протокола, формата данных;
- границы модулей и правила взаимодействия;
- модель жизненного цикла;
- неочевидное ограничение, из-за которого пришлось отступить от красивого
  решения;
- любое решение, которое дорого менять позже.

Не пишем ADR на локальный рефакторинг и на то, что очевидно из кода.

## Глоссарий

`.agents/GLOSSARY.md` - оглавление. Термины лежат в `.agents/glossary/`
по доменам. Один термин живёт ровно в одном файле. Если термин в коде,
интерфейсе и обсуждении называется по-разному, побеждает глоссарий.

Новый термин добавляется сразу: в подходящий файл и в оглавление. Глоссарий
не содержит деталей реализации.

## Спецификации

`.agents/specs/` - долговечные спецификации поведения: сценарии, состояния,
ошибки, данные, границы и приёмка. Спека не пересказывает код и не заменяет
ADR. При конфликте главнее ADR.

Спека обновляется, когда меняется поведение. Задача, план и черновик в спеку
не попадают.

## Шаблоны

`.agents/auxiliary/templates/` - формы для ADR, спек, задач, страниц
библиотеки, стартовых индексов и project-правил. Шаблон - подсказка, а не
обязательный каркас: лишние разделы удаляются, пустые не заполняются.
Порядок старта нового проекта - `.agents/auxiliary/bootstrap.md`.

## Скрипты

Есть два места, и они не смешиваются:

- `.agents/auxiliary/scripts/` - переносные скрипты для работы с каталогом
  `.agents` и документацией: проверка документации и сборка указателя ADR.
  Переезжают в новый проект вместе с `.agents/`.
- `scripts/` в корне - скрипты проекта: сборка, проверки кода, обслуживание
  артефактов. В новый проект не переносятся, у него свои команды.

Скрипт, который не работает с `.agents` и документацией, лежит в `scripts/`
в корне, даже если им пользуется агент.

## Библиотека

`.agents/library/` - каталог готовых элементов и решений. Перед новой
реализацией агент проверяет `README.md` и не пишет заново то, что уже есть.
Страницы разложены по областям: область называет крупную часть проекта.
Индекс называет элемент, путь, назначение и ADR. Страница элемента описывает
интерфейс и подключение.

## Скилы

`.agents/skills/` - каталог скилов, если проект их использует. Управляется
установщиком. Вручную не редактируем. Методология скила применяется только
в части, не противоречащей правилам проекта.
