# Проверки и завершение задачи

Проверка соразмерна правке и моменту задачи. Полный цикл после каждой мелочи
не нужен: он тратит время и не даёт нового сигнала. Конкретные команды задаёт
`rules/project/quality.md`.

## Три уровня

- **Точечная** - изменённый файл или один сценарий: формат файла, линтер
  файла, проверка типов файла, тест изменённого модуля.
- **Областная** - затронутая часть проекта: тесты домена, сборка модуля,
  проверка затронутого инструмента.
- **Полная** - весь проект: все тесты, линтер, проверка типов, сборка,
  проверка документации и живая проверка, если проект её требует.

Уровень выбирается по границам правки, а не по числу строк. Правка одного
файла может задеть контракт и потребовать полной проверки.

## Когда какой уровень

- Каждая мелкая правка - точечная.
- Группа правок или законченный шаг - областная.
- Перед коммитом - областная как минимум. Полная нужна, если менялись
  контракты, конфиги, зависимости или несколько областей сразу.
- Перед ответом «готово», релизом и PR - полная.
- Живая проверка выполняется один раз на законченный сценарий, а не после
  каждой правки.
- Изменение логики без теста оставляет задачу незавершённой, даже если правка
  выглядит мелкой.
- Сомнение в границах правки - повод проверить шире, а не уже.

## Живая проверка

Если у проекта есть интерфейс, его проверяют в собранном виде: запускают
приложение и проходят сценарий. Инструмент задаёт проектное правило:
браузерный отладчик, драйвер интерфейса, запуск командной строки.

Живая проверка не заменяет тесты: тесты проверяют логику, живая проверка -
то, что видит пользователь. Успешная сборка не доказывает, что элемент
работает. Без интерфейса шаг не нужен: достаточно тестов и сборки.

## Чего не делать

- Не запускать полный цикл после каждой мелкой правки: это не даёт нового
  сигнала и замедляет задачу.
- Не отключать падающий тест из-за окружения: выясняется причина.
- Не считать коммит готовым без проверки в своей области.
- Не подменять тесты ручным осмотром и наоборот.

## Что задаёт проект

- Команды каждого уровня и матрицу областей.
- Инструмент и сценарий живой проверки.
- Проверку документации и пересборку производных указателей.
