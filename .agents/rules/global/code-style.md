# Стиль написания кода

## Общие принципы

- Семантически полные имена
- Запрещены сокращения, теряющие контекст (`cb`, `mr`, `slp`)
- Разрешены общепринятые аббревиатуры (`id`, `URL`, `API`)
- Допустимы сокращения длины без потери корня (`Dir` в `getAvatarsDir`, `btn` в `btnProfile`)

## Стиль комментариев и докстрингов

### Номинативный стиль (главное правило)

Комментарии и докстринги — в **назывном падеже**, описывают суть, а не действие.

✅ Правильно:

- «Кэширование данных профиля»
- «Нормализация телефонного номера»
- «Идемпотентная обработка webhook»

❌ Неправильно:

- «Кэширует данные профиля»
- «Нормализует номер»
- «Обрабатываем webhook идемпотентно»

### Запрет на очевидные комментарии

- Не комментировать импорты, инициализацию стандартных хуков, очевидные return
- JSDoc только для неочевидных контрактов (не для самодокументируемых функций)
- Комментарии объясняют **почему**, не **что**

Исключение: обучающие комментарии для пользователя, они должны быть подробными, целостными, с пометкой об обучающем признаке.
