# Архитектура: общие правила

Архитектуру задают ADR проекта: слои, зоны ядра, границы и порядок модуля.
Здесь только правила, которые применяются при каждой правке.

## Импорты

- Зависимости идут только вниз:
  `contracts → core → ui → { tools | workbench } → app`.
- `contracts` - словарь обмена: только типы, без поведения, Vue и Tauri.
- `core` делится на `infra ← store ← services`; импортов вверх нет.
- Команды Tauri живут в `core/commands/` отдельным слоем над сервисами:
  команда разбирает аргументы и зовёт сервис, правило остаётся в сервисе
  (ADR 0048). Обратная стрелка запрещена и проверяется `core::zone_tests`.
- `core` импортирует `vue` только держателям наблюдаемого состояния
  (`reactive`/`ref`); правила, разбор и проверка ввода живут в модулях
  без Vue. Границу проверяет `check-zones` (ADR 0047).
- `tools` и `workbench` не импортируют друг друга; инструмент попадает
  в оболочку только через реестр из `app`.
- Между слоями - алиас `@/`; внутри модуля - относительные пути.

## Модули

- С другими инструментами - только через шину, не импортом.
- Удаление инструмента - стереть папку и строки регистрации; следов
  не остаётся.

## Данные

- Запись атомарная: `*.tmp` в той же папке и переименование.
- Неизвестные поля в JSON сохраняются: файл могут открыть более старой
  версией.
- Повреждённый файл не роняет приложение: берутся значения по умолчанию,
  причина идёт в журнал и лог.

## Удаление

- Файловая сущность (профиль, пресет, внешний словарь, целый файл данных)
  удаляется после подтверждения переносом в `local/trash/`. При отказе
  переноса исходник остаётся на месте.
- Верхний уровень корзины - единица удаления: `profiles/<id>/`,
  `presets/<profile>/<tool>/<id>.json`, `languages/<code>.jsonc`.
- Запись внутри документа (свой DNS-сервер, строка таблицы, значение
  настройки) удаляется правкой документа, без корзины и подтверждения.
- Машинное состояние и производные файлы (рабочее пространство, логи,
  `*.updates.jsonc`, `*.tmp`) удаляются сразу, без корзины.
- Корзина внутренняя: в интерфейсе нет входа и восстановления, тексты
  не обещают возврат. Записи старше 14 дней удаляются при старте
  и после каждого удаления.
- Совпадение имени не перезаписывает корзину: свободное имя получает суффикс.
- Повреждённый пользовательский файл не удаляется: показывается ошибка.
- `local/` не синхронизируется; корзина предполагает это и не проверяет.

## Чего не делать

- Импорт `tools/a` из `tools/b` → общий код опустить в `core` или `ui`.
- Импорт инструмента из `workbench` → передать через реестр из `app`.
- Поведение в `contracts` → тип остаётся, функция уходит в домен.
- Имя инструмента в `core` или `ui` → это домен, ему там не место.
- Импорт `core::services` из `core::infra` или `core::store` (то же в TS) →
  механизм не знает домен.
- Правило домена в `lib.rs` или в команде → в сервис; точке сборки
  остаются побочные эффекты и сводки из нескольких доменов, команде -
  разбор аргументов и вызов сервиса.
- Обёртка, проброс или новый файл без собственной ответственности →
  «слой ради слоя».

## Границы держат стражи

- Rust - `core::zone_tests`.
- TypeScript - `scripts/check-zones.mjs` в `npm run build`.

Правило, которое держится только документом, расходится с кодом.
