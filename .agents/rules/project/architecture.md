# Архитектура: слои, зоны ядра и контракт модуля

Основано на ADR 0012 и ADR 0035. Правила действуют для всего кода в `src/`
и `src-tauri/src/`.

## Слои интерфейса

Зависимости идут только вниз:

```text
contracts → core → ui → { tools | shell } → app
```

| Слой | Что содержит | Чего не содержит |
|---|---|---|
| `contracts` | топики, дескриптор инструмента, раскладка, шаблон, запись журнала | поведения, импортов Vue и Tauri |
| `core` | мост в Rust, журнал, домены ядра: настройки, профили, пресеты, шаблоны, вкладки | компонентов, имён инструментов |
| `ui` | preset темы, примитивы сетки и рейла | домена, обращений к шине |
| `tools/<id>` | один инструмент целиком | импортов других инструментов и оболочки |
| `shell` | сайдбар, вкладки, оболочка пространства | импортов конкретных инструментов |
| `app` | `App.vue`, `main.ts`, сборка реестра | бизнес-логики |

Правила импорта:

- `contracts` не импортирует ничего из перечисленного и не содержит
  поведения: только типы;
- `core` не импортирует `ui`, `tools`, `shell`, `app`;
- `ui` не импортирует `tools`, `shell`, `app`;
- `tools` и `shell` **не импортируют друг друга**;
- `app` — единственное место, которое знает всех.

## Composition root

Реестр инструментов собирается в `app` и передаётся оболочке. Оболочка
рендерит инструмент по `component` из дескриптора и не импортирует папки
`tools/*`.

## Зоны ядра

`core` делится на три зоны с одинаковыми именами в Rust и TypeScript
(ADR 0035). Зависимости идут только вниз:

```text
infra ← store ← services
```

| Зона | Что содержит | Чего не содержит |
|---|---|---|
| `infra` | механизмы без предметного словаря: шина, `Deps`, сообщение, `Module`, приёмник, трасса; в TS — мост, журнал, статусы операций, ошибки, стражи формы | имён профиля, пресета, шаблона |
| `store` | где лежат файлы и как они читаются: `files`, `names`, `storage`, `stats` | решений «что делать» |
| `services` | один домен на файл: `settings`, `profiles`, `presets`, `templates`, `workspace`, `data`, `logging`, `window` | чужих правил |

Состав зон разный, потому что разный стек: `store` есть только в Rust —
файлы читает он; `contracts` есть только в TypeScript — словарь обмена
между интерфейсом и ядром.

Правила:

- граница проходит по владению правилами: файл объясняется без предметных
  слов — `infra`; знает пути и форматы, но не решает — `store`; решает —
  `services`;
- `infra` не знает ни `store`, ни `services`; `store` не знает `services`;
- связи между сервисами редки и видны по импортам (`settings` читает
  профили, `presets` — указатель в `profile.json`);
- побочные эффекты (логгер, событие интерфейсу, окно) остаются в `lib.rs`:
  сервис возвращает результат, а не зовёт Tauri;
- сводки, собранные из нескольких доменов, живут в точке сборки —
  `AppInfo` и `StartupStatus`.

Рамки держат стражи:

- Rust — тест `core::zone_tests` в `src-tauri/src/core/mod.rs`: падает,
  если `infra` или `store` сослались наверх; строки комментариев
  не считаются;
- TypeScript — `scripts/check-zones.mjs` перед сборкой (`npm run build`):
  проверяет импорты и запрещает экспортируемое поведение в `contracts`.

## Контракт модуля

Инструмент — папка и, при наличии поведения в Rust, пара к ней:

```text
src/tools/ping/
  index.ts        дескриптор: id, title, icon, component, order
  PingView.vue    представление
  usePing.ts      состояние и сценарий
  api.ts          вызовы моста

src-tauri/src/modules/ping.rs   impl Module
src-tauri/src/modules/mod.rs    +1 строка в register_all
src/modules/index.ts            +1 строка в реестре (до появления app/)
```

Требования:

- инструмент импортирует только `contracts`, `core`, `ui`;
- с другими инструментами общается **только через шину**;
- удаление — стереть папку и строки регистрации; следов не остаётся;
- `id` совпадает с Rust-модулем, **если** Rust-часть существует;
- чисто фронтовый инструмент (секундомер, заметки) — норма, Rust-части
  у него нет.

Соответствие списка инструментов и списка Rust-модулей один-к-одному
не требуется. Отдельного файла со списком и проверок на равенство нет.
Обработчик без пункта меню безвреден; пункт меню без обработчика виден
при первом вызове.

## Rust

```text
lib.rs → modules → core
```

`core` не знает имён модулей. Регистрация модуля — одна строка в
`modules::register_all`. Зависимости обработчик получает из `Deps`
по типу, а не создаёт сам.

Внутри `core` — три зоны (ADR 0035):

```text
src-tauri/src/core/
  infra/      bus, deps, message, module, sink, trace
  store/      files, names, storage, stats
  services/   settings, profiles, presets, templates, workspace, data,
              logging, window
```

Правило `infra ← store ← services` проверяется тестом `core::zone_tests`.

## Транспорт и состояние

- Компонент не вызывает `invoke`, `send_event`, `ask` напрямую — только
  через `api.ts` своего инструмента.
- `api.ts` — тонкая обёртка над мостом, без состояния и бизнес-логики.
- Состояние операции гранулярное: `status.<операция>.loading/error`.
  Монолитного `isLoading` на весь инструмент нет.
- Ошибка вызова обязана быть видна: строка в журнале и сообщение в панели
  инструмента. Молчаливой кнопки, которая ничего не делает, быть не должно.

## Анти-паттерны

- Импорт `tools/a` из `tools/b` → общий код опустить в `core` или `contracts`.
- Импорт инструмента из `shell` → передать через реестр из `app`.
- `invoke` внутри компонента → перенести в `api.ts`.
- Имя инструмента в `core` или `ui` → это домен, ему там не место.
- Поведение в `contracts` → тип остаётся, функция уезжает в домен
  или в `infra`.
- Импорт `core::services` из `core::infra` или `core::store` (то же для
  TS) → правило принадлежит сервису, механизм не должен знать домен.
- Правило домена в `lib.rs` → перенести в сервис; точке сборки остаются
  только побочные эффекты.
- Нумерованные «слои» на каждый модуль → модули ровесники, порядок задаётся
  полем `order`.

## Чек-лист нового инструмента

- [ ] Папка `src/tools/<id>` с `index.ts`, `*View.vue`, `use*.ts`, `api.ts`
- [ ] Импорты только из `contracts`, `core`, `ui`
- [ ] Нет обращений к мосту в обход `api.ts`
- [ ] Гранулярный `status` на каждую операцию
- [ ] Ошибка видна в журнале и в панели
- [ ] При наличии Rust-части — `impl Module` и строка в `register_all`
- [ ] `id` совпадает на обеих сторонах
