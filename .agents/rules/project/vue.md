# Vue и TypeScript

## Версия и стиль

- Vue 3.5+, TypeScript строгий. Ослаблять strict ради прохождения сборки
  запрещено.
- Только Composition API и `<script setup lang="ts">`. Options API,
  `setup()` внутри `defineComponent` и миксины не используются.
- Порядок в SFC: `<script setup>`, затем `<template>`, затем `<style scoped>`.

## Именование файлов

- `.ts` — camelCase: `useBusprobe.ts`, `workspaceStorage.ts`.
- `.vue` — PascalCase: `BusprobeView.vue`, `TabStrip.vue`.
- Папка инструмента — по `id`: `src/tools/busprobe/`, `src/tools/dnslookup/`.
- Имя файла composable = имя функции: `useBusprobe.ts` → `useBusprobe`.
- Имя служебного файла называет роль, а не формат: `logLevels.ts`,
  `formatBytes.ts`, `navigation.ts` вместо `constants.ts`, `format.ts`,
  `state.ts`. Общее имя остаётся только для файла, который собирает
  модульное: `constants.ts` — константы нескольких разделов, `types.ts` —
  типы модуля (ADR о порядке модуля).

Имена — полные слова. Сокращения допустимы только общепринятые (`id`, `URL`)
или не теряющие корень (`btn`, `dir`).

## Разделение ответственности

```text
api.ts        транспорт: обёртки над мостом, без состояния
use<Инструмент>.ts   состояние и сценарий
<Инструмент>View.vue представление
index.ts      дескриптор инструмента
```

- Компонент не содержит бизнес-логики и не вызывает мост.
- `use*` не знает о разметке и не импортирует компоненты.
- Один файл — одна публичная сущность; мелкие помощники — внутренние,
  без `export`.
- Сценарий выносится в `use*.ts` при втором потребителе или когда перерос
  SFC; форма одного раздела остаётся в компоненте — обёртка с единственным
  вызовом запрещена (ADR о порядке модуля).
- Разделы экрана живут в `sections/`, когда их два и более; корень модуля —
  экран, навигация, общие сценарии и помощники с точными именами.

## Состояние операции

- На каждую операцию своё состояние:

```ts
status: {
  ping: { loading: Ref<boolean>, error: Ref<string | null> },
  trace: { loading: Ref<boolean>, error: Ref<string | null> }
}
```

- Монолитный `isLoading` на весь инструмент запрещён.
- Долгая операция не блокирует остальные: у ping и трассы независимые
  состояния.
- Ошибка из `api.ts` не глотается: она попадает в `status`, в журнал и
  в панель инструмента.

## Мост

- `invoke`, `send_event`, `ask`, `subscribeEvent` — только в `api.ts`.
- Подписка на событие создаётся в `onMounted`/`onUnmounted` (или в `use*`
  с явным `stop`), отписка обязательна.
- Типы нагрузки — из `contracts`, не из компонента.

## PrimeVue

- Компоненты PrimeVue используются напрямую. Обёртка появляется только
  под общую логику (например, единая рамка инструмента).
- Свой компонент допустим, если он дешевле подгонки библиотеки; причина
  фиксируется в задаче.
- Стили компонента - `scoped` рядом с компонентом. Общий каркас инструментов
  с таблицей - `src/ui/tool-layout.css` (классы `tool-*`, токены `--tool-*`),
  импорт один раз в `main.ts`. Общие стили инструмента -
  `tools/<id>/styles.css` без `scoped`, с BEM-префиксом инструмента.
  Глобальный CSS содержит только базу и раскладку оболочки.
- Тема — `src/ui/primevue/theme.ts` (preset). Переключение темы — классом на `html`,
  не правкой компонентов.

## Тексты

- Видимый пользователю текст — только ключом словаря через `t("…")`;
  готовых строк в разметке и `.ts` нет.
- Новый текст добавляется ключом сразу, вместе с английским переводом:
  «перевод потом» — это расхождение языков.
- Как писать формулировки, вести ключи и проверять словари — `i18n.md`.

## Запреты

- `any` → узкий тип или generic с ограничением.
- `console.*` → журнал интерфейса или `log_frontend` для отказа моста.
- Магические числа и строки в разметке и логике → `constants.ts`.
- Импорт `tools/a` из `tools/b`.
- Прямой `invoke` в компоненте.
- Опции Options API, миксины, `provide/inject` для доменных данных
  без необходимости.

## Чек-лист компонента

- [ ] `<script setup lang="ts">`, без `any`
- [ ] Нет обращений к мосту в обход `api.ts`
- [ ] `status` по операциям, ошибки не глотаются
- [ ] Нет бизнес-логики в разметке
- [ ] Стили `scoped`, без сырых цветов
- [ ] Новый видимый текст — ключом из словаря через `t("…")`
