# Проверка живого окна через CDP

Живое окно Tauri открывает Chrome DevTools Protocol. Это основной способ
проверить интерфейс: разметку, стили, клавиши, фокус, размеры, прокрутку
и ошибки консоли. Успешная сборка не доказывает, что элемент работает.

## Запуск

- `npm run dev:cdp` запускает обычный `tauri dev` с переменной
  `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<порт>`.
- Порт по умолчанию 9222; другой задаётся переменной `CDP_PORT`.
- Порт слушает только локальную машину. В `tauri.conf.json` его не добавляют:
  отладка нужна только в dev-сборке.
- Управление: `scripts/cdp.mjs` через `npm run cdp -- <команда>`.

## Команды

| Команда | Назначение |
|---|---|
| `npm run cdp -- targets` | список целей; страница приложения должна быть одна |
| `npm run cdp -- eval "<выражение>"` | выполнить код в окне и напечатать результат |
| `npm run cdp -- screenshot [файл]` | снимок окна в PNG |
| `npm run cdp -- resize <ширина> <высота>` | настоящее изменение размера окна |
| `npm run cdp -- resize clear` | вернуть размер окна |
| `npm run cdp -- key ctrl+w` | нажать сочетание клавиш |
| `npm run cdp -- logs [секунды]` | консоль, предупреждения и исключения |

- `eval` возвращает значение выражения: строку, число, массив, объект.
- `key` сравнивает `event.code`, поэтому раскладка не важна. Модификаторы:
  `ctrl`, `alt`, `shift`, `meta`. Именованные клавиши: `enter`, `escape`,
  `tab`, `space`, `backspace`, `delete`, стрелки, `home`, `end`, `pageup`,
  `pagedown`, `f1`...`f12`.
- `logs` завершается с кодом 1, если за время прослушивания была ошибка или
  исключение. Предупреждения печатаются, но код не меняют.
- `resize` поднимает `ResizeObserver` и пересчитывает раскладку, поэтому
  проверяет настоящее поведение, а не только CSS.

## Когда обязательно

- Любая правка видимого поведения: разметка, стили, горячие клавиши, фокус,
  прокрутка, перетаскивание, ширины колонок, темы, тексты интерфейса.
- Перед ответом «готово»: снимок экрана и проверка состояния через `eval`.
- После сценария: `logs` не должен находить ошибок.
- Для раскладки: `resize` на 960, 1125, 1280 и 1400, если правка её касается.

## Как проверять

1. Запустить `npm run dev:cdp`.
2. Дождаться цели: `npm run cdp -- targets`.
3. Выполнить сценарий шагами `eval` и `key`.
4. Снять экран: `npm run cdp -- screenshot`.
5. Послушать консоль: `npm run cdp -- logs 3`.
6. Остановить приложение, если оно больше не нужно.

Пример проверки `Ctrl+W`:

```powershell
npm run cdp -- eval "document.querySelectorAll('.tab').length"
npm run cdp -- key ctrl+w
npm run cdp -- eval "document.querySelectorAll('.tab').length"
```

Пример проверки раскладки:

```powershell
npm run cdp -- resize 960 700
npm run cdp -- eval "document.querySelector('thead th:nth-child(2)').getBoundingClientRect().left"
npm run cdp -- resize clear
```

Результат проверки - наблюдаемое состояние: класс, число элементов, текст,
размер, отсутствие ошибок. «Команда отработала» доказательством не считается.

## Границы

- CDP не заменяет тесты: логику проверяют `npm run test` и `cargo test`,
  CDP проверяет уже собранное окно.
- Системную рамку окна, нативные диалоги, трей и поведение реальных устройств
  CDP не видит: их проверяет владелец.
- Порт открыт, пока приложение запущено. После проверки dev-сервер
  останавливают, если он больше не нужен.
- Снимки и временные файлы кладут во временный каталог, а не в репозиторий.
- CDP работает только в dev-сборке. В конфигурацию релиза отладочный порт
  не попадает.
