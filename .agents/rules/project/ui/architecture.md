# Интерфейс: архитектура стилей

Как устроены стили: кто владеет значением, где живёт правило, какие границы
держат раскладку. Вид и поведение элементов - `design.md`, конкретные
элементы - `elements.md`.

Основано на ADR 0009, ADR 0012, ADR 0019, ADR 0022 и ADR 0037.

## Токены

- Цвета задаются в preset `src/ui/primevue/theme.ts`. В компонентах - только токены,
  без сырых цветов.
- Схема одна - светлая (ADR 0019). Тёмных значений в пресете нет, класс
  `.dark` и `prefers-color-scheme` вид приложения не меняют.
- Шкала отступов, радиусов и текста - именные токены `--ag-*` в
  `src/styles/global.css` (ADR 0022):

  | Роль | Токены |
  |---|---|
  | Отступы | `--ag-space-xs` 4, `sm` 8, `md` 12, `lg` 16, `xl` 24, `2xl` 32 |
  | После шапки экрана | `--ag-space-heading` 24 |
  | Высота контрола | `--ag-control-h` 32 |
  | Радиусы | `--ag-radius-sm` 6, `md` 8, `lg` 16, `round` 50% |
  | Текст | `--ag-text-xs` 13, `sm` 14, `md` 15, `lg` 18, `xl` 24 |
  | Цвет заголовка экрана | `--ag-text-heading` #44403c |

- Значения пресета повторяют ту же шкалу: радиусы, отступы полей, размеры
  текста и плотность таблицы задаются в `theme.ts`, а не в экранах.
- В компонентах нет чисел вместо токенов. Литерал остаётся линии (1 px),
  иконке и оптической поправке (2 px, −4 px): у них своя роль.
- Свои CSS-переменные - только для того, чего нет в пресете (оболочка,
  сетка, служебные элементы), префикс `--ag-`: это именные токены владельца
  дизайн-системы. Семантическое имя важнее визуального:
  `--ag-panel-border`, а не `--ag-gray`. Размеры общего каркаса инструментов
  с таблицей - отдельные токены `--tool-*` в `src/ui/tool-layout.css`.
- Один токен - одна роль. Дубли под разными именами не создаются.
  Семантический токен роли отводится отдельно, даже когда его значение
  совпадает со ступенью шкалы: имя фиксирует роль, а не число.
- Значение живёт у владельца, а не у потребителя: отступ после шапки задаёт
  шапка, ширину поля - роль поля (ADR 0053). Потребитель чужое значение
  не компенсирует и не складывает со своим.

## Где живут стили

| Уровень | Где | Что |
|---|---|---|
| База | `src/styles/global.css` | токены, `html/body`, шрифт, фон, сброс |
| Тема | `src/ui/primevue/theme.ts` | preset PrimeVue |
| Общий контрол | `src/ui/` | варианты контролов на общих токенах |
| Каркас инструмента | `src/ui/tool-layout.css` | шапка, строка добавления, фильтры, таблица и раскрытие (`tool*`, `--tool-*`) |
| Компоненты каркаса | `src/ui/tool/` | экран, таблица, раскрытие, раздел раскрытия, липкая шапка, числовое поле |
| Инструмент | `src/tools/<id>/styles.css` | классы, общие для двух и более компонентов инструмента |
| Оболочка | `src/workbench/styles.css` | каркас экранов: шапка экрана и раздел (`wb-*`) |
| Компонент | рядом с `.vue` | `scoped`-стили компонента |

Правила:

- глобальный файл не содержит стилей карточек, кнопок, диалогов;
- стили уровня инструмента подключаются один раз в корневом view -
  `import "./styles.css"` в `<script setup>`: со `scoped` правила
  не доходят до соседних компонентов, а второй импорт раздувает бандл;
- общий каркас инструментов с таблицей - `src/ui/tool-layout.css`;
  он подключается один раз в `src/app/main.ts`, классы несут префикс
  `tool-`, размеры - токены `--tool-*`; экран ставит их рядом со своими;
- общие части каркаса с поведением - компоненты `src/ui/tool/`:
  `ToolScreen`, `ToolTable`, `ToolDetails`, `ToolDetailsSection`,
  `ToolExpansionHead`, `ToolNumberField`; инструмент не копирует их разметку,
  `ResizeObserver`, перенос строк и состояние раскрытия;
- `ToolTable` - единственный владелец рамки таблицы, пустого состояния,
  раскрытия и прокрутки к подсвеченной строке; инструмент помечает строку
  маркером `data-tool-row` и приносит колонки слотами;
- раскрытие удерживает контекст строки: `ToolTable` даёт слот
  `expansion-head` для липкой шапки, `markExpanded` включает подсветку
  раскрытой строки, `ToolDetails` с `nested` рисует линию вложенности;
  свой цвет строки важнее общего акцента: у расхождения DNS сохраняются
  предупреждающие фон и полоса, а раскрытие добавляет жирное имя;
- файл инструмента описывает только своё: колонки, ячейки, статусы и
  раскрытие, которых нет у соседнего инструмента;
- общий файл оболочки подключается один раз в `WorkbenchView.vue`; его классы
  несут префикс `wb-` (`wb-screen__title`, `wb-section__head`) - без `scoped`
  это единственная защита от протечки в стили инструментов;
- повторяющийся контрол оболочки становится компонентом (`RailItem.vue`),
  а не набором общих классов: у пункта рейла есть пропсы и событие;
- повторяющаяся часть каркаса инструмента с состоянием становится
  компонентом `src/ui/tool/`; обёртка без состояния и слотов не нужна -
  остаются классы `tool-*`;
- классы файла инструмента несут BEM-префикс инструмента (`dns-table`,
  `dns__hint`): без `scoped` это единственная защита от протечки. Общий
  каркас берётся классами `tool-*`, а не копией под префиксом инструмента;
- вариант контрола, нужный нескольким инструментам, живёт обёрткой в
  `src/ui/` и берётся как есть: правила вида не копируются между экранами;
- селектор имеет минимально необходимую область действия;
- глобальные селекторы - только сброс и семантические значения по умолчанию;
- `Teleport`-слои (диалог, тост) получают уникальный namespace и явно
  владеют `z-index` и `overflow`.

## Состояния

- `default → hover → focus-visible → active/selected → disabled`.
- Состояние, которое должно сохраняться после действия, хранится в данных:
  активная вкладка, выбранный инструмент, свёрнутый сайдбар.
- `:hover` не является единственным источником активного состояния.
- `:has()` не используется как источник бизнес-состояния.
- Каждый интерактивный элемент имеет видимый `focus-visible`.

## Раскладка

- Перед правкой CSS проверяются: размер и направление контейнера,
  `min-width`/`min-height` у flex/grid-потомков, `box-sizing`,
  `gap` + `padding` + `border` в расчёте места, `overflow` каждого уровня.
- Прокручиваемым flex/grid-потомкам задаётся `min-width: 0` /
  `min-height: 0`.
- Фиксированный набор равных элементов - grid с `minmax(0, 1fr)`.
- Горизонтальный `overflow` устраняется на уровне причины, а не на внешней
  странице.
- `overflow: hidden` не используется как маскировка неизвестного переполнения.
- Проверяется не только узкое, но и низкое окно: минимум 960×640.
- Появление данных не двигает уже отображённые блоки без требования.

## Порядок разбора визуального дефекта

1. Сверить DOM с контрактом раскладки.
2. Найти все правила, влияющие на размер, позицию и overflow.
3. Проверить владельца состояния: не зависит ли стиль от `:hover`.
4. Сравнить обычное, узкое и низкое окно.
5. Исправить единственную причину у владельца.
6. Удалить ставшие ненужными компенсации.
7. Проверить enter/leave, loading, error, empty, active, disabled.

## Запреты

- Стили виджетов в глобальном файле.
- Сырые цвета в компонентах вместо токенов.
- Числа вместо `--ag-space-*`, `--ag-radius-*`, `--ag-text-*` в отступах,
  радиусах и размерах текста: литерал остаётся линии, иконке и оптической
  поправке.
- Фиксированная высота, скрывающая переполнение.
- Сжатые однострочные CSS-блоки, скрывающие независимые правила.
