# Rust

## Структура

```text
src-tauri/src/
  core/      шина, сообщения, зависимости, лог, настройки, хранилище
  modules/   подсистемы: dnslookup, core.ping (протокол самопроверки)
  lib.rs     composition root: порядок инициализации и мост
```

- `core` не импортирует `modules`.
- Модуль регистрируется одной строкой в `modules::register_all`.
- Новый сервис ядра добавляется в `core` и в `Deps`; пункта меню он
  не имеет.

## Модуль

```rust
impl Module for DnslookupModule {
    fn id(&self) -> &'static str { "dnslookup" }

    fn register(&self, bus: &MessageBus) { /* обработчики */ }
}
```

- Модуль знает свои топики и не знает чужих.
- Общение с другими модулями - только через шину.
- Зависимости - из `Deps` по типу, не создаются внутри обработчика.

## Ошибки

- Ошибка возвращается вызывающему, а не проглатывается.
- Текст ошибки - по-русски, с путём или идентификатором: `"Не удалось
  записать '{}': {error}"`.
- Ошибка интерфейсу - `AppError { code, params, fallback }`: код
  `errors.<область>.<случай>` переводит словарь, `params` - данные
  подстановок, `fallback` - русский текст для лога и тестов. Код - контракт
  с интерфейсом: формулировку меняем, код нет.
- `unwrap`/`expect` допустимы только там, где отказ означает ошибку
  программиста: инициализация статики, тесты.
- Ошибка модуля не роняет приложение: она уходит событием в интерфейс.

## Логирование

- Лог отвечает только на вопрос «почему приложение или функция не сработали».
- Модули **не вызывают** `log::` и не пишут в файл: их работа идёт в журнал
  интерфейса через события.
- Уровни: `error`, `warn`, `info`, `debug`. Уровня `trace` нет.
- Писать в stderr запрещено: приложение оконное, вывода никто не увидит.
- Секреты, токены и полные ответы сети в лог не попадают.

## Файлы и запись

- Всё состояние - рядом с исполняемым файлом. Отката в системные каталоги нет.
- Запись документов атомарная: `*.tmp` в той же папке и переименование.
- Путь к файлу не собирается вручную в модуле: его выдаёт `storage`.
- Временные файлы при ошибке удаляются; мусор в папке профиля не остаётся.

## Асинхронность

- Обработчик события не блокирует диспетчер долгой работой: тяжёлое -
  в отдельную задачу с публикацией результата.
- Блокировки не удерживаются во время ввода-вывода.
- Отмена операции - через шину, а не обрывом задачи без уведомления.

## Тесты

- Общие принципы - `../../global/tests.md`.
- Тесты - в `#[cfg(test)] mod tests` того же файла: идиома языка, а не
  отдельная папка.
- Временная папка теста уникальна: `std::env::temp_dir()` + имя теста +
  `process::id()`.
- Своя бизнес-логика не мокается; мокаются файловая система, время, сеть.

## Запреты

- `println!`, `eprintln!`, `dbg!` в рабочем коде.
- `std::process::exit` вне обработки фатального отказа запуска.
- Имя модуля в `core`.
- Паника в обработчике события: ошибка возвращается или логируется.

## Чек-лист модуля

- [ ] `impl Module`; `id` совпадает с дескриптором инструмента либо, если
      Rust-части с именем инструмента нет, с именем протокола (`core.ping`)
- [ ] Строка в `register_all`
- [ ] Зависимости из `Deps`, без глобальных синглтонов
- [ ] Нет `log::` и вывода в stderr
- [ ] Ошибки с путём и понятным текстом
- [ ] Тесты на ветвления и граничные случаи
