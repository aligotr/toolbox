# Интерфейс и стили

Основано на ADR 0009, ADR 0012, ADR 0019, ADR 0021, ADR 0022 и ADR 0023.

## Токены

- Цвета задаются в preset `src/ui/theme.ts`. В компонентах — только токены,
  без сырых цветов.
- Схема одна — светлая (ADR 0019). Тёмных значений в пресете нет, класс
  `.dark` и `prefers-color-scheme` вид приложения не меняют.
- Шкала отступов, радиусов и текста — именные токены `--ag-*` в
  `src/styles/global.css` (ADR 0022):

  | Роль | Токены |
  |---|---|
  | Отступы | `--ag-space-xs` 4, `sm` 8, `md` 12, `lg` 16, `xl` 24, `2xl` 32 |
  | После заголовка экрана | `--ag-space-heading` 24 |
  | Радиусы | `--ag-radius-sm` 6, `md` 8, `lg` 16, `round` 50% |
  | Текст | `--ag-text-xs` 13, `sm` 14, `md` 15, `lg` 18, `xl` 24 |

- Значения пресета повторяют ту же шкалу: радиусы, отступы полей, размеры
  текста и плотность таблицы задаются в `theme.ts`, а не в экранах.
- В компонентах нет чисел вместо токенов. Литерал остаётся линии (1 px),
  иконке и оптической поправке (2 px, −4 px): у них своя роль.
- Свои CSS-переменные — только для того, чего нет в пресете (оболочка,
  сетка, служебные элементы), префикс `--ag-`: это именные токены владельца
  дизайн-системы. Семантическое имя важнее визуального:
  `--ag-panel-border`, а не `--ag-gray`.
- Один токен — одна роль. Дубли под разными именами не создаются.
  Семантический токен роли отводится отдельно, даже когда его значение
  совпадает со ступенью шкалы: имя фиксирует роль, а не число.

## Типографика и spacing

- Корень — 16 px (технический: rem, масштаб, умолчание). Основной текст —
  14 px. Шкала: 24 / 18 / 15 / 14 / 13 — токены `--ag-text-xl…xs`.
- Основной шаг — 8 px; половинный шаг 4 px (`--ag-space-xs`) допустим внутри
  строки: иконка, знак, зазор между подписью и значением. Линии — 1 px.
  Зазоры берутся из `--ag-space-*`, а не пишутся числом.
- После основного заголовка экрана — зазор `--ag-space-heading` (24 px):
  один на все экраны, чтобы заголовок отделялся от содержимого одинаково.
- Межстрочный интервал и вес задаются в пресете, а не точечно в компонентах.
- Базовые размеры шрифтов компонентов PrimeVue (подсказки, меню, диалоги,
  поля) задаются в пресете: экран не переопределяет размер ради одного
  компонента.

## Где живут стили

| Уровень | Где | Что |
|---|---|---|
| База | `src/styles/global.css` | токены, `html/body`, шрифт, фон, сброс |
| Тема | `src/ui/theme.ts` | preset PrimeVue |
| Общий контрол | `src/ui/` | варианты контролов на общих токенах |
| Оболочка | `src/shell/` | сайдбар, вкладки, сетка, рейл |
| Компонент | рядом с `.vue` | `scoped`-стили компонента |

Правила:

- глобальный файл не содержит стилей карточек, кнопок, диалогов;
- вариант контрола, нужный нескольким инструментам, живёт обёрткой в
  `src/ui/` и берётся как есть: правила вида не копируются между экранами;
- селектор имеет минимально необходимую область действия;
- глобальные селекторы — только сброс и семантические значения по умолчанию;
- `Teleport`-слои (диалог, тост) получают уникальный namespace и явно
  владеют `z-index` и `overflow`.

## Состояния

- `default → hover → focus-visible → active/selected → disabled`.
- Состояние, которое должно сохраняться после действия, хранится в данных:
  активная вкладка, выбранный инструмент, свёрнутый сайдбар.
- `:hover` не является единственным источником активного состояния.
- `:has()` не используется как источник бизнес-состояния.
- Каждый интерактивный элемент имеет видимый `focus-visible`.

## Раскладка

- Перед правкой CSS проверяются: размер и направление контейнера,
  `min-width`/`min-height` у flex/grid-потомков, `box-sizing`,
  `gap` + `padding` + `border` в расчёте места, `overflow` каждого уровня.
- Прокручиваемым flex/grid-потомкам задаётся `min-width: 0` /
  `min-height: 0`.
- Фиксированный набор равных элементов — grid с `minmax(0, 1fr)`.
- Горизонтальный `overflow` устраняется на уровне причины, а не на внешней
  странице.
- `overflow: hidden` не используется как маскировка неизвестного переполнения.
- Проверяется не только узкое, но и низкое окно: минимум 960×640.
- Появление данных не двигает уже отображённые блоки без требования.

## Акценты

- Главное на экране — данные: таблица или результат занимает свободное место
  и видна первой. Заголовок, фильтры и кнопки — обслуживающие элементы.
- Панель управления компактнее данных: мелкий размер полей и кнопок,
  строка ввода не растягивается на всю ширину без нужды.
- Текст не переносится, пока в контейнере есть место: ограничение ширины
  ставится там, где длинная строка мешает чтению, а не по привычке.
- Сообщение об ошибке живёт, пока актуально: правка поля его снимает,
  а место ошибки ввода — само поле, не отдельная строка под панелью.
- Статус не дублирует результат: успешный ответ показывает адрес без «OK»,
  ошибка резолва показывается статусом.

## Анимации

- Один переход — один механизм: не смешивать keyframes и transition
  на одном элементе.
- Анимация не меняет layout-свойства.
- `prefers-reduced-motion: reduce` отключает движение.
- Внешний слой и внутренняя панель завершаются одновременно, если DOM
  удаляется по внешнему переходу.

## Порядок разбора визуального дефекта

1. Сверить DOM с контрактом раскладки.
2. Найти все правила, влияющие на размер, позицию и overflow.
3. Проверить владельца состояния: не зависит ли стиль от `:hover`.
4. Сравнить обычное, узкое и низкое окно.
5. Исправить единственную причину у владельца.
6. Удалить ставшие ненужными компенсации.
7. Проверить enter/leave, loading, error, empty, active, disabled.

## Запреты

- Стили виджетов в глобальном файле.
- Сырые цвета в компонентах вместо токенов.
- Числа вместо `--ag-space-*`, `--ag-radius-*`, `--ag-text-*` в отступах,
  радиусах и размерах текста: литерал остаётся линии, иконке и оптической
  поправке.
- Фиксированная высота, скрывающая переполнение.
- Несколько независимых transition для одного enter/leave.
- Сжатые однострочные CSS-блоки, скрывающие независимые правила.
