# Инструмент DNS: проверка и сравнение резолверов

## Цель

Дать один экран, на котором видно, что отвечают на домен разные DNS-серверы,
где ответы расходятся и почему ответа нет. Экран работает и как одиночная
проверка (один домен, один сервер), и как пакетная (список доменов против
нескольких серверов). История не сохраняется: сеанс живёт, пока открыта
вкладка.

## Что решено

- ADR 0018 — PrimeVue 4.5.5 без лицензионного ключа; DNS на API мажора 4.
- ADR 0016 — DNS через `hickory-proto` 0.26.3, свой синхронный UDP/TCP,
  системные резолверы через `ipconfig` 0.3, без кэша и tokio.
- ADR 0017 — состояние инструмента привязано к `cellKey`
  (`<tabId>:<columnIndex>:<toolIndex>`), карта сеансов живёт в модуле.

## Границы фичи

Входит:

- единый экран «DNS» с таблицей доменов;
- типы A, AAAA, CNAME, MX, TXT, NS, SOA, SRV, CAA, PTR;
- список доменов, вставка списком, повтор строки и всей проверки;
- серверы: системный, четыре преднастроенных, свои `IP[:port]`;
- сравнение ответов с системным сервером и фильтр расхождений;
- остановка проверки, очистка сеанса, экспорт CSV;
- хранение своих серверов в профиле.

Не входит:

- история проверок и сохранение результатов на диск;
- периодический опрос и режим «распространение записи»;
- DoH, DoT, DNSSEC, обратная зона кроме PTR;
- переименование домена на месте (строку удаляют и добавляют заново);
- виртуализация таблицы: 500 строк × 8 серверов рисуются обычной таблицей.

## Экран

Экран один: таблица доменов есть всегда, даже если в ней одна строка.
Одиночная проверка — это таблица из одной строки с одним сервером.

Сверху вниз:

1. **Строка добавления** — поле домена (или IP для PTR), выбор типа,
   кнопка «Добавить», справа «Вставить список».
2. **Строка серверов** — выбранные серверы чипами, кнопки добавления
   и настройки своих серверов.
3. **Строка фильтров** — поиск, фильтр по статусу, «Только расхождения»,
   «Колонки».
4. **Таблица** — строки домены, колонки серверы.
5. **Строка состояния** — счётчики и вердикт по расхождениям.
6. **Панель действий** — «Проверить», «Остановить», «Очистить»,
   «Экспорт CSV».

### Один домен, один сервер

```text
┌ DNS ───────────────────────────────────────────────────────────────────────────┐
│ [example.com____________________] [A ▾] [+ Добавить]        [Вставить список] │
│ Серверы: [Системный ×]  [Google]  [Cloudflare]  [Quad9]  [AdGuard]  [+ Свой]   │
├────────────────────────────────────────────────────────────────────────────────┤
│ Домен                     │ Тип │ Системный                                      │
│ example.com            ↻  │ A   │ 93.184.216.34                                  │
├────────────────────────────────────────────────────────────────────────────────┤
│ 1 домен · 1 сервер · 1 из 1     [Проверить] [Остановить] [Очистить]  [CSV]    │
└────────────────────────────────────────────────────────────────────────────────┘
```

Вердикт «совпадает у N из M» не показывается: сравнивать не с чем, кроме
самого системного сервера.

### Один домен, три сервера

```text
┌ DNS ───────────────────────────────────────────────────────────────────────────┐
│ [example.com____________________] [A ▾] [+ Добавить]        [Вставить список] │
│ Серверы: [Системный ×] [Google ×] [Cloudflare ×] [Quad9] [AdGuard] [+ Свой]    │
├────────────────────────────────────────────────────────────────────────────────┤
│ Домен                     │ Тип │ Системный      │ Google         │ Cloudflare │
│ example.com            ↻  │ A   │ 93.184.216.34  │ 93.184.216.34  │ 93.184.216.34 │
│ совпадает у 2 из 2        │     │                │                │            │
├────────────────────────────────────────────────────────────────────────────────┤
│ 1 домен · 3 сервера · 3 из 3    [Проверить] [Остановить] [Очистить]  [CSV]    │
└────────────────────────────────────────────────────────────────────────────────┘
```

Строка расхождений подсвечивается, когда хотя бы один сервер ответил иначе,
чем системный. Подсветка не заменяет вердикт: цвет виден и без чтения чисел.

## Поведение интерфейса

### Добавление домена

- Ввод обрезается по краям; пустой ввод игнорируется.
- Enter в поле и кнопка «Добавить» делают одно и то же.
- Домен нормализуется: нижний регистр, точка в конце отбрасывается, IDN
  переводится в punycode. Отображение — как ввёл пользователь (без точки
  в конце), запрос уходит в нормализованном виде.
- Допустимые символы метки: буквы, цифры, `-`, `_`. `*` разрешена только
  как вся первая метка (`*.example.com`). Длина имени — до 253 символов,
  метки — до 63.
- Для PTR принимается IP (IPv4/IPv6) или имя в зоне `.in-addr.arpa` /
  `.ip6.arpa`; IP превращается в reverse-имя в Rust.
- IP при типе, отличном от PTR, — ошибка валидации: «IP-адрес допустим
  только для типа PTR».
- Дубликат определяется по паре «нормализованное имя + тип». Новая строка
  не создаётся: существующая подсвечивается, прокручивается в видимую
  область и проверяется повторно.
- Успешное добавление сразу запускает проверку этой строки на всех
  выбранных серверах. Если лимит запросов уже исчерпан, строка
  добавляется, проверка не стартует, причина видна в строке состояния.
- После добавления поле очищается и получает фокус; тип остаётся прежним.

### Вставка списка

- Строки разделяются переводом строки; пустые пропускаются.
- Нормализация и проверки те же, что при одиночном добавлении.
- Дубликаты внутри вставки и относительно таблицы пропускаются; счётчик
  «пропущено дублей» показывает, сколько.
- Ошибочные строки не добавляются; диалог показывает количество ошибок
  и первую ошибку с номером строки.
- «Добавить» добавляет строки и закрывает диалог, проверку не запускает.
- «Добавить и проверить» добавляет строки и запускает проверку всех строк
  таблицы (не только новых), чтобы столбцы были заполнены целиком.
- После закрытия диалога таблица прокручивается к первой добавленной строке.

### Тип записи

- Тип задаётся у каждой строки отдельным `Select`; изменение типа сбрасывает
  результаты строки и сразу запускает её повторную проверку.
- Тип в строке добавления — значение по умолчанию для новых строк, а не
  глобальный фильтр.
- Для PTR подпись поля меняется на «IP-адрес или reverse-имя».

### Серверы

- Преднастроенные: «Системный», Google `8.8.8.8`, Cloudflare `1.1.1.1`,
  Quad9 `9.9.9.9`, AdGuard `94.140.14.14`.
- По умолчанию в новом сеансе выбраны «Системный», Google, Cloudflare.
- Одновременно выбрано от 1 до 8 серверов, включая системный. Выбор
  девятого не даёт интерфейс (`selection-limit`), а ядро отклоняет такой
  запрос своей проверкой.
- Свои серверы добавляются в диалоге и сразу становятся выбранными, если
  выбрано меньше восьми серверов.
- Выбор сервера не запускает проверку: появляется пустая колонка, данные
  заполняются по «Проверить». Снятый сервер скрывает колонку, но
  результаты остаются в сеансе и возвращаются при повторном выборе.
- Системный сервер показывает подсказку со списком адресов, полученных
  от ОС; если список пуст — «Системные резолверы не найдены».
- Свои серверы хранятся в профиле; преднастроенные в файл не пишутся.

### Проверка и остановка

- «Проверить» запускает все строки на всех выбранных серверах. Уже
  полученные результаты заменяются новыми; старые видны до прихода новых
  в виде приглушённых значений.
- «↻» у строки и «Повторить строку» в раскрытии проверяют только эту строку
  на всех выбранных серверах.
- «Остановить» отменяет текущую проверку: незавершённые ячейки получают
  статус `cancelled` (подпись «—»), полученные результаты остаются.
- «Очистить» убирает строки, результаты, ошибки и сбрасывает фильтры;
  выбранные серверы и тип по умолчанию сохраняются. Очистка во время проверки
  сначала спрашивает подтверждение и останавливает её.
- Пока проверка идёт, заблокированы «Проверить», добавление строк и вставка
  списка, смена типа строки, повтор и удаление; «Остановить» активна.
- Пределы: 500 запросов в проверке (строки × серверы), 8 серверов,
  4 одновременных запроса, 3 секунды на попытку (UDP и TCP отдельно).
- Превышение лимита запросов — ошибка до отправки: «Слишком много запросов:
  N. Предел — 500. Уменьшите число строк или серверов».

### Таблица

- Колонки «Домен» и «Тип» закреплены слева (`frozen`); колонки серверов
  прокручиваются горизонтально.
- «Колонки» открывает меню с флажками серверов: строка списка — название
  сервера, без адреса резолвера. «Домен» и «Тип» скрыть
  нельзя; серверные колонки можно скрыть все. Скрытая колонка не рисуется:
  таблица получает только видимые серверы, данные сеанса при этом целы.
- Ширина колонки домена — не меньше 220 px, серверной — не меньше 160 px;
  длинные значения обрезаются с многоточием, полное значение — в раскрытии.
- Порядок строк — порядок добавления. Сортировки нет: она ломала бы
  соответствие «строка — домен», а сравнение идёт построчно.
- Раскрытие строки (шеврон слева от домена или клик по ячейке) показывает
  по каждому выбранному серверу: название, адрес, время ответа, статус,
  все записи с TTL или текст ошибки. Внизу — «Повторить строку»
  и «Удалить строку».
- В ячейке показывается первая запись; если записей больше — `+N`.
  Для `MX`, `SRV`, `SOA`, `CAA` запись показывается в формате зоны.
- Статус `OK` с пустым набором записей не бывает: пустой ответ — `NODATA`.

### Сравнение и расхождения

- База сравнения — ответ системного сервера для той же пары «домен + тип».
- Сравниваются статус и множество значений записей. Порядок записей,
  регистр имён и TTL не влияют. Имена сравниваются без точки в конце.
- Сервер «совпадает», если его статус и значения равны системному.
- Вердикт строки — «совпадает у N из M», где M — число выбранных серверов
  без системного; «расходится у K из M». Если системный не выбран,
  вердикт скрыт.
- Строка с расхождением получает тонкую левую полосу и приглушённый фон.
- «Только расхождения» показывает строки, где N < M. Если системный сервер
  не выбран или он единственный, переключатель заблокирован и подписан
  «Только расхождения (нужен системный сервер)» или «(нужен ещё сервер)».
- Фильтр по статусу: «все», «есть ошибка» (`SERVFAIL`, `REFUSED`, `FORMERR`,
  `NOTIMP`, `TIMEOUT`, «нет сети», «ошибка ответа»), «без ответа»
  (`NODATA`, `NXDOMAIN`). Поиск — по подстроке введённого имени и
  нормализованного имени без учёта регистра (IDN находится и по написанию
  в Unicode, и по punycode).
- Фильтры не удаляют строки и не влияют на проверку: «Проверить» всегда
  проверяет весь список.

### Статусы

Проводные значения — строчные; подписи — как в таблице.

| Значение | Подпись | Смысл |
|---|---|---|
| `ok` | `OK` | Есть хотя бы одна запись |
| `nodata` | `NODATA` | `NOERROR`, но записей запрошенного типа нет |
| `nxdomain` | `NXDOMAIN` | Имени не существует |
| `servfail` | `SERVFAIL` | Сервер не смог ответить |
| `refused` | `REFUSED` | Сервер отказал в запросе |
| `formerr` | `FORMERR` | Сервер не понял запрос |
| `notimp` | `NOTIMP` | Операция не поддерживается |
| `timeout` | `TIMEOUT` | Нет ответа за 3 секунды |
| `offline` | `НЕТ СЕТИ` | Сокет не смог отправить или принять пакет |
| `bad_response` | `ОШИБКА ОТВЕТА` | Ответ не разобрался или не совпал с запросом |
| `pending` | — | Запрос отправлен, ответа ещё нет (интерфейсный статус) |
| `cancelled` | `—` | Проверка остановлена (интерфейсный статус) |

### Экспорт CSV

- Кнопка «Экспорт CSV» собирает файл в `useDnslookup`: штатный
  `DataTable.exportCSV` пишет без BOM и с запятой, а нужен Excel-совместимый
  файл с `;`.
- Экспортируются текущие отфильтрованные строки и видимые колонки.
- Колонки: «Домен», «Тип», по колонке на видимый сервер, «Совпадение».
- Значения — подписи статусов и записи в формате зоны; пустая ячейка пуста.
- Файл скачивается штатным механизмом WebView2. Дополнительно CSV копируется
  в буфер обмена: блокировка скачивания не даёт исключения, и отличить её от
  успеха нельзя. Уведомление говорит о копии только при удачной записи;
  если не удалось ни сохранить файл, ни скопировать — показывается ошибка.
- Разделитель — `;`, кодировка — UTF-8 с BOM: Excel открывает русский текст.

### Клавиатура и доступность

- Enter в поле домена — добавить; Esc в диалоге — закрыть без действий.
- Кнопки и поля имеют подписи для экранного диктора; иконка «↻» — кнопка
  с подписью «Повторить строку».
- Статус — не только цвет: в ячейке всегда есть текст подписи.
- Во время проверки строка состояния объявляет прогресс (`aria-live="polite"`).

## Модель состояния TypeScript

```ts
export type RecordType =
  | "A" | "AAAA" | "CNAME" | "MX" | "TXT"
  | "NS" | "SOA" | "SRV" | "CAA" | "PTR";

export type CellStatus =
  | "pending" | "ok" | "nodata" | "nxdomain" | "servfail"
  | "refused" | "formerr" | "notimp" | "timeout" | "offline"
  | "bad_response" | "cancelled";

export interface DnsRow {
  id: string;            // crypto.randomUUID()
  input: string;         // как ввёл пользователь
  name: string;          // нормализованное имя или reverse-имя
  type: RecordType;
}

export interface ServerOption {
  id: string;            // "system", "google", "cloudflare", "quad9",
                         // "adguard" или uuid своего сервера
  label: string;
  address: string | null; // null — системный
  kind: "system" | "preset" | "custom";
}

export interface DnsAnswer {
  value: string;         // формат зоны, имя без точки в конце
  ttl: number | null;
}

export interface DnsCell {
  status: CellStatus;
  answers: DnsAnswer[];
  elapsedMs: number | null;
  error: string | null;
}

export interface DnsSession {
  rows: DnsRow[];
  servers: string[];                  // выбранные id, порядок — порядок колонок
  defaultType: RecordType;
  cells: Map<string, DnsCell>;        // ключ `${rowId}:${serverId}`
  customServers: ServerOption[];
  systemAddresses: string[];
  runId: string | null;
  status: {
    run: { loading: boolean; error: string | null };
    servers: { loading: boolean; error: string | null };
  };
  filters: {
    search: string;
    status: "all" | "error" | "empty";
    diffOnly: boolean;
  };
  hiddenServers: string[];            // скрытые колонки
}
```

Правила:

- Карта сеансов — `Map<cellKey, DnsSession>` в модуле `useDnslookup.ts`,
  а не в `reactive` компонента.
- При монтировании: взять сеанс по `cellKey` или создать; удалить сеансы,
  чьих `tabId` нет в `workspace.tabs`.
- Пустой сеанс получает серверы по умолчанию и тип `A`.
- Один сеанс — одна активная проверка. Повторный запуск при
  `status.run.loading` игнорируется.
- Результаты приходят по `queryId`; ячейка обновляется, только если
  `runId` события совпадает с текущим.
- `pending` ставится перед отправкой; при остановке все `pending`
  становятся `cancelled`.
- Состояние операции гранулярное: `status.run` и `status.servers`
  независимы (правило Vue).

## Модуль Rust

Файлы:

```text
src-tauri/src/modules/dnslookup/
  mod.rs        Module, топики, обработчики, реестр проверок
  request.rs    структуры запроса/ответа, валидация
  transport.rs  UDP/TCP, сборка и разбор через hickory-proto
  records.rs    перевод RData в строки формата зоны
  servers.rs    чтение и запись servers.json, системные резолверы
```

`modules/mod.rs` добавляет `mod dnslookup;` и `Box::new(dnslookup::DnsLookupModule)`.
Идентификатор модуля — `"dnslookup"`.

### Поток проверки

1. Обработчик `dnslookup:run` валидирует запрос: до 500 запросов, до 8
   серверов, известные `type`, корректные `name` и адреса.
2. Создаёт `Run { id, cancelled: Arc<AtomicBool> }` и кладёт в
   `Mutex<HashMap<String, Run>>`; отвечает `accepted` сразу, чтобы не
   занимать диспетчер шины.
3. Запускает 4 рабочих потока, которые берут запросы из общей очереди.
   Для системного сервера запрос уходит на каждый найденный адрес
   параллельно; ответ — первый пришедший.
4. Каждый результат публикуется событием `dnslookup:result` по мере
   готовности; порядок не гарантируется.
5. После последнего результата публикуется `dnslookup:finished`.
   При отмене флаг проверяется перед каждым запросом и после ответа;
   результаты, посчитанные после отмены, не публикуются, а начатые сокеты
   закрываются по таймауту 3 с.
6. Запись в реестре удаляется по завершении.

Ошибки обработчика не пишутся в лог модулем: возврат ошибки и события
`core:error` — работа шины. Модуль не вызывает `log::`.

### Транспорт

- UDP: `UdpSocket::bind("0.0.0.0:0")`, `connect(server)`, `set_read_timeout(3s)`,
  отправка и приём. DNS `id` — случайный; ответ принимается, только если
  `id` совпал и адрес отправителя совпадает с сервером.
- Усечение (`TC = 1`) — повторный запрос по TCP: подключение с таймаутом,
  двухбайтовый префикс длины, чтение полного ответа.
- Системный сервер: список адресов активных адаптеров из
  `ipconfig::get_adapters()` (`dns_servers()`), без повторов, порядок ОС.
  Адреса читаются в рабочем потоке, а не в обработчике шины. Запросы ко всем
  адресам одновременно; первый ответ отменяет остальные (флаг на `Arc`).
- Запросы уже начатых ячеек при отмене не прерываются: сокеты закрываются
  по таймауту 3 с, а результат после отмены не публикуется.
- Кэша нет: каждый запуск и каждый повтор идут в сеть.
- `EDNS` не добавляется: ответ должен быть не больше 512 байт по UDP,
  иначе сработает TCP-фолбэк. Это осознанно: интересует сравнение,
  а не большие ответы.

### Разбор ответа

| Условие | Статус |
|---|---|
| `RCODE = NOERROR`, записи есть | `ok` |
| `RCODE = NOERROR`, записей нет | `nodata` |
| `RCODE = NXDOMAIN` | `nxdomain` |
| `RCODE = SERVFAIL` | `servfail` |
| `RCODE = REFUSED` | `refused` |
| `RCODE = FORMERR` | `formerr` |
| `RCODE = NOTIMP` | `notimp` |
| таймаут сокета | `timeout` |
| ошибка сокета (`NetworkUnreachable`, `HostUnreachable` и т.п.) | `offline` |
| не разобралось, `id` не совпал, ответ от чужого адреса | `bad_response` |

В `answers` попадают только записи запрошенного типа из секции ответа.
`CNAME`-цепочка не разворачивается и не добавляется: показываются записи
того типа, что запрошен. Для `TXT` строки склеиваются; для `SOA`, `MX`,
`SRV`, `CAA` — формат зоны без завершающей точки у имён.

### Валидация в Rust

- Имя: `hickory_proto::rr::Name::from_utf8` (IDN поддерживается), длина
  до 253, метки до 63. PTR: IP → reverse-имя.
- Тип: только десять перечисленных; неизвестный — ошибка.
- Сервер: `SocketAddr` с портом по умолчанию 53; IPv6 — в скобках.
- Дубликаты серверов по адресу — ошибка.
- Лимиты проверяются ещё раз: UI может ошибиться.

## Хранение

- Свои серверы: `profiles/<id>/data/dnslookup/servers.json`.
- Путь берётся из `Storage::data_dir()`, а не собирается в модуле вручную.
- Формат:

```json
{
  "version": 1,
  "servers": [
    { "id": "9a0c…", "label": "Локальный DNS", "address": "10.0.0.53:53" }
  ]
}
```

- Файла нет — пустой список, это не ошибка.
- Битый JSON — ошибка `status.servers.error`; список в интерфейсе остаётся
  пустым, запись не выполняется до исправления или удаления файла.
- Запись атомарная: временный файл рядом и переименование.
- Результаты проверок не сохраняются.

## Ошибки и пустые состояния

| Ситуация | Где видно |
|---|---|
| Нет строк | Таблица с подсказкой «Добавьте домен или вставьте список» |
| Нет серверов | «Проверить» заблокирована, подсказка «Выберите хотя бы один сервер» |
| Больше 500 запросов | `status.run.error` и строка состояния |
| Неверный домен/IP | Ошибка у поля добавления, строка не создаётся |
| Дубликат | Подсветка существующей строки, без сообщения об ошибке |
| Нет системных резолверов | Подсказка у сервера; ячейки — `bad_response` с текстом |
| Свой сервер не сохранился | `status.servers.error`, список в памяти не теряется |
| Проверка отменена | Незавершённые ячейки `cancelled`, строка состояния «остановлено» |
| Ответ не разобрался | Ячейка `ОШИБКА ОТВЕТА`, подробность в раскрытии |
