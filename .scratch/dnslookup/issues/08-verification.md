# 08. Финальная проверка DNS

Blocked by: 01, 02, 03, 04, 05, 06, 07

**Статус:** проверено вживую через CDP в release-сборке; не проверено
только отключение сети.

Проверено в живом окне 12.11.2026 (release, WebView2 + CDP):
- DNS открывается из сайдбара; одиночная проверка `example.com` / A на
  «Системный» + Google + Cloudflare — три `OK`, вердикт «совпадает у 2 из 2».
- `nonexistent.example` — `NXDOMAIN` у всех, расхождений нет.
- Повторное добавление `example.com` не создаёт строку, существующая
  подсвечивается.
- Вставка списка из 10 строк с дублями: «Добавлено 8 · пропущено дублей 2»,
  в таблице 9 строк.
- Смена типа строки на MX перепроверяет только её.
- Недоступный сервер `192.0.2.1:53` даёт `TIMEOUT`, вердикт «расходится
  у 1 из 3», в сводке «1 расхождение»; «Только расхождения» оставляет
  расходящиеся строки, фильтр «есть ошибка» — строки с ошибкой.
- Снятие системного сервера скрывает вердикты и блокирует фильтр расхождений;
  возврат сервера восстанавливает вердикты.
- Поиск фильтрует строки и восстанавливает список при очистке.
- Скрытие колонки Cloudflare убирает её из таблицы.
- «Экспорт CSV»: файл сформирован, копия в буфере проверена — `;`, BOM,
  подписи статусов и вердикт на месте; сообщение о копии появляется только
  при успешной записи в буфер.
- Свой сервер `1.0.0.1` добавлен, попал в колонки выбранным, ответил `OK`,
  вердикт «совпадает у 3 из 3»; удаление сервера убирает колонку, строки целы.
- Перезапуск приложения: свой сервер на месте в диалоге, строки и результаты
  пусты, выбраны серверы по умолчанию.
- 60 строк × 6 серверов: 360 ячеек, «Остановить» — 240 ответов, 120 отменены
  («—»), окно отвечает за 1 мс; в журнале «проверка остановлена: получено
  240 из 360».
- Переключение на журнал и обратно: строки и результаты на месте.
- Закрытие вкладки DNS и новая вкладка: сеанс пуст.
- Второй экземпляр DNS в другой вкладке: сеансы независимы, возврат
  к первому сохраняет его строки.
- В профиле лежат только `profile.json` и `data/dnslookup/servers.json`;
  файл лога без `ERROR`, `WARN` и паник за прогон.

Не проверено вживую: отключение сети (шаг 6) — статусы `TIMEOUT` и
`offline` разведены в транспорте, но ручное отключение адаптера не
выполнялось.

Технические проверки: `npm run build`, `cargo check`, `cargo test --lib`
(120 тестов); `invoke`/`listen` только в `api.ts`, `any` нет; модуль Rust
не вызывает `log::` и не импортирует другие модули; ADR 0013, 0016–0018
на месте, 0015 помечен заменённым; глоссарий и спека сверены с кодом.

## Задача

Проверить фичу целиком в живом окне и закрыть хвосты: сборку, тесты,
журнал, лог, переносимость, отсутствие регрессий оболочки.

## Ручной сценарий

1. Запустить `npm run tauri dev`, открыть DNS из сайдбара.
2. Одиночная проверка: `example.com` / A на «Системный» + Google +
   Cloudflare — три `OK`, записи читаются.
3. Добавить `nonexistent.example` — `NXDOMAIN` у всех, расхождения нет.
4. Вставить список из 10 доменов, включая дубликат: дубликат подсвечен,
   строк стало 10.
5. Сменить тип одной строки на MX — строка перепроверилась, остальные
   не тронуты.
6. Отключить сеть и проверить строку — `НЕТ СЕТИ` (или `TIMEOUT`), ошибка
   видна в раскрытии.
7. Включить сеть, добавить свой сервер `1.1.1.1:53`, проверить — колонка
   заполнилась.
8. Снять системный сервер — вердикты скрыты, фильтр расхождений
   заблокирован.
9. Включить «Только расхождения» — остаются только расходящиеся строки.
10. Скрыть колонку, экспортировать CSV, открыть в Excel.
11. Запустить 60 строк × 6 серверов, нажать «Остановить» — часть ячеек
    заполнена, остальные «—», приложение отзывчиво.
12. Переключиться на журнал и обратно — строки и результаты на месте.
13. Закрыть вкладку DNS, открыть новую — сеанс пуст.
14. Перезапустить приложение: свои серверы на месте, строки и результаты
    пусты.
15. Открыть второй экземпляр DNS в другой вкладке — сеансы независимы.

## Технические проверки

```powershell
npm run build
Set-Location src-tauri
cargo check
cargo test --lib
```

- Новых предупреждений компилятора нет.
- В `src/tools/dnslookup/` нет `invoke`/`listen` вне `api.ts`, нет `any`.
- Модуль Rust не вызывает `log::` и не импортирует другие модули.
- В `profiles/<id>/data/dnslookup/` лежит только `servers.json`;
  результатов проверок нет.
- Файл лога не содержит ошибок, вызванных штатным сценарием; отключение
  сети даёт journal-запись, а не панику.
- Лицензионного баннера нет: PrimeVue 4 не проверяет ключ.

## Документация

- ADR 0013, 0016–0018 актуальны; ADR 0015 помечен как заменённый.
- Глоссарий содержит `cellKey`, «сеанс», «проверка», «расхождение»,
  «системный сервер».
- Спека `.scratch/dnslookup/spec.md` совпадает с реализацией; расхождения
  либо исправлены в коде, либо дописаны в спеку.

## Готово, когда

- Все 15 шагов проходят в живом окне.
- Три обязательные проверки зелёные.
- Ошибки видны в панели и журнале, молчаливых кнопок нет.
- Сеанс не сохраняется, свои серверы сохраняются, папка программы
  остаётся переносимой.
