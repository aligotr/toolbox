# Чистка ключей до выпуска и файл изменений

## Цель

До первого выпуска держать ключи внутренними: править и сливать напрямую,
без манифеста и разрешения старых имён. Пользователю внешнего словаря
отдавать файл изменений по его словарю: что добавить (`messages`)
и что убрать (`obsolete`).

## Решения

- Ключ - внутреннее имя до первого выпуска (ADR 0081). После выпуска -
  публичный контракт, переименование требует миграции.
- Старые имена не резолвятся и в словарях не остаются:
  `translate` и `hasMessage` ищут только точный ключ.
- Одинаковые текст, подстановки и формы живут в одном ключе.
  `check-messages` валит сборку при дублях.
- Общие действия и подписи без предмета - в `common.*`; общие подписи
  пресетов - в `presets.*`; доменные тексты остаются у инструмента.
- Внешний словарь не перезаписывается. Файл изменений -
  `<code>.updates.jsonc` с `messages` и `obsolete`; прежний
  `<code>.missing.jsonc` убирается.

## Границы

Входит:

- прямая чистка ключей и удаление дублей;
- общая таблица подписей пресетов `src/ui/tool/presets/texts.ts`;
- модель языков: недостающие и устаревшие ключи, документ изменений;
- раздел «Язык»: «Внешний», «Полный», «Добавить», «Удалить»,
  «Выгрузить изменения»;
- Rust: `<code>.updates.jsonc`, счётчики, шапка файла, старый файл
  не создаётся;
- проверка дублей в `check-messages`;
- ADR 0081, уточнения ADR 0039, 0057, 0072, 0078 и `i18n.md`.

Не входит:

- манифест переименований и разрешение старых имён;
- перезапись внешнего словаря пользователя;
- baseline дублей: дублей нет и новые запрещены.

## Критерий готовности

- `npm run test`, `npm run build`, `cargo check`, `cargo test --lib`.
- `check-messages` не находит дублей и старых имён в коде.
- Внешний словарь со старым ключом получает файл изменений:
  новый ключ в `messages`, старый в `obsolete`.
- Раздел «Язык» показывает «Внешний», «Полный», счётчики и кнопку.
- В браузере нет старых подписей и потерянных ключей.
