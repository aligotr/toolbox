# Удаление данных и корзина

Основание: ADR 0061. Решение согласовано: корзина внутренняя, верхний
уровень повторяет единицу удаления, записи внутри документов не попадают
в корзину, автоочистка через 14 дней.

## Решение

- Файловая сущность (профиль, пресет, внешний словарь, целый файл данных)
  удаляется после подтверждения переносом в `local/trash/`. При отказе
  переноса исходник остаётся на месте.
- Верхний уровень корзины - единица удаления:

  ```text
  local/trash/
    profiles/<id>/                       профиль удалён целиком
    presets/<profile>/<tool>/<id>.json   отдельный пресет
    languages/<code>.jsonc               внешний словарь
  ```

- Запись внутри документа (свой DNS-сервер, строка таблицы, значение
  настройки) удаляется правкой документа, без корзины и подтверждения.
- Машинное состояние и производные файлы (рабочее пространство, логи,
  `*.missing.jsonc`, `*.tmp`) удаляются сразу, без корзины.
- Корзина не показывается в интерфейсе: нет входа, списка и восстановления.
  Подтверждения и уведомления называют предмет и действие, но не обещают
  возврат.
- Записи старше 14 дней удаляются при старте и после каждого удаления.
  Срок считается от удаления, а не от времени изменения содержимого.
  Чистка после удаления не трогает только что перенесённую запись, даже
  если отметка времени не легла.
- Сначала снимаются ссылки, затем переносится файл: умолчание пресета
  снимается до переноса, файл дополнений языка убирается до переноса словаря.
- Старая раскладка корзины не мигрирует и чистится по общему сроку.
- `trash/data/` не заводится: ветка без писателя - обещание без механизма.
- Переиспользование id профиля может смешать пресеты двух поколений
  в `trash/presets/<id>/`. Это приемлемо: файлы не перезаписываются,
  даты в пути не вводятся.

## Разногласия, закрытые работой

| Место | Было | Стало |
|---|---|---|
| ADR 0028 | пресеты в `local/trash/presets/<tool>/` | новая раскладка ADR 0061 |
| README, глоссарий | в корзине «данные инструментов» | данных в корзине нет: списки правятся |
| `storage.rs` | профили «ждут решения пользователя» | корзина внутренняя, чистится через 14 дней |
| `presets.rs`, `profiles.rs` | «корзину чистят руками» | автоочистка |
| `dnslookup.preset.removed` | «перемещён в корзину» | «удалён» |
| README | удаление профиля «переносит в корзину» | удаление убирает профиль |
| ADR 0056 | корзина чистится руками | срок задаёт ADR 0061 |
| журнал | печатал путь корзины | называет предмет и действие |

Старые `.scratch/*` описывают прошлые раскладки и остаются историей.

## Приёмка

- `npm run verify` зелёный: интерфейсные тесты, `vue-tsc`, сборка,
  `cargo check`, `cargo test --lib`.
- Тесты корзины: свежая запись переживает чистку, старая удаляется,
  старая раскладка чистится, пустые папки убираются.
- Тесты профиля и пресета: цель лежит в новой ветке, профиль с именем
  `presets` не сталкивается с категорией, одинаковый id пресета из разных
  профилей не смешивается.
- Тест языка: файл дополнений убирается до переноса словаря.
- Живьём: удаление пресета и профиля, очистка старых записей после удаления,
  отсутствие слова «корзина» в подтверждениях и уведомлениях.

## Швы тестов

- `core::services::trash::stamp` - время удаления;
- `core::services::trash::prune` - срок и старые формы;
- `core::services::trash::prune_keep` - защита только что перенесённой записи;
- `core::services::profiles::delete` - путь и целостность профиля;
- `core::services::presets::delete` - путь с профилем, умолчание;
- `core::services::languages::revert_builtin` - порядок уборки и переноса.
