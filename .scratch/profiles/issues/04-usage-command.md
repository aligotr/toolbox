# 04. Счётчики профилей отдельной командой

- **Состояние:** сделано

## Что сделать

- `Profile` теряет `presets` и `data_files`; `profiles_list` файлы не считает.
- Новая команда `profiles_usage` и контракт `ProfileUsage`.
- Секция «Профили» грузит счётчики отдельно; сайдбар — нет.

## Готово, когда

- Открытие сайдбара не обходит папки профилей.
- Счётчики в настройках обновляются после создания, удаления и очистки данных.

## Итог

- `Profile` содержит только `id` и `title`; счётчики — `ProfileUsage`.
- `profiles::usage` и `profiles::list` делят обход `profile_dirs`: правило
  «что считать профилем» не расходится между запросами. `usage` сортирует
  по идентификатору ради стабильного ответа.
- `profiles_usage` зарегистрирована; сайдбар её не вызывает.
- В интерфейсе: `profileUsage`, `profileUsageOf`, `loadProfilesUsage`.
  `refreshUsage` после создания и удаления не превращает отказ счётчиков
  в отказ операции.
- `ProfilesSection` показывает счётчики через `usageLabel` и грузит их при
  открытии; `DataSection` обновляет их после очистки данных.
- Тесты: Rust `usage_counts_presets_and_data_per_profile` (временный файл
  не считается); TS `tests/profiles/usage.test.ts` (отдельная команда,
  список не читается).
