# Инструмент Ping: проверка отклика узлов

## Цель

Дать один экран, на котором видно, отвечает ли узел по ICMP, сколько
длится ответ и где теряются пакеты. Экран работает и как одиночная
проверка, и как список доменов и адресов IPv4/IPv6 с общими параметрами.
История не сохраняется: сеанс живёт, пока открыта вкладка.

## Что решено

- ADR 0068 - Windows IP Helper, транспорт за трейтом, Unix позже.
- ADR 0016 - без `ping.exe`, без tokio и новых сетевых пакетов.
- ADR 0017 - состояние инструмента привязано к `cellKey`.

## Границы фичи

Входит:

- единый экран Ping с таблицей целей;
- цели: домен, IPv4, IPv6, включая scope id у link-local;
- семейство: «Авто», «IPv4», «IPv6»;
- разрешение имён один раз при старте, все найденные адреса;
- период, количество пакетов, таймаут;
- запуск по кнопке, остановка, сохранение уже полученных результатов;
- общая строка цели, раскрытие с адресами и пакетами;
- фильтры по тексту, статусу и семейству;
- пресеты: список, параметры, пресет по умолчанию;
- выгрузка сводки и пакетов в CSV;
- журнал старта, завершения и остановки.

Не входит:

- история результатов на диск;
- график задержек;
- вставка списка из буфера;
- TCP-проверка портов и HTTP;
- полноценный Unix-бэкенд: на других ОС инструмент недоступен;
- изменение размера пакета и TTL, фрагментация, DF.

## Экран

Сверху вниз:

1. **Шапка** - название Ping и кнопка пресета.
2. **Строка добавления** - поле цели, выбор семейства, «Добавить».
3. **Строка параметров** - период, мс; количество; таймаут, мс;
   «Запустить» / «Остановить».
4. **Строка фильтров** - поиск, статус, семейство.
5. **Таблица** - строка на введённую цель.
6. **Строка состояния** - цели, адреса, пакеты, отставание.
7. **Панель действий** - «Сводка CSV», «Пакеты CSV», «Очистить».

### Главная строка

Показывает то, что нужно для общего понимания, и помещается в ширину окна:

- введённая цель и, если имя нормализовано, ASCII-форма;
- число найденных адресов верхним индексом у цели, если адресов больше
  одного; при одном адресе индекс не показывается;
- отправлено/получено одной компактной парой;
- средняя задержка;
- общий статус.

Минимум, среднее, максимум и последний RTT остаются в раскрытии: в строке
они занимали четыре колонки и вытесняли статус за край.

Кнопки строки: раскрыть, повторить, удалить. Перестановка - перетаскиванием
за свободное место цели.

### Раскрытие

Строка цели на время раскрытия подсвечена и связана с раскрытием линией
вложенности. В начале раскрытия - липкая шапка с целью, числом адресов
и статусом; при прокрутке она остаётся на виду. Кнопка «Свернуть» в шапке
закрывает раскрытие.

Два блока.

**Адреса** - строка на каждый IPv4/IPv6:

- адрес и семейство;
- отправлено, получено, потери;
- минимум, среднее, максимум, последний RTT;
- статус адреса.

**Пакеты** - строка на каждый пакет:

- адрес, семейство, номер, статус, RTT, TTL, время.

Обе подтаблицы прокручиваются внутри раскрытия, если колонок больше, чем
места: раскрытие не растягивает экран и не наследует ширину главной строки.

TTL для IPv6 не показывается: Windows не отдаёт его в `ICMPV6_ECHO_REPLY`.

### Пустые состояния

- Нет целей: подсказка «Добавьте домен или IP-адрес».
- Фильтр ничего не нашёл: «Ничего не найдено».
- Имя не разрешилось: строка цели со статусом «Не разрешён».
- На не-Windows: сообщение «Проверка ICMP недоступна на этой платформе».

## Семантика проверки

- Цель - то, что ввёл пользователь. Адрес проверки - конкретный IPv4/IPv6.
- Домен разрешается один раз при старте. «Авто» берёт все адреса A и AAAA,
  `IPv4` и `IPv6` - только своё семейство.
- IP-литерал не разрешается: сразу становится адресом проверки.
- Период применяется к каждому адресу отдельно. Адреса одной цели
  проверяются параллельно.
- Следующий пакет адреса уходит не раньше периода после отправки
  предыдущего. Если ответ задержался дольше периода, следующий стартует сразу.
- Количество - пакетов на адрес. После последнего пакета адрес завершён.
- Остановка сохраняет полученные результаты и помечает незавершённое
  как отменённое.

## Статусы

Цель и адрес:

- `ok` - ответили все пакеты;
- `loss` - ответила часть;
- `timeout` - не ответил ни один;
- `unreachable` - сеть или узел недоступен;
- `unresolved` - имя не разрешилось;
- `error` - отказ API или команды;
- `cancelled` - проверка остановлена.

Интерфейс добавляет `pending`: новая цель ещё ни разу не проверялась, идёт
прогон или ждём разрешения. Пока идёт серия, `pending` держится и при
частичных ответах без потерь; первая настоящая потеря сразу даёт `loss`.
Отказ запуска помечает цели `error`, остановка - `cancelled`.

Общий статус цели считается по всем её пакетам тем же правилом.
Статус адреса - по пакетам этого адреса.

## Пределы

- Целей: 64.
- Адресов проверки: 128. Если разрешение дало больше, запуск отклоняется
  с отказом, а не режет список молча.
- Период: 200..60000 мс, по умолчанию 1000.
- Количество: 1..100, по умолчанию 4.
- Таймаут: 200..10000 мс, по умолчанию 1000.
- Рабочих потоков: 16.
- Данные запроса: 32 байта.

## Пресеты

Пресет хранит:

- цели как есть (идентификатор, ввод, семейство);
- семейство по умолчанию;
- период, количество, таймаут;
- фильтры поиска, статуса и семейства.

Результаты не сохраняются. Пресет по умолчанию загружается в свежую ячейку.
Загрузка заменяет список и сбрасывает результаты; идущая проверка
останавливается. Выбор пресета закрывает диалог; итог загрузки показывается
уведомлением.

## CSV

Обе выгрузки в UTF-8 с BOM и разделителем `;`.

**Сводка** - строка на адрес: цель, адрес, семейство, отправлено, получено,
потери, минимум, среднее, максимум, последний, статус.

**Пакеты** - строка на пакет: цель, адрес, семейство, номер, статус, RTT,
TTL, время.

## Журнал

- `journal.icmp.started` - старт, число целей.
- `journal.icmp.finished` - завершение, адреса, отправлено, получено.
- `journal.icmp.cancelled` - остановка, сколько успели.
- Ошибки запуска и подписки - с кодом, как у DNSlookup.
- По каждому пакету журнал не пишется.

## Клавиатура и доступность

- Enter в поле добавления добавляет цель.
- Enter в поле параметров запускает проверку.
- Escape в поле параметров возвращает сохранённое значение.
- Кнопка раскрытия имеет `aria-expanded`, статусы читаются текстом,
  а не только цветом.

## Тесты

Стыки, на которых проверяется поведение:

- разбор цели: домен, IPv4, IPv6, scope id, отказ;
- проверка запроса Rust: пустой список, пределы, период, количество,
  таймаут, семейство;
- разрешение с фейковым резолвером: авто, IPv4, IPv6, ошибка, лишние
  адреса;
- оркестрация с фейковым транспортом: число пакетов, период, остановка,
  события результата и завершения, повторный `run_id`;
- сводка TS: все ответы, часть, ни одного, отменённые, RTT;
- CSV: обе выгрузки, экранирование, BOM;
- фильтры и строки: добавление, дубликат, удаление, перестановка;
- пресет: разбор, снимок, неполный payload.

Живая проверка: `127.0.0.1`, `::1`, внешний IPv4 и IPv6, несуществующий
домен, недостижимый адрес, остановка, пресет, CSV.
