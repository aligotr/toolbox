# 08. Рабочее пространство

Blocked by: 06

**Статус:** сделано.

## Задача

Сохранять открытые вкладки, активную вкладку и размеры колонок
в `local/workspace.json`.

## Объём

- Rust: команды `workspace_load`, `workspace_save`; содержимое —
  непрозрачный JSON, проверяется только «это объект».
- Vue: `src/core/workspace.ts` — загрузка при старте, сохранение
  с задержкой ~300 мс и при закрытии.
- Восстановление: неизвестный инструмент → пустая ячейка с подписью,
  вкладка не ломается.
- Пустой или битый файл → одна пустая вкладка, причина в журнале.
- Вкладок не меньше одной после восстановления.

## Как выполнено

- Общие правила файлов состояния (`read`, `strip_bom`, `write_atomic`)
  вынесены из `settings.rs` в `core/files.rs`. Ошибка в них ломает сразу все
  файлы, поэтому правило должно быть одно, а не копия в каждом сервисе.
- Rust `core/workspace.rs`: `load` возвращает `Option<Value>` (`null` —
  файла нет), `save` пишет атомарно по ADR 0010. Содержимое **не
  разбирается**: формат принадлежит интерфейсу, и правка раскладки не должна
  требовать правки Rust. Проверяется только внешний договор — «это
  JSON-объект»: массив или строка означали бы файл, записанный кем-то другим,
  и интерфейс не смог бы отличить «вкладок нет» от «файл испорчен».
- Команды `workspace_load`/`workspace_save` — в `lib.rs`; отказ возвращается
  текстом, успешная запись пишет `debug` в лог.
- TS `core/workspace.ts`: `parseFile` проверяет версию и отбрасывает битые
  элементы, повторные идентификаторы и второй экземпляр журнала/настроек —
  иначе полоса вкладок разошлась бы с правилами `openSingleton`. Заголовки
  и иконки одиночных вкладок берутся из `SINGLETON_TABS`, а не из файла:
  журнал называется одинаково в любой версии программы.
- Отсутствие файла — первый запуск: оболочка открывает одну пустую вкладку
  и в журнал ничего не пишет. Любая другая поломка объясняется в журнале
  и сводится к той же одной пустой вкладке: пустое окно не даёт понять,
  что случилось.
- Неизвестный инструмент вкладку не ломает: `ToolGrid` рисует подписанную
  пустую ячейку «Инструмент не найден: `<id>`».
- Запись отложенная — 300 мс после последнего изменения (`watch` с `deep`):
  перетаскивание границы колонки меняет ширину десятки раз в секунду, и
  писать файл на каждое движение значит нагружать диск и синхронизацию ради
  промежуточных значений. Записи выстроены в цепочку промисов: таймер
  и закрытие окна не должны писать файл одновременно.
- Закрытие окна: `onCloseRequested` досрочно сбрасывает ожидающую запись,
  ожидание ограничено 3 с. Окно обязано закрыться, даже если папка программы
  на сетевой шаре и запись зависла: потеря последней правки дешевле
  незакрывающегося окна.
- Разрешение `core:window:allow-destroy` в `capabilities/default.json`
  обязательно: наличие обработчика закрытия заставляет Tauri отменить
  системное закрытие, и окно уничтожает сам интерфейс после обработчика.
  Без разрешения окно оставалось бы висеть.
- Без ядра (отладка одной страницы в браузере) сохранение не подключается:
  `startup === null` → только `ensureWorkspace()`, ошибок чтения нет.

Попутно исправлена поломка из тикета 07, которую не мог заметить сам тикет:
закрытие окна подвешивало приложение. `CloseRequested` вызывал
`GeometrySaver::flush()`, то есть `join()` потока записи, а тот снимал
геометрию окна; геттеры окна отвечает поток событий — тот самый, который
стоял в `join()`. Теперь снимок геометрии делается в обработчике событий
окна, а фоновая запись только пишет готовый снимок (подробности в тикете 07).

## Проверено

- `cargo check` — без предупреждений; `cargo test --lib` — 52 теста,
  из них 7 на рабочее пространство; `npm run build` — 235 модулей.
- В живом окне Tauri (WebView2 DevTools + помощник user32, потому что
  закрытие через DevTools не проходит через обработчик приложения):
  - чистый старт: одна пустая вкладка, `workspace.json` не создаётся;
  - открытие Ping создаёт файл с двумя вкладками (`Новая вкладка`, `Ping`)
    и верным `activeId`; ключи пишутся по алфавиту;
  - вкладка добавлена и окно закрыто через **17 мс** (таймер записи — 300 мс):
    окно закрылось без зависания, правка оказалась в файле;
  - перезапуск вернул те же 4 вкладки, активной стала добавленная перед
    закрытием;
  - удаление `workspace.json` → одна пустая вкладка, записей в журнале нет;
  - битый файл → одна пустая вкладка и запись в журнале с путём и причиной
    (`key must be a string at line 1 column 29`); работа продолжается;
  - файл с инструментом `dns` (нет в реестре) → ячейка «Инструмент не
    найден: dns», соседний `ping` в той же колонке работает;
  - повтор идентификатора вкладки отброшен: три записи в файле дали три
    вкладки без дубля;
  - ширины колонок `2.5` и `1` пережили перезапуск и запись при закрытии.

## Готово, когда

- Перезапуск возвращает те же вкладки, активную и размеры.
- Удаление `workspace.json` даёт чистый старт.
- Ошибка чтения не мешает работе.
