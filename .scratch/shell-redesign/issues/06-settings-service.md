# 06. Сервис настроек

Blocked by: 05

**Статус:** сделано.

## Задача

Вырастить `core/settings.rs` из одного поля в типизированную схему
по ADR 0010 и ADR 0012.

## Объём

- Схема `version: 1`:

```json
{
  "version": 1,
  "log": { "level": "info" },
  "window": { "width": 1280, "height": 800, "x": null, "y": null, "maximized": false },
  "ui": { "sidebar_collapsed": false },
  "active_profile": "work"
}
```

- Атомарная запись `*.tmp` + переименование.
- Неизвестные ключи сохраняются при перезаписи.
- Битое поле → значение по умолчанию + замечание; файл не роняет старт.
- Команды: `settings_get`, `settings_set` (частичное обновление),
  `window_reset`.
- Событие `core:settings:changed` с изменённым разделом.
- `set_log_level` переводится на общий сервис.
- Тесты: отсутствие файла, битый JSON, неизвестный уровень, сохранение
  неизвестных ключей, круговое чтение.

## Как выполнено

- Схема описана структурами `Settings` → `LogSettings`, `WindowSettings`,
  `UiSettings`; `active_profile` — строка. Размеры окна по умолчанию
  вынесены в константы `DEFAULT_WIDTH` / `DEFAULT_HEIGHT`.
- Чтение разбирает разделы по отдельности: битый `log` не сбрасывает окно
  и профиль, а причина попадает в `warnings` и пишется в лог уровнем `warn`
  после запуска логгера — как и раньше.
- Неизвестные ключи верхнего уровня и внутри разделов складываются
  в `extra` (`#[serde(flatten)]`) и возвращаются в файл при следующей записи.
- Уровень лога в файле разбирается без учёта регистра: файл правят руками,
  и `DEBUG` не должен молча превращаться в `info`.
- `apply_patch` меняет ровно один раздел. Слияние идёт через JSON:
  неизвестные ключи раздела сохраняются, проверка типов остаётся у `serde`.
  Опечатка в имени раздела — ошибка, а не тихое сохранение.
- `active_profile` проверяется как идентификатор папки: латиница, цифры,
  `-`, `_`. Кириллица и разделители пути отклоняются — иначе профиль мог бы
  вывести запись за пределы `profiles/`.
- Запись атомарная: `settings.json.tmp`, затем переименование; при отказе
  временный файл удаляется.
- `settings_set` и `window_reset` идут через общий `commit_settings`:
  сначала файл, потом память и уровень логгера. Если запись не удалась,
  действующие настройки не расходятся с диском.
- После сохранения публикуется `core:settings:changed` с `{ "section": ... }`.
  Недоставка события только логируется: файл уже записан.
- Команда `set_log_level` удалена; уровень меняется через `settings_set`
  с разделом `log`. `startup_status` читает `settings.log.level`.
- Порядок запуска немного уточнён: настройки читаются до пробы записи,
  потому что активный профиль определяет, какую папку проверять. Проба
  по-прежнему идёт до логгера и до показа окна — смысл ADR 0005 сохранён.

## Проверено

- `cargo check` проходит без предупреждений.
- `cargo test --lib`: 34 теста, все успешны (добавлены 6 проверок настроек).
- `npm run build` проходит.
- В живом окне Tauri (через DevTools-протокол WebView2):
  `settings_get` вернул схему версии 1; `settings_set` для `log` переключил
  уровень на `debug`, для `window` поставил ширину 1000; `window_reset`
  вернул 1280×800; неизвестный раздел `theme` отклонён с текстом
  «Неизвестный раздел настроек: 'theme'».
- Событие `core:settings:changed` пришло три раза с разделами
  `log`, `window`, `window`.
- В `local/settings.json` после записей сохранился посторонний ключ
  `plugin.enabled`, временных `*.tmp` не осталось.
- После переключения на `debug` в `local/logs/` появились строки `DEBUG`
  о сохранении разделов — уровень меняется без перезапуска.

## Готово, когда

- Уровень лога меняется из интерфейса и переживает перезапуск.
- Неизвестные поля не теряются.
- `cargo test --lib` проходит.
