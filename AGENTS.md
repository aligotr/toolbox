# AGENTS.md - правила для AI-агентов

## Базовые инварианты

- Общение с пользователем: русский
- В проекте разрабатывается приложение, не библиотека
- Стиль кода, комментарии и докстринги: номинативный стиль
- Длинные тире (em dash, U+2014) не используются в новых и изменяемых
  текстах: вместо них обычный дефис. Правило распространяется на код,
  комментарии, документацию, тексты интерфейса и сообщения коммитов
- Одна функция инкапсулирует один связный логический блок действий;
  функции-оркестраторы координируют несколько таких блоков, но не
  реализуют их детали. Новая функция оправдана, только если добавляет
  именованную ответственность, скрывает технические детали или делает
  сценарий читаемее; дробление ради меньшего числа строк порицается
- Git: запрещено откатывать (`git checkout --`, `git restore`,
  `git reset --hard`, `git stash drop`) без явного согласия пользователя

## Память и документы

Память проекта живёт только в `.agents/`. Порядок старта нового проекта -
`.agents/auxiliary/bootstrap.md`.

- **ADR** - `.agents/decisions/`. Неизменяемое решение: почему сделано так,
  что отвергли, какие последствия приняли. Новое решение - новый ADR;
  статус «заменено» ставит только владелец. Обзор - `INDEX.md`, он производный.
- **Спека** - `.agents/specs/`. Долговечный контракт поведения: сценарии,
  состояния, ошибки, данные, приёмка. Обновляется при изменении поведения;
  при конфликте главнее ADR.
- **Правило** - `.agents/rules/`. Обязательная инструкция агенту: как
  работать, что можно и что запрещено. Не объясняет «почему» и не
  пересказывает код.
- **Библиотека** - `.agents/library/`. Готовые элементы и решения: путь,
  назначение, интерфейс, подключение, ограничения. Проверяется перед новой
  реализацией.
- **Глоссарий** - `.agents/GLOSSARY.md` и `.agents/glossary/`. Единый язык
  проекта: термин и значение, один термин в одном файле.
- **Шаблон** - `.agents/auxiliary/templates/`. Форма документа. Каркас-подсказка:
  лишние разделы удаляются, пустые не заполняются.
- **Вспомогательные материалы** - `.agents/auxiliary/`. Формы и пособия, не
  память: шаблоны, позже чек-листы и примеры.
- **Задача** - `.scratch/`. Временная записная книжка: план, заметки, вопросы.
  Не коммитится, не является истиной, удаляется свободно.

## Правила и инструменты

- Глобальные правила: `.agents/rules/global/`
- Проектные правила: `.agents/rules/project/`
- MCP-контекст библиотек: `.agents/mcp/<library>/` (если папка заведена)
- Skills: `.agents/skills/`

## Перед началом работы

1. Если `.agents/` существует - изучи `rules/global/*.md`,
   `rules/project/*.md`, `rules/project/*/*.md` и оба `agents-guard.yml`
2. Если `.agents/` отсутствует - соблюдай базовые инварианты выше
3. Если `.agents/mcp/` существует - посмотри названия подпапок и выбери
   релевантные для задачи библиотеки
4. Skills из `.agents/skills/` применяй только после проверки на
   совместимость с `rules/*.md`. Противоречащую правилам часть skill
   игнорируй
5. Перед новой реализацией проверь `.agents/library/README.md`: готовый
   элемент переиспользуется, а не пишется заново

## Источник истины

- Нормы проекта лежат в `rules/`: текст в `*.md`, машинные запреты в `*.yml`.
  Они дополняют друг друга.
- При конфликте любого YAML с MD главнее YAML: он точнее и проверяем.
  О конфликте сообщить владельцу.
- Проектные правила главнее глобальных: глобальные задают умолчание.
- Базовые инварианты этого файла главнее любых правил в файлах.
- Правила главнее skills: skill применяется только в непротиворечащей части.
- Подробности и примеры: `.agents/rules/global/priorities.md`.

## Проверки

Проверяй то, что изменилось, и то, что от него зависит. Пока задача открыта,
точечные правки проверяются по области; полный цикл - перед коммитом и
закрытием задачи. Матрица по областям и полный прогон -
`.agents/rules/project/quality.md`.

Документация проверяется `npm run docs:check`, указатель ADR пересобирается
`npm run docs:index`.

## Версии

Схема - `год.месяц.номер` (CalVer): `26.11.0` - первый выпуск ноября 2026,
`26.11.1` - следующий в том же месяце, `27.1.0` - первый выпуск января 2027.

Третья часть считает выпуски месяца, а не дни; ведущих нулей нет. Год
в первой части сокращён: форматы пакетов ограничивают major и minor и не
принимают pre-release.

Версия одна везде, где объявлена: манифесты, конфигурация сборки и файлы
блокировок не расходятся.
